## 지금 이 논문을 읽어야 하는 이유

GPT-3가 2020년에 던진 질문은 단순했다. '모델이 충분히 크다면, fine-tuning 없이도 새로운 task를 수행할 수 있을까?' 당시 NLP의 주류는 BERT처럼 task마다 labeled 데이터를 모아 별도로 fine-tuning하는 방식이었다. GPT-3는 175B parameter의 autoregressive language model 하나로, gradient update 없이 prompt context만으로 수십 개의 benchmark에서 경쟁력 있는 성능을 냈다. 이 in-context learning 패러다임은 '모델을 고치는 것'이 아니라 '모델에게 말 거는 방식을 고치는 것'이 핵심임을 처음으로 대규모로 증명했다.

이 논문 한 편이 오늘날 우리가 매일 쓰는 도구들의 직접적인 조상이다. Codex는 GitHub Copilot이 되었고, InstructGPT는 ChatGPT로 이어졌으며, GPT-4와 Claude, Gemini 모두 GPT-3가 확립한 scaling + in-context learning 철학 위에 서 있다. LangChain, LlamaIndex 같은 프레임워크가 prompt를 중심으로 설계된 것도, OpenAI API를 호출하는 수많은 프로덕트가 fine-tuning 대신 prompt engineering에 먼저 투자하는 것도 모두 이 논문이 만든 세계관의 산물이다.

지금 이 논문을 읽으면 두 가지 실용적 통찰을 얻는다. 첫째, scaling law의 함의다. Model size, data, compute를 함께 늘릴 때 few-shot 성능이 예측 가능하게 향상된다는 실험적 근거는, 오늘날 모델 개발 투자 결정 시 scaling 곡선을 먼저 추정해보는 습관의 이론적 토대가 된다. 둘째, prompt 설계가 곧 engineering이라는 인식이다. Zero-shot과 few-shot 사이의 성능 차이, instruction 포함 여부에 따른 결과 변화를 직접 데이터로 확인하면, prompt engineering을 단순한 텍스트 작성이 아닌 하나의 설계 discipline으로 다루게 된다.

## [Language Models are Few-Shot Learners (GPT-3)](https://arxiv.org/abs/2005.14165)

> 2020년  ·  Tom B. Brown, Benjamin Mann, Nick Ryder  ·  NeurIPS 2020  ·  인용 25,000회

### 한 줄 요약

당시 NLP 모델들은 특정 task를 수행하기 위해 대규모 fine-tuning 데이터가 필요했고, 이는 실용적인 범용 AI 개발에 큰 걸림돌이었다. GPT-3는 175billion parameter의 autoregressive language model을 구축하고, in-context learning을 통해 few-shot, one-shot, zero-shot 방식으로 별도의 gradient update 없이 다양한 NLP task를 수행할 수 있음을 보였다. 그 결과 GPT-3는 translation, question answering, cloze task 등 수십 개의 benchmark에서 fine-tuned 모델에 준하거나 능가하는 성능을 달성했다.

### 역사적 배경

2020년 당시 NLP 커뮤니티는 BERT류의 encoder 기반 모델과 task-specific fine-tuning이 사실상 표준으로 자리 잡고 있었고, 모델 크기를 수백억 parameter 수준으로 키우는 것은 비현실적이라는 인식이 지배적이었다. OpenAI는 GPT-2에서 이미 large-scale autoregressive language model의 가능성을 시사했지만, 당시에는 안전 우려로 전체 모델을 공개하지 않았을 만큼 이 방향성은 주류 연구 흐름과 거리가 있었다.

### 왜 혁신적이었는가

기존의 task마다 labeled 데이터를 모아 별도로 fine-tuning하는 방식 대신, 단일 pretrained model의 prompt context만을 활용하는 in-context learning 방식을 써서, gradient update 없이도 수십 개의 NLP benchmark에서 경쟁력 있는 성능을 달성함으로써 범용 language model의 실현 가능성을 처음으로 대규모로 입증했다.

### 이 논문이 만들어낸 변화

GPT-3의 등장으로 prompt engineering이라는 새로운 실무 분야가 탄생했고, fine-tuning 없이 in-context learning만으로 모델을 활용하는 패러다임이 산업 전반에 확산되었다. 이후 Codex, InstructGPT, ChatGPT, GPT-4로 이어지는 large language model 계보의 직접적인 출발점이 되었으며, foundation model이라는 개념 자체를 AI 업계의 표준 담론으로 정착시켰다.

### 오늘날 배울 수 있는 것

1. Scaling law의 실무적 함의: model size, data, compute를 함께 늘릴 때 few-shot 성능이 예측 가능하게 향상된다는 사실은, 오늘날 모델 개발 투자 결정 시 scaling 곡선을 먼저 추정해보는 습관으로 이어질 수 있다.
2. Prompt 설계가 곧 모델 성능이다: GPT-3는 동일한 모델이라도 prompt 구성 방식(zero-shot vs. few-shot, instruction 포함 여부)에 따라 성능이 크게 달라짐을 보여줬으며, 실무에서 prompt engineering을 단순한 텍스트 작성이 아닌 하나의 engineering discipline으로 다뤄야 함을 시사한다.
3. Task-agnostic evaluation의 중요성: 특정 benchmark에 과적합된 fine-tuned 모델보다 다양한 task에서 일관된 성능을 내는 모델이 실제 프로덕션 환경에서 더 강건할 수 있으며, 모델 평가 시 다양한 distribution의 test set을 구성하는 것이 중요하다.

### 한계 및 이후 발전

GPT-3는 in-context learning의 가능성을 보였지만 prompt 구성 방식에 따라 성능 편차가 크고, reasoning이나 arithmetic 등 복잡한 multi-step 추론에서는 한계를 드러냈으며, 이는 이후 chain-of-thought prompting, instruction tuning, RLHF 등의 연구로 부분적으로 극복되었다.

## [PointNet: Deep Learning on Point Sets for 3D Classification and Segmentation](https://arxiv.org/abs/1612.00593)

> 2016년  ·  Charles R. Qi, Hao Su, Kaichun Mo  ·  CVPR 2017  ·  인용 10,000회

### 한 줄 요약

기존 3D 데이터 처리 방식은 point cloud를 voxel grid나 이미지로 변환하여 정보 손실과 연산 낭비가 발생했다. PointNet은 point cloud를 직접 입력으로 받는 neural network를 설계하여, 각 point를 독립적으로 처리한 뒤 symmetric function(max pooling)으로 global feature를 집계하는 방식을 제안했다. 결과적으로 3D object classification, part segmentation, scene semantic parsing 등 다양한 태스크에서 당시 state-of-the-art 성능을 달성했다.

### 역사적 배경

2016년 당시 deep learning은 2D 이미지 도메인에서 CNN이 지배적인 패러다임으로 자리잡고 있었고, 3D 데이터를 다루기 위해 연구자들은 point cloud를 voxel이나 이미지로 변환하는 우회적 방법에 의존했다. PointNet은 이러한 변환 기반 패러다임에 정면으로 도전하여, 비정형(irregular) 데이터를 있는 그대로 처리할 수 있는 새로운 network 설계 철학을 제시했다.

### 왜 혁신적이었는가

기존의 voxelization 또는 multi-view projection 방식 대신, point cloud를 직접 입력으로 받고 shared MLP와 max pooling이라는 symmetric function을 결합하여 permutation invariance와 transformation invariance(T-Net 기반 input/feature transform)를 동시에 달성했다.

### 이 논문이 만들어낸 변화

PointNet은 이후 PointNet++, VoxNet 대비 효율적인 3D perception 연구의 기반이 되었으며, 자율주행, 로보틱스, AR/VR 등 실시간 3D 이해가 필요한 산업 전반에 걸쳐 point cloud deep learning의 표준적인 출발점으로 자리잡았다. 또한 permutation invariance 문제를 symmetric function으로 해결하는 아이디어는 이후 set-based learning 및 graph neural network 연구에도 광범위하게 영향을 미쳤다.

### 오늘날 배울 수 있는 것

1. **Permutation invariance 설계 원칙**: 순서가 없는 집합(set) 형태의 데이터를 다룰 때, symmetric function(예: max pooling, sum)을 aggregation 단계에 사용하면 입력 순서에 무관한 robust한 representation을 학습할 수 있다.
2. **데이터 변환 없이 raw 형식 직접 처리**: 데이터를 억지로 정형 포맷으로 변환하면 정보 손실과 연산 오버헤드가 발생한다. 원본 데이터 구조에 맞는 inductive bias를 network 설계에 반영하는 것이 더 효과적일 수 있다.
3. **Joint alignment network(T-Net)를 통한 invariance 학습**: 기하학적 변환(rotation, translation)에 robust하게 만들기 위해 별도의 mini-network로 transformation matrix를 예측하고 feature space에 적용하는 방식은, 도메인 특화 invariance를 end-to-end로 학습시키는 실용적인 패턴으로 다양한 분야에 응용 가능하다.

### 한계 및 이후 발전

PointNet은 각 point를 독립적으로 처리하기 때문에 local geometric structure(인접 point 간의 관계)를 포착하지 못한다는 한계가 있었으며, 이는 이후 hierarchical local feature aggregation을 도입한 PointNet++에 의해 극복되었다.
