## 지금 이 논문을 읽어야 하는 이유

2015년, object detection 파이프라인은 region proposal 생성과 detection 네트워크가 완전히 분리된 구조였다. Selective Search 같은 CPU 기반 알고리즘이 속도 병목을 만들었고, end-to-end 학습은 불가능했다. Faster R-CNN은 Region Proposal Network(RPN)를 도입해 convolutional feature map을 공유함으로써 이 구조적 한계를 단번에 허물었다. 단순히 빠른 detection이 아니라, '파이프라인의 두 단계가 같은 feature를 공유할 수 있다'는 설계 철학의 전환이었다.

이 논문의 영향은 지금도 현장 곳곳에 살아있다. Mask R-CNN, Feature Pyramid Network(FPN)은 Faster R-CNN의 two-stage 구조를 직접 계승했고, anchor box 개념은 YOLO와 SSD 같은 one-stage detector 설계에도 이식되었다. 오늘날 DETR처럼 anchor-free 방식이 주목받는 이유도, anchor box의 한계를 이해해야 비로소 납득된다.

지금 이 논문을 읽으면 두 가지 실용적 통찰을 얻는다. 첫째, feature sharing 설계 원칙이다. 파이프라인의 서로 다른 단계가 동일한 중간 표현을 공유하면 계산 비용과 학습 복잡도를 동시에 줄일 수 있다. 멀티모달 모델이나 복잡한 inference 파이프라인을 설계할 때도 이 질문은 여전히 유효하다. 둘째, end-to-end trainability를 초기 설계 목표로 삼아야 한다는 것이다. 단계별 개별 최적화보다 전체를 하나의 backpropagation 그래프로 연결할 때 각 단계가 서로를 보완하며 수렴한다는 원칙은, LLM 기반 파이프라인 설계에도 그대로 적용된다.

## [Faster R-CNN: Towards Real-Time Object Detection with Region Proposal Networks](https://arxiv.org/abs/1506.01497)

> 2015년  ·  Shaoqing Ren, Kaiming He, Ross Girshick  ·  NeurIPS 2015  ·  인용 50,000회

### 한 줄 요약

당시 object detection 파이프라인은 region proposal 생성(예: Selective Search)과 detection 네트워크가 완전히 분리되어 있어 속도 병목이 심각했다. 이 논문은 Region Proposal Network(RPN)를 도입하여 convolutional feature map을 detection 네트워크와 공유함으로써 region proposal 비용을 사실상 제로에 가깝게 만들었다. 그 결과 GPU 기준 초당 5프레임 수준의 처리 속도와 당시 SOTA detection 정확도를 동시에 달성했다.

### 역사적 배경

2015년은 deep learning 기반 detection이 전통적인 sliding window + hand-crafted feature(예: HOG, DPM) 방식을 막 대체하던 시기였다. R-CNN 계열이 정확도 면에서 우위를 점했지만, proposal 생성과 feature 추출이 분리된 구조는 당시 연구자들 사이에서 '어쩔 수 없는 설계 제약'으로 받아들여지고 있었다.

### 왜 혁신적이었는가

기존의 Selective Search 같은 외부 CPU 알고리즘으로 region proposal을 생성하던 방식 대신, convolutional feature map을 detection 네트워크와 공유하는 RPN을 설계하여 proposal 생성 비용을 10ms 수준으로 줄이고 end-to-end backpropagation 학습을 가능하게 만들었다.

### 이 논문이 만들어낸 변화

Faster R-CNN은 RPN을 통해 proposal 생성을 네트워크 내부로 흡수함으로써 완전한 end-to-end trainable object detection 패러다임을 열었고, 이후 Mask R-CNN, Feature Pyramid Network(FPN) 등 수많은 two-stage detector의 표준 backbone 구조로 자리잡았다. 또한 anchor box 개념을 대중화하여 YOLO, SSD 등 one-stage detector 설계에도 직접적인 영향을 미쳤다.

### 오늘날 배울 수 있는 것

1. **Feature sharing 설계 원칙**: 파이프라인의 서로 다른 단계가 동일한 중간 표현(feature map)을 공유하도록 설계하면 계산 비용과 학습 복잡도를 동시에 줄일 수 있다. 모델 아키텍처를 설계할 때 '어떤 연산을 재사용할 수 있는가'를 먼저 질문하라.
2. **Anchor box를 통한 multi-scale 처리**: 단일 feature map 위에서 다양한 크기와 종횡비의 anchor box를 정의하면 image pyramid나 filter pyramid 없이도 multi-scale object를 효율적으로 처리할 수 있다. 이 아이디어는 오늘날 detection 헤드 설계에서도 여전히 유효하다.
3. **End-to-end trainability의 중요성**: 파이프라인의 각 단계를 분리하여 개별 최적화하는 것보다, 전체를 하나의 backpropagation 그래프로 연결하여 공동 학습하면 각 단계가 서로를 보완하도록 수렴하여 전체 성능이 향상된다. 복잡한 멀티스테이지 시스템을 설계할 때 end-to-end 학습 가능성을 초기 설계 목표로 삼아야 한다.

### 한계 및 이후 발전

two-stage 구조 특성상 one-stage detector(예: YOLO, SSD)에 비해 여전히 latency가 높았으며, 이후 연구들은 anchor-free 방식(예: FCOS, CenterNet)이나 transformer 기반 DETR로 anchor box 의존성 자체를 제거하는 방향으로 한계를 극복했다.
