## 지금 이 논문을 읽어야 하는 이유

Layer Normalization과 LoRA는 오늘날 Transformer를 학습하고 특정 과제에 맞추는 두 개의 표준 부품이지만, 둘 다 처음에는 큰 구조를 바꾸지 않는 작은 재매개변수화에서 출발했다. Layer Normalization은 한 샘플의 layer 내부 통계로 활성값을 정규화해 mini-batch 크기와 학습·추론 모드 차이에 대한 의존을 없앴다. LoRA는 전체 가중치를 다시 학습하는 대신 가중치 변화량을 낮은 rank의 두 행렬로 표현했다.

두 논문을 함께 읽으면 실무의 중요한 원칙이 보인다. 계산량을 줄이는 방법은 단순히 더 작은 모델을 쓰는 것이 아니라, **어떤 축에서 통계를 공유하고 어떤 부분만 업데이트할지**를 선택하는 일이다. LayerNorm은 샘플 내부 feature 축을 택했고, LoRA는 task adaptation의 변화량이 낮은 내재 rank를 가질 수 있다는 가설을 택했다.

원 논문의 범위도 기억해야 한다. 2016년 LayerNorm 논문은 오늘날의 모든 Transformer 변형을 검증한 문서가 아니며, Pre-LN·Post-LN 배치는 후속 연구에서 계속 바뀌었다. LoRA의 대표 실험은 2021년 당시의 RoBERTa·DeBERTa·GPT-2·GPT-3에 집중했고, rank와 적용 모듈의 최적값은 현재 모델·과제마다 달라진다. 고전의 핵심 아이디어와 현재 라이브러리의 관행을 구분해서 읽어야 한다.

## [Layer Normalization](https://arxiv.org/abs/1607.06450)

> **저자**: Jimmy Lei Ba, Jamie Ryan Kiros, Geoffrey E. Hinton  
> **연도**: 2016  
> **발표 형태**: arXiv preprint (최초 제출 2016-07-21)  
> **원문 확인**: 2026-10-13  

### 한 줄 요약

Batch Normalization이 mini-batch 전체에서 각 unit의 통계를 계산한다면, Layer Normalization은 **각 학습 사례에서 한 layer의 unit 전체**를 사용해 평균과 분산을 계산한다. 따라서 batch 크기와 무관하고 학습과 추론에서 같은 연산을 수행하며, recurrent network에서도 각 time step에 곧바로 적용할 수 있다.

### 역사적 배경

2015년 Batch Normalization은 깊은 feed-forward network의 학습을 크게 안정화했지만, batch 통계에 의존해 작은 batch·가변 길이 시퀀스·RNN에 적용하기가 까다로웠다. RNN의 hidden state는 시간에 따라 달라지며, 서로 다른 길이의 사례를 같은 batch 축에서 정규화하는 방식도 자연스럽지 않았다. LayerNorm은 정규화 축을 batch에서 한 사례의 hidden unit으로 돌려 이 문제를 피했다.

### 왜 혁신적이었는가

핵심은 모델 구조를 크게 바꾸지 않고 통계 계산의 축만 바꾼 점이다. 한 사례의 pre-activation에 대해 평균과 분산을 구하고, 정규화 뒤 각 neuron의 학습 가능한 gain과 bias를 적용한다. 같은 입력에는 batch 동료가 달라도 같은 결과가 나오며 running statistics를 따로 유지할 필요가 없다. 원 논문은 이 특성이 recurrent network의 hidden-state dynamics를 안정화하고 기존 기법보다 학습 시간을 줄일 수 있음을 여러 RNN 과제에서 보였다.

### 이 논문이 만들어낸 변화

LayerNorm은 Transformer의 residual block 주변에서 사실상 기본 구성요소가 되었다. 후속 연구는 normalization을 residual 뒤에 두는 Post-LN과 앞에 두는 Pre-LN의 최적화 차이를 분석했고, RMSNorm처럼 평균 제거를 생략한 변형도 등장했다. 오늘날의 대형 언어모델에서 “LayerNorm을 쓴다”는 말만으로는 부족하며, 위치·epsilon·정밀도·RMS 계열 여부까지 아키텍처의 일부가 되었다.

### 오늘날 배울 수 있는 것

1. **통계 축을 먼저 정하라.** 작은 batch, sequence 길이, 분산 학습 조건이 달라질 때 batch 축 통계는 불안정할 수 있다. 입력별 feature 축 정규화가 문제 정의와 맞는지 확인한다.
2. **학습·추론 일치를 테스트하라.** LayerNorm은 running mean/variance를 쓰지 않으므로 eval mode에서 batch 통계가 바뀌는 문제를 피한다. 구현 검증은 동일 샘플을 서로 다른 batch 구성에 넣었을 때 출력이 같은지 확인하면 된다.
3. **위치까지 실험하라.** Transformer에서는 Pre-LN과 Post-LN이 gradient 흐름과 warm-up 민감도를 바꾼다. normalization 종류만 고정하지 말고 residual 배치와 함께 ablation해야 한다.

### 한계 및 이후 발전

LayerNorm은 feature dimension의 통계를 한꺼번에 사용하므로 feature 의미와 scale이 크게 다른 모델에서 항상 최선은 아니다. 긴 네트워크에서 Post-LN은 초기 gradient 불안정을 만들 수 있고, Pre-LN은 깊이에 따른 표현 변화가 약해지는 문제가 보고됐다. 또한 작은 hidden size에서는 평균·분산 추정 자체가 거칠 수 있다. RMSNorm, ScaleNorm, GroupNorm과 다양한 residual scaling은 이런 비용·안정성·표현력 trade-off를 다룬 후속 발전이다.

## [LoRA: Low-Rank Adaptation of Large Language Models](https://arxiv.org/abs/2106.09685)

> **저자**: Edward J. Hu, Yelong Shen, Phillip Wallis, Zeyuan Allen-Zhu, Yuanzhi Li, Shean Wang, Lu Wang, Weizhu Chen  
> **연도**: 2021 preprint / ICLR 2022  
> **발표 장소**: International Conference on Learning Representations (ICLR 2022)  
> **원문 확인**: 2026-10-13  

### 한 줄 요약

LoRA는 pretrained weight (W_0)를 고정하고 task-specific update를 (Delta W=BA)로 표현한다. 여기서 (Ainmathbb{R}^{r	imes k}), (Binmathbb{R}^{d	imes r}), (rllmin(d,k))이므로 전체 (d	imes k) 행렬 대신 작은 두 행렬만 학습·저장한다.

### 역사적 배경

GPT-3 175B처럼 모델이 커지면서 과제마다 전체 parameter를 fine-tuning하고 별도 checkpoint로 배포하는 방식은 optimizer state, GPU memory와 저장 공간에서 감당하기 어려워졌다. Adapter는 작은 module을 추가하지만 inference path를 늘릴 수 있고, prefix tuning은 입력 sequence 일부를 사용한다. LoRA는 pre-trained 모델의 adaptation 변화량이 낮은 “intrinsic rank”를 가질 수 있다는 관찰을 이용해 weight update 자체를 재매개변수화했다.

### 왜 혁신적이었는가

LoRA는 forward pass에서 (W_0x+BAx)를 계산하되 학습 시 (W_0)에는 gradient를 저장하지 않는다. 배포할 때 (BA)를 (W_0)에 합치면 원래와 같은 크기의 행렬 하나로 추론할 수 있어 구조상 추가 latency가 없다. 논문은 주로 attention의 query·value projection에 LoRA를 적용했고, GPT-3 175B 예에서 full fine-tuning 대비 trainable parameter를 10,000배 줄이고 training GPU memory를 약 3분의 1 수준으로 낮출 수 있다고 보고했다.

### 이 논문이 만들어낸 변화

LoRA는 parameter-efficient fine-tuning의 대표 방식이 되었고, 하나의 base model에 여러 작은 adapter를 저장·교체하는 배포 패턴을 확산시켰다. 이후 QLoRA는 quantized base model 위에서 LoRA를 학습해 메모리 장벽을 더 낮췄고, AdaLoRA·DoRA 등은 rank 배분이나 update parameterization을 바꿨다. 공식 `loralib`뿐 아니라 Hugging Face PEFT 등 주요 생태계가 이를 지원한다.

### 오늘날 배울 수 있는 것

1. **적용 모듈을 측정으로 고르라.** 원 논문의 q·v projection 설정을 그대로 복사하지 말고 q/k/v/o와 MLP 조합을 동일 trainable-parameter budget에서 비교한다.
2. **rank보다 전체 예산을 통제하라.** rank (r), 적용 layer 수, scaling (alpha/r), dropout이 함께 용량을 결정한다. validation 성능과 adapter 크기, peak VRAM을 함께 기록한다.
3. **merge 전후 동등성을 검증하라.** 배포 완료 기준은 같은 입력에서 merge 전후 logits가 허용 오차 안에 있고 latency가 base model 수준으로 돌아오는 것이다.
4. **base checkpoint를 고정하라.** 작은 LoRA 파일만으로 모델이 완성되는 것이 아니므로 base model revision·tokenizer·target module 목록을 함께 버전 관리한다.

### 한계 및 이후 발전

낮은 rank 가정은 모든 과제와 layer에서 동일하게 성립하지 않는다. 여러 adapter를 한 batch에서 동적으로 섞으면 weight merge의 무지연 장점을 그대로 얻기 어렵고, 서로 다른 LoRA를 단순 합성하면 간섭이 생길 수 있다. 원 논문은 Transformer 언어모델의 일부 attention weight에 집중했으므로 현대 multimodal·MoE·장문맥 모델의 최적 설정을 보장하지 않는다. full fine-tuning보다 trainable parameter가 적다는 사실이 학습 데이터 품질, catastrophic forgetting, 안전성 평가를 대신하지도 않는다.

### 카드 1 — 표지

**LayerNorm과 LoRA, 왜 아직도 기본인가**  
통계를 계산하는 축과 업데이트하는 부분을 바꾼 두 편의 고전.

### 카드 2 — Layer Normalization

BatchNorm은 batch에서 통계를 계산한다.  
LayerNorm은 한 샘플의 layer feature에서 평균과 분산을 구한다.  
그래서 batch 크기에 덜 민감하고 학습·추론 연산이 같다.  
Transformer에서는 종류뿐 아니라 Pre-LN·Post-LN 위치도 중요하다.

### 카드 3 — LoRA

전체 weight를 다시 학습하지 않는다.  
업데이트 (Delta W)를 작은 두 행렬 (BA)로 표현한다.  
GPT-3 175B 사례에서 논문은 trainable parameter 10,000배 감소와 GPU memory 약 3배 절감을 보고했다.  
이 수치는 모든 모델의 보장값이 아니라 해당 설정의 결과다.

### 카드 4 — 공통 원리

LayerNorm은 **통계의 축**을 바꿨다.  
LoRA는 **업데이트의 부분공간**을 줄였다.  
큰 모델을 통째로 바꾸기 전에, 필요한 계산이 어디에 있는지 다시 정의한 것이다.

### 카드 5 — 실행 체크리스트

- 작은 batch → LayerNorm/RMSNorm과 BatchNorm을 동일 조건에서 비교
- Transformer 안정성 → Pre-LN/Post-LN, warm-up, gradient norm 기록
- LoRA 튜닝 → target module·rank·(alpha)를 전체 예산 기준으로 ablation
- 배포 → merge 전후 logits·latency·base revision 검증
