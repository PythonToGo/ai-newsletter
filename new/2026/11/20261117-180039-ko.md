## 이번 주 연구 동향

최근 호의 국소 학습·문서 평가·추론 압축에 이어, 이번에는 언어모델 구조와 로봇 조작 계획을 함께 살핀다. 두 연구를 하나의 성능 경쟁으로 묶을 수는 없다. Latent Lattice Language Models는 토큰 사이에 유지되는 계산 상태를 더하고, Lazy-MOSAIC은 비싼 시뮬레이션을 언제 수행할지 바꾼다.

공통으로 읽을 질문은 “계산 자원을 어디에 배치했는가”다. 다만 언어모델의 추정 FLOPs와 실제 지연, 로봇의 계획 시간과 물리적 실행 시간은 다르다. 좋은 점수뿐 아니라 무엇을 고정한 비교인지 확인해야 한다는 것이 편집부의 해석이다.

일반 AI·ML·비전·과학 ML·로보틱스 후보를 탐색하고 최근 30일 신규 논문 아카이브의 제목·URL과 대조했다. 아래 두 편은 모두 11월 16일 최초 제출된 프리프린트이며, 검색 목록의 11월 17일 노출일을 발표일로 바꾸지 않았다. 원문은 열어 확인했으나 신규 두 편의 실행 가능한 저자 코드는 확인하지 못했다. 그 제약을 감추거나 다른 연구의 코드를 해당 구현으로 연결하지 않는다.

## 논문 분석

### 1. Latent Lattice Language Models: 토큰을 넘어서 유지되는 층별 계산 상태

- **출처**: arXiv / MIT·Adobe 연구진
- **점수**: 8.3/10 *(편집 선정 점수이며 실측 성능 점수가 아님)*
- **URL**: https://arxiv.org/abs/2611.21608
- **저자**: Shivam Duggal, Zongze Wu, William T. Freeman, Antonio Torralba, Richard Zhang, Eli Shechtman
- **최초 제출**: 2026-11-16 18:59:38 UTC
- **분석 버전·상태**: v1 프리프린트; 학회 채택으로 표시하지 않음
- **발견 경로**: 최신 ML 논문 검색·ArXivSignals 목록 → arXiv 전문 → 저자 프로젝트 페이지
- **확인일**: 2026-11-17; 별도 수정본은 확인하지 않음

**요약**

이 연구는 언어모델의 깊이·너비 외에 유지되는 계산 상태를 늘린다. 층을 통과하는 기존 표현에, 토큰 사이에서 갱신되는 층별 잠재 벡터를 더한다. 이 벡터는 attention과 MLP의 계산을 조절한다. 기존 Transformer에 추론용 플러그인을 붙이는 방식이 아니라 새 구조를 학습하는 연구다.

**방법론**

기본 갱신은 병렬 스캔이 가능한 affine recurrence다. 과거 상태를 선형 변환하고 새 입력을 더하는 형태로, 순서 의존성을 효율적으로 계산한다. 추가 상태는 attention을 없애지 않고 읽기·쓰기와 MLP를 조건화한다. 입력 직접 주입과 층 방향 readout을 더한 단일 패스 구성, 별도 반복 정제 구성 J3를 구분한다.

**주요 기여**

저자 프로젝트는 ‘층을 더 깊게’와 ‘토큰을 더 많이 생성’하는 선택 외에, 지속 상태를 계산에 배분하는 설계를 보여준다. 편집부가 주목하는 기여는 최고 점수 하나보다 비교 축의 확장이다. 어떤 상태가 추가됐고 기존 통로가 얼마나 좁아졌는지 함께 읽어야 한다.

**실험 결과**

v1 표 1의 FineWeb-Edu **200억 토큰** 학습, **2,048 토큰 문맥** 조건에서 기본 Transformer는 **406.7M 파라미터·0.71 GFLOP/토큰·perplexity 15.410**, 입력 주입·readout을 더한 LLLM은 **405.6M·0.72·14.400**이다. Perplexity는 다음 토큰 예측의 불확실성을 요약하며 낮을수록 좋다.

저자 프로젝트의 표는 J3의 **14.03**을 **1.85 GFLOP/토큰** 조건으로 제시한다. 같은 체크포인트의 순차 rollout은 **0.72 GFLOP/토큰·14.73**이다. 저비용 경로에도 14.03이 유지된다고 읽으면 안 된다. 이는 저자 보고 수치이며 독립 재현 결과가 아니다.

**맥락**

최근 아카이브의 Transformer 반복 연구와는 다른 논문이다. 반복 횟수만 늘리는 대신, 지속 상태를 별도 경로에 두는 설계를 검토한다. 어떤 구조가 유리한지는 동일 데이터·연산·평가 조건의 비교로 판단해야 한다.

**실무 시사점**

- **대상**: 소형 언어모델 구조를 비교하는 연구·인프라 팀.
- **방법**: 코드가 제공되면 단일 패스를 먼저 재현하고 J3를 별도 실험으로 둔다. 동일 토크나이저·학습 데이터·파라미터 예산 아래 perplexity, 실제 토큰 지연, 상태 메모리와 KV 캐시를 각각 기록한다.
- **완료 기준**: 품질 개선이 반복 시드에서 유지되고, 추정 FLOPs뿐 아니라 배포 장치의 측정 비용도 사전 한도를 만족해야 한다. 편집부의 제안이며 이번에 실행한 실험이 아니다.

**한계**

논문의 주요 Transformer 실험은 400M–600M 규모다. 이를 대형 다국어 서비스나 긴 문맥의 성능으로 확대할 근거는 부족하다. 연산 수 감소를 같은 비율의 실제 속도 향상으로 해석하지 않는다. 추가 상태의 저장·갱신 비용도 평가해야 한다.

확인한 저자 페이지는 코드를 ‘공개 예정’으로 표시한다. arXiv의 프로젝트 링크는 오류를 반환했지만, 검색으로 찾은 복수형 경로의 저자 페이지에서 상태를 확인했다. 코드 검토·실행·학습 재현을 완료했다고 주장하지 않는다.

### 2. Lazy-MOSAIC: 싸게 예측하되 반환할 로봇 계획은 시뮬레이션으로 확인한다

- **출처**: arXiv / CMU·Technion 연구진
- **점수**: 8.2/10 *(편집 선정 점수이며 실측 성능 점수가 아님)*
- **URL**: https://arxiv.org/abs/2611.21517
- **논문명**: Lazy-MOSAIC: Accelerating Skill-Centric Manipulation Planning with Learned Skill-Effect World Models
- **저자**: Itamar Mishani, Mukund Krishnakumar, Oren Salzman, Maxim Likhachev *(arXiv 메타데이터 순서; 본문은 앞의 두 저자를 공동 기여로 표시)*
- **최초 제출**: 2026-11-16 18:10:52 UTC
- **분석 버전·상태**: v1; arXiv에 심사 중으로 표시
- **발견 경로**: 최신 로보틱스 논문 목록 검색 → arXiv 전문 → 논문이 연결한 프로젝트 페이지
- **확인일**: 2026-11-17; 별도 수정본은 확인하지 않음

**요약**

Lazy-MOSAIC은 여러 조작 기술을 이어 붙이는 계획기의 계산을 줄인다. 학습 모델이 기술의 성공 가능성과 결과 상태를 먼저 예측한다. 유망한 경로만 비싼 물리 시뮬레이션으로 확인하고, 예측이 틀리면 관련 부분을 고친다. 반환 계획의 모든 기술은 시뮬레이터에서 검증하지만, 이것이 실제 환경의 안전 보장은 아니다.

**방법론**

Deep Sets 기반 앙상블이 물체 집합과 기술 조건을 입력받는다. 물체 순서에 의존하지 않도록 정보를 모으고, 모델 간 불일치를 불확실성으로 쓴다. 예측 그래프와 검증 그래프를 분리하며, 검증된 앞선 상태에서 다음 기술을 시뮬레이션한다.

**주요 기여**

핵심은 예측 정확도만 높이는 것이 아니라 **예측을 신뢰하는 범위**를 제한하는 설계다. 편집부 관점에서 중요한 질문은 “빠른 모델이 정답을 대신하는가, 비싼 검증의 순서를 정하는가”다. 이 구분은 결과 표를 읽는 기준이 된다.

**실험 결과**

UR10e·ManiSkill3/SAPIEN의 선반 조작 **8개 설정**, 설정당 같은 무작위 구성 **20회**, 계획 제한 **600초**에서 비교했다. 성공은 Lazy-MOSAIC **104/160**, MOSAIC **81/160**이었다. 어려운 설정의 평균 시뮬레이터 질의는 **41.3회 대 134.5회**다.

표 1에서 렌치 재배치 중간 난도는 **60.3초·11/20 성공** 대 **397.2초·6/20 성공**이다. 시간은 성공한 실행만의 평균이며 로봇 동작 시간은 제외한다. 따라서 같은 성공 사례의 짝 비교나 전체 처리 시간의 6.6배 개선으로 표현하지 않는다.

**맥락**

최근 호의 로봇 정책 개선·운동 계획과 비교하면, 이번 대상은 기술 조합 탐색이다. 로봇의 동작 능력 자체와 계획기의 계산 절약을 분리해서 읽는 것이 유용하다. 어느 하나가 다른 쪽의 개선을 자동 보장하지 않는다.

**실무 시사점**

- **대상**: 시뮬레이터 호출이 병목인 조작 계획팀.
- **방법**: 기존 계획기, 예측으로 순위만 정하는 방식, 검증을 미루는 방식을 동일 문제에서 비교한다. 성공률과 함께 실패·시간 초과를 포함한 총 대기 시간, 질의 수, 그래프 복구 비용을 기록한다.
- **완료 기준**: 사전에 합의한 성공률을 유지하면서 전체 비용이 줄어야 한다. 실제 로봇 도입은 별도의 저위험 검증과 정지 조건을 거친다. 이는 편집 제안이며 수행 결과가 아니다.

**한계**

학습·평가는 같은 작업 공간과 물체 종류를 사용한다. 새로운 작업장에 대한 일반화와 시뮬레이션-현실 오차는 별도 문제다. 가장 어려운 렌치 설정의 성공은 **4/20**에 그쳐 범용 해결로 보기 어렵다. 실제 로봇 시연을 시뮬레이션의 160회 평가와 합산하지 않는다.

논문이 연결한 사이트는 기존 MOSAIC 프로젝트 내용을 보여준다. 확인 범위에서 Lazy-MOSAIC 전용 공개 코드·체크포인트를 찾지 못했으므로, 기존 프로젝트를 새 방법의 재현 패키지로 소개하지 않는다. 원문 알고리즘은 읽었지만 구현 검토·독립 실행은 하지 못했다.
