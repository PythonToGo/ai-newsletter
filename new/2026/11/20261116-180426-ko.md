## 이번 주 연구 동향

최근 호에서는 추론 압축과 국소 학습 규칙을 다뤘다. 이번에는 문서 AI의 평가 지표를 살핀다. 원문과 거의 같은 문장이라도 금액이나 부정 표현 하나가 바뀌면 실제 의미는 달라진다. 반대로 표의 표현 형식만 달라졌다면 정보 손실이 아닐 수 있다. ParseBench-2는 이 두 종류의 차이를 구별하려는 연구다.

중요한 전환은 모델을 평가하기 전에 **평가 함수가 원하는 오류에 반응하는지 시험한다**는 점이다. 다만 오류의 중요도는 자연법칙처럼 주어지지 않는다. 어느 오류를 치명적으로 볼지 명시하고 그 선택을 검토할 수 있게 만드는 것이 핵심이다. 한 벤치마크의 높은 점수가 모든 업무의 안전한 자동 처리를 보장하지는 않는다.

- **확인일**: 2026-11-16

**요약**

ParseBench-2는 문서 변환 결과의 정보 보존과 오류 심각도를 함께 평가하는 벤치마크다. 잘못된 숫자나 표 머리글 연결처럼 의미를 바꾸는 오류와, 의미를 유지하는 형식 차이를 구별한다. 지표를 고정된 정답으로 취급하지 않고 통제된 변형에 대한 반응부터 검증한다. 모델을 새로 학습하는 방법이 아니라 평가 기준 자체를 설계·점검하는 연구다.

**방법론**

먼저 오류를 critical·major·minor·benign으로 분류하는 정책과 기대 감점 범위를 정한다. 고정된 정책 아래 코딩 에이전트가 지표 구현을 수정하고 사람이 검토한다. 텍스트·서식·표·차트·양식의 최종 점수는 내용 회복 점수와 오류 기반 상한 중 작은 값이다. 시각적 위치 연결 차원에는 같은 상한을 적용하지 않는다.

공개 README는 전체를 텍스트·서식·표·차트·위치 연결·양식의 6개 차원으로 나눈다. `next_score.py`를 직접 읽으면 각 차원은 정해진 하위 집합 가중치로 집계되고, 전체는 6개 차원의 단순 평균이다. 일부 하위 집합이 빠지면 해당 차원과 전체 점수를 누락 상태로 남긴다. 일부 능력만 평가한 점수를 전체 점수처럼 제시하지 않도록 한 처리다.

**주요 기여**

공개 구현은 2,645개 문서의 4,317개 페이지 수준 사례와 600개 양식 페이지를 안내한다. 오류를 많이 찾았다는 설명만 남기는 대신, 무엇을 얼마나 감점할지 정책과 시나리오로 드러낸다. 사용자는 같은 파서 출력을 다시 생성하지 않고도 평가 정책을 검토할 출발점을 얻는다.

기여를 읽을 때 ‘사람의 중요도 판단과 가까움’과 ‘실제 업무의 손실을 예측함’을 구분해야 한다. 전자는 논문이 평가하는 대상이고 후자는 별도 현장 검증 과제라는 것이 편집부의 해석이다.

**실험 결과**

동일한 통제 시나리오에서 지표를 비교한 저자 실험에서, 표의 정책 준수 요약 점수 PCS는 내용 지표만 쓸 때 **50.0**, 심각도 상한과 결합할 때 **87.8**이었다. PCS는 파서 정확도가 아니라 정해진 감점 정책을 지표가 얼마나 따르는지 요약한 수치다. 시험한 무해한 변형에 벌점을 주는 비율은 각 시험군에서 최대 **3.4%**였다.

별도의 파서 비교에는 전용 파서 19개, 직접 비전 모델 16개, 공개 가중치 모델 9개 구성이 포함된다. 구성별 실행은 한 번이며, 문서 단위로 묶은 2,000회 부트스트랩의 95% 신뢰구간은 반복 실행 변동을 포함하지 않는다. 따라서 이 구간만으로 API의 실행 안정성을 설명할 수 없다.

**맥락**

문자 일치율이 높아도 결정에 필요한 사실은 틀릴 수 있다. 예를 들어 긴 표에서 한 숫자만 바뀌면 평균 문자열 차이는 작다. 반면 같은 표를 다른 마크업으로 표현했다고 반드시 정보가 손실된 것은 아니다. 두 경우를 구별하는 평가가 문서 검색·추출 시스템에 유용하다는 것이 이번 연구의 문제의식이다.

개발 주체가 비교 대상인 LlamaParse도 제공한다는 점은 해석에 중요하다. 공개 코드·출력은 검토를 가능하게 하지만 정책의 중립성을 자동 보장하지 않는다. 최신 저장소의 순위표와 논문 v1의 표도 갱신 시점이 다를 수 있어 혼합하지 않았다.

**실무 시사점**

- **대상**: OCR·문서 변환·구조화 추출 시스템을 비교하는 ML 및 데이터 엔지니어.
- **방법**: 기존 출력 복사본에서 숫자 변경, 부정 표현 삭제, 표 머리글 교환, 의미를 보존한 형식 변경을 하나씩 만든다. 각 변경이 어느 정도 감점돼야 하는지 업무 담당자가 먼저 정하고, 기존 지표와 심각도 기반 지표를 비교한다. 파서 호출과 저장 출력의 재채점은 분리한다.
- **완료 기준**: 중요한 오류에 사전 합의한 감점이 발생하고 무해한 차이에 과도한 벌점이 없으며, 누락 차원을 전체 점수로 포장하지 않는 것이다. 최종 선택은 실제 업무 실패율과도 대조한다. 이는 편집부의 제안이며 이번에 실행한 실험이 아니다.

**한계**

중요도 정책은 저자의 판단이며 다른 업무에서 그대로 최적이라는 보장은 없다. 정책에 맞추도록 개발한 지표를 같은 계열 시나리오로 평가하므로, 새로운 오류 유형에 대한 독립 검증이 중요하다. 탐지되지 않은 오류는 상한에도 반영되지 않는다.

README는 기본 채점이 결정적·규칙 기반이라고 설명하지만, 파서 실행은 선택한 공급자의 API를 호출할 수 있으며 차트 정규화에는 선택적 LLM 기능도 있다. 공개 코드가 곧 무료 실행 전체 경로라는 뜻은 아니다. 이번에는 문서·코드만 읽었고 패키지나 레거시 파이프라인을 실행하지 않았으며 유료 API도 호출하지 않았다. ParseBench-1과 2의 점수는 직접 비교하지 않는다.
