## 논문 분석

### 1. cuRoboV2-Fast: Fast Torque-Limited Collision-Free Motion Planning

- **출처**: Balakumar Sundaralingam, Adithyavairavan Murali, Stan Birchfield · arXiv
- **점수**: 8.2/10 (편집 선정 점수)
- **URL**: https://arxiv.org/abs/2611.06913
- **분석 버전**: v1, HTML 표기 2026-11-04 · **확인일**: 2026-11-08
- **발견 경로**: 최근 로보틱스 논문 탐색 → 원문·공식 README
- **상태**: 프리프린트; 구현 공개

**요약**

cuRoboV2-Fast는 충돌과 관절 토크 한계를 고려하는 GPU 동작 계획기다. B-spline으로 궤적을 표현하고 경로 위의 시간 배분도 최적화한다. 운반 물체의 무게가 바뀌는 상황을 다룬다. 계획 지연과 실행 시간을 따로 줄이려는 접근이다.

**방법론**

필요할 때 RRT로 초기 경로를 찾고 궤적 최적화와 TimeOpt 시간 조정을 결합한다. 역동역학 계산은 하중에 따른 토크를 반영한다. 이는 학습된 정책의 성공률 순위와 다른 종류의 시스템 기여다.

**주요 기여**

제약을 만족하는 경로를 빨리 계산하는 것과 빨리 실행 가능한 경로를 만드는 것을 결합했다. GPU 병렬화만이 아니라 최적화 반복 수와 표현 방식도 바꾼다.

**실험 결과**

저자는 3kg 하중·RTX 5090 조건에서 평균 계획 4.4ms, cuRoboV2 대비 14.7배 속도를 보고한다. 실제 YAM의 완료된 이송 사이클 평균은 5.93초로 34.6% 짧다. 그러나 계획은 실제 사이클의 1%에 불과하다. 실제 비교는 약 50회 대 15회 완료 사이클로 표본 수가 다르고, 완료 조건부 시간은 전체 시도 성공률이 아니다.

**맥락**

계산 벤치마크의 배수를 로봇 전체 처리량 배수로 옮기면 잘못된 도입 판단이 된다. 그리퍼와 인식·대기 시간도 시스템 병목으로 남는다.

**실무 시사점**

자동화팀은 동일 하중·충돌 여유·토크 제한으로 비교하고, 계획 지연과 전체 사이클을 함께 측정하자. 완료 기준은 실패·재시도를 포함한 처리량과 제약 위반을 함께 보고하는 것이다. 읽기 순서는 실험 IV-C~G → 한계 → README다.

**한계**

샘플에서 검사한 제약을 연속 시간의 절대 안전 보장으로 해석하지 않는다. 독립 재현은 하지 않았다. 공식 README는 v2에서 API가 크게 바뀌었으며 v1 의존 사용자는 v0.7.8에 고정하라고 안내한다. 본체 Apache 2.0과 로봇 자산별 라이선스도 구분해야 한다. 이번에는 설치·실행하지 않았다.
