## 이번 주 연구 동향

이번 주 논문들은 공통적으로 두 가지 방향을 향해 수렴한다. 첫째는 AI agent의 자율성 심화이고, 둘째는 기존 파이프라인의 구조적 병목 해소다. 수학 증명 agent(Erdős 문제 자율 해결), source-level self-rewriting을 수행하는 MOSS, 그리고 millisecond 단위 checkpoint/rollback을 가능케 하는 DeltaBox는 모두 '사람의 개입 없이 얼마나 깊이 탐색하고 스스로 개선할 수 있는가'라는 질문에 답하려 한다. 여기에 tokenisation을 convex optimisation으로 재정의한 ConvexTok까지 더하면, 이번 주 연구의 저변에는 greedy 또는 heuristic에 의존하던 기존 설계를 수학적으로 엄밀하게 재구성하려는 흐름이 뚜렷하다.

방법론적으로는 verification loop의 반복 등장이 눈에 띈다. 수학 증명 agent는 LLM generation과 Lean verifier를 교대로 돌리는 generation-verification cycle을 핵심으로 삼고, MOSS 역시 source-level patch 생성 후 자동 검증 단계를 필수 루프로 설계한다. DeltaBox의 delta 기반 C/R은 이러한 고빈도 verification loop를 인프라 수준에서 뒷받침하는 역할을 한다. 즉, 상위 알고리즘의 반복 탐색 패턴과 하위 시스템의 효율화가 서로를 전제하는 구조로 맞물리고 있다.

남겨진 과제도 선명하다. Erdős 문제 해결률은 약 2.5%에 그쳤고, MOSS의 self-rewriting은 아직 routing logic 같은 국소적 수정에 집중돼 있다. ConvexTok 역시 downstream task 성능 개선은 미검증 상태다. 결국 자율성의 범위를 어디까지 확장할 수 있는지, 그리고 그 과정에서 발생하는 비용(compute, 안전성, 예측 불가능성)을 어떻게 통제할지가 다음 스텝의 핵심 과제로 남는다.

ML 엔지니어에게 가장 직접적인 실무 시사점은 DeltaBox에서 나온다. Test-time tree search나 RLHF/RLVR 파이프라인을 운영 중이라면, sandbox의 C/R latency가 전체 throughput의 숨겨진 병목일 가능성이 높다. Delta 기반 C/R 설계를 인프라에 도입하는 것만으로도 agent 탐색 성능을 의미 있게 끌어올릴 수 있다.

### 1. Advancing Mathematics Research with AI-Driven Formal Proof Search

- **출처**: arxiv
- **점수**: 7.6
- **URL**: http://arxiv.org/abs/2605.22763v1

**요약**

이 논문은 LLM이 수학적 추론에서 뛰어난 성능을 보이지만 신뢰성 부족으로 실제 수학 연구에 활용하기 어렵다는 문제를 다룬다. 해결책으로 LLM이 Lean과 같은 formal proof language로 증명을 생성하고 자동 검증하는 agent 시스템을 구축했다. 353개의 미해결 Erdős 문제 중 9개를 문제당 수백 달러 비용으로 자율적으로 해결했고, OEIS conjecture 492개 중 44개를 증명했다. 이는 AI 기반 formal proof search가 실제 수학 연구에 실질적으로 기여할 수 있음을 최초로 대규모로 입증한 연구다.

**방법론**

핵심 아이디어는 LLM의 창의적 증명 생성 능력과 Lean proof assistant의 기계적 정확성 검증을 결합해 신뢰할 수 있는 수학 증명 agent를 구성하는 것이다. Basic agent는 LLM이 Lean 코드로 증명 후보를 생성하면 Lean verifier가 즉시 정오를 판별하고, 실패 시 피드백을 LLM에 돌려보내는 generation-verification loop를 반복한다. 더 발전된 agent는 이 loop에 추가적인 탐색 전략과 비용 최적화를 적용해 어려운 문제에서의 효율을 개선했다.

**주요 기여**

1. 미해결 Erdős 문제 353개와 OEIS conjecture 492개를 대상으로 AI formal proof search를 최초로 대규모 평가하여 실제 수학 연구에서의 실용성을 입증했다.
2. LLM generation과 Lean verification을 결합한 agent가 문제당 수백 달러 비용으로 9개의 open Erdős 문제를 자율 해결하는 성과를 달성했다.
3. Basic agent와 고급 agent의 설계 비교를 통해 agent 구조가 성능과 비용에 미치는 영향을 분석하고, combinatorics·quantum optics 등 실제 연구 분야에 배포 사례를 제시했다.

**실험 결과**

353개 미해결 Erdős 문제 중 9개 해결 (약 2.5%), 492개 OEIS conjecture 중 44개 증명 (약 8.9%). 가장 강력한 agent가 문제당 수백 달러(a few hundred dollars) 비용으로 Erdős 문제를 해결했으며, basic agent도 동일한 Erdős 문제를 해결했으나 가장 어려운 문제에서는 더 높은 비용이 소요됨.

**맥락**

LLM 기반 수학 추론은 빠르게 발전하고 있지만, 모델이 틀린 증명을 자신 있게 생성하는 hallucination 문제로 인해 연구자들이 결과를 신뢰하기 어렵다. Lean 같은 formal verification 시스템과 LLM을 결합하면 증명의 정확성을 기계적으로 보장할 수 있어, 이 조합이 미해결 수학 문제에 실제로 통하는지 검증하는 것이 중요한 시점이다. 기존 연구들은 주로 이미 알려진 문제나 competition 문제에 집중했으나, 이 논문은 실제 open problem에 대한 최초의 대규모 평가를 수행했다.

**실무 시사점**

ML 엔지니어는 LLM generation과 Lean-based formal verification을 교대로 수행하는 basic agent 구조만으로도 상당한 성과를 낼 수 있음을 확인할 수 있으며, 이를 combinatorics, graph theory, algebraic geometry 등 다양한 수학 분야 연구 파이프라인에 통합할 수 있다. 문제당 수백 달러 수준의 비용으로 미해결 문제를 공략할 수 있다는 점은 실용적인 cost-benefit 기준을 제시하며, 특히 난이도가 낮은 open problem 탐색 자동화에 즉시 적용 가능하다.

**한계**

9/353이라는 Erdős 문제 해결률은 전체의 약 2.5%에 불과하며, 가장 어려운 문제들에서는 비용이 급격히 증가해 현재 접근법의 확장성에 한계가 있다. 또한 Lean으로 formalize하기 어려운 문제나 기존 Lean mathlib에 필요한 lemma가 없는 경우 agent가 실패할 가능성이 높아, 적용 가능한 문제 유형이 제한된다.

**관련 링크**

- http://arxiv.org/abs/2605.22763v1

### 2. DeltaBox: Scaling Stateful AI Agents with Millisecond-Level Sandbox Checkpoint/Rollback

- **출처**: arxiv
- **점수**: 7.2
- **URL**: http://arxiv.org/abs/2605.22781v1

**요약**

LLM 기반 AI agent는 test-time tree search나 reinforcement learning 같은 고빈도 상태 탐색을 위해 sandbox의 빠른 checkpoint/rollback(C/R)이 필수적이다. 기존 방식은 전체 상태를 복제해 수백 밀리초~수 초의 latency가 발생하는 병목이 있었다. 이 논문은 연속된 checkpoint 간 상태가 매우 유사하다는 관찰을 바탕으로, 변경분(delta)만 저장하는 OS-level abstraction인 DeltaState를 제안한다. 그 결과 C/R latency를 밀리초 수준으로 대폭 단축해 대규모 agent 탐색을 가능하게 한다.

**방법론**

핵심 아이디어는 연속된 checkpoint 간 변경분(delta)만 저장·복원하는 change-based transactional C/R이다. 이를 위해 파일 시스템 상태를 layer로 구조화하고 동적으로 delta를 추적하는 DeltaFS와, 프로세스 메모리·컨텍스트의 변경분만 캡처하는 DeltaProc 두 가지 co-designed OS 메커니즘을 새로운 OS abstraction인 DeltaState 위에 구현한다. 두 메커니즘은 AI agent의 sandbox 수명주기에 맞춰 트랜잭션 단위로 동작해 atomic하고 일관된 C/R을 보장한다.

**주요 기여**

1. 연속 checkpoint 간 상태 유사성을 활용한 delta 기반 C/R이라는 핵심 insight를 제시하고, 이를 실현하기 위한 새로운 OS-level abstraction DeltaState를 설계함.
2. 파일 시스템 C/R을 위한 DeltaFS와 프로세스 상태 C/R을 위한 DeltaProc를 co-design하여 밀리초 수준의 end-to-end sandbox C/R latency를 달성함.
3. LLM agent의 test-time tree search 및 RL 학습 시나리오에서 기존 full-duplication 방식 대비 대규모 fan-out과 deep search가 실용적으로 가능함을 실증함.

**실험 결과**

논문 본문 발췌 범위 내에서 구체적인 수치 benchmark 결과는 제공되지 않았으나, 기존 full-duplication 기반 C/R 대비 latency를 수백 밀리초~수 초에서 밀리초(millisecond) 수준으로 단축한다고 보고하고 있으며, 이를 통해 deep search 및 large-scale fan-out 시나리오에서의 병목을 해소함을 주장한다.

**맥락**

AI agent가 복잡한 작업을 수행할 때 tree search나 RL 기반 탐색은 수십~수백 번의 sandbox C/R을 반복해야 하는데, 기존 full-duplication 방식은 이 과정에서 심각한 latency 병목을 일으킨다. 특히 deep search나 large-scale fan-out 시나리오에서는 C/R 비용이 전체 추론 시간을 지배하게 되어 실용적인 배포가 어렵다. OS 수준의 지원 부재로 인해 delta 기반 C/R을 구현하는 것 자체가 비자명한 문제였다.

**실무 시사점**

ML 엔지니어는 DeltaFS와 DeltaProc 두 OS 메커니즘을 활용해 기존 sandbox 인프라 대비 C/R latency를 밀리초 수준으로 낮출 수 있으며, 이는 test-time compute scaling이나 RLHF/RLVR 파이프라인의 throughput을 직접적으로 향상시킨다. 특히 coding agent, tool-use agent처럼 반복적인 환경 상태 분기가 필요한 시스템에서 DeltaBox를 sandbox 백엔드로 채택하면 대규모 병렬 탐색이 현실적으로 가능해진다.

**한계**

논문이 제안하는 DeltaState abstraction은 새로운 OS-level 지원을 요구하므로 기존 커널이나 컨테이너 환경에 바로 적용하기 어렵고, 범용 배포를 위한 upstream OS 통합 경로가 아직 불명확하다. 또한 delta가 누적될 경우 장기 실행 시나리오에서의 메모리·스토리지 overhead에 대한 분석이 추가로 필요하다.

**관련 링크**

- http://arxiv.org/abs/2605.22781v1

### 3. Tokenisation via Convex Relaxations

- **출처**: arxiv
- **점수**: 6.9
- **URL**: http://arxiv.org/abs/2605.22821v1

**요약**

현재 NLP pipeline에서 필수적인 tokenisation 과정을 개선하기 위해, 기존의 greedy 방식(BPE, Unigram) 대신 linear program으로 문제를 재정의하고 convex optimisation으로 푸는 새로운 알고리즘 ConvexTok을 제안한다. ConvexTok은 intrinsic tokenisation metric과 language model의 bits-per-byte(BpB)를 일관되게 향상시키며, downstream task 성능도 부분적으로 개선한다. 특히 사용자가 자신의 tokeniser가 특정 objective 기준으로 optimal에서 얼마나 떨어져 있는지 lower bound를 통해 인증(certify)할 수 있으며, 일반적인 vocabulary size에서 optimal 대비 1% 이내임을 실험적으로 확인했다.

**방법론**

핵심 아이디어는 tokeniser vocabulary 선택 문제를 linear program으로 정식화하여 convex optimisation 도구로 전역 최적해를 탐색하는 것이다. 기존 BPE/Unigram이 각 병합/제거 단계에서 greedy하게 결정을 내리는 것과 달리, ConvexTok은 vocabulary 전체를 하나의 최적화 목표 아래 동시에 고려한다. Convex relaxation을 통해 정수 최적화 문제를 연속 공간에서 풀고, lower bound를 계산하여 얻어진 해의 optimality gap을 인증한다.

**주요 기여**

1. Tokeniser 구성 문제를 linear program으로 재정식화하고 convex optimisation으로 푸는 새로운 알고리즘 ConvexTok을 제안.
2. Intrinsic tokenisation metric 및 language model의 bits-per-byte(BpB)에서 BPE/Unigram 대비 일관된 성능 향상을 실험적으로 입증.
3. Lower bound 계산을 통해 tokeniser의 optimality gap을 정량적으로 인증하는 기능 제공 — 일반적인 vocabulary size에서 optimal 대비 1% 이내임을 확인.

**실험 결과**

ConvexTok은 intrinsic tokenisation metric과 language model의 bits-per-byte(BpB)에서 BPE 및 Unigram 대비 일관된 향상을 보였다. Optimality 인증 실험에서는 일반적인 vocabulary size 기준으로 optimal 대비 1% 이내의 gap을 달성했다. Downstream task 성능 향상은 일부 태스크에서 관찰되었으나 일관되지 않았다.

**맥락**

BPE와 Unigram 같은 기존 tokenisation 알고리즘은 vocabulary 전체를 고려하지 않고 locally optimal한 결정을 내리는 greedy 방식이라, 전역적으로 최적의 vocabulary를 보장하지 못한다는 근본적인 한계가 있다. Tokenisation은 모든 NLP 모델의 입력 단계에서 작동하므로, 이 단계의 품질이 downstream task 전반에 영향을 미침에도 불구하고 optimality 보장 연구는 부족했다. 이 연구는 tokeniser 설계를 최적화 문제로 엄밀하게 정식화함으로써 이 공백을 메우려 한다.

**실무 시사점**

ML 엔지니어는 ConvexTok을 기존 BPE/Unigram tokeniser의 drop-in 대안으로 고려할 수 있으며, 특히 language model의 BpB 개선이 일관되게 나타나므로 pretraining 효율성 향상에 직접 활용 가능하다. Lower bound를 통한 optimality 인증 기능은 tokeniser 품질을 정량적으로 검증해야 하는 프로덕션 환경에서 신뢰성 있는 근거를 제공한다.

**한계**

Downstream task 성능 향상은 일관되지 않아(less consistently), 모든 태스크에서 BPE/Unigram 대비 우위를 보장하지 못한다. 또한 linear program 기반 최적화는 greedy 방식보다 계산 비용이 높을 수 있어, 매우 큰 vocabulary size나 대규모 corpus에서의 확장성(scalability)은 추가 검토가 필요하다.

**관련 링크**

- http://arxiv.org/abs/2605.22821v1

### 4. MOSS: Self-Evolution through Source-Level Rewriting in Autonomous Agent Systems

- **출처**: arxiv
- **점수**: 6.9
- **URL**: http://arxiv.org/abs/2605.22794v1

**요약**

MOSS는 배포 후 정적으로 고정되는 기존 autonomous agent 시스템의 한계를 극복하기 위해, agent가 스스로 소스 코드를 직접 수정·진화할 수 있는 self-evolution 프레임워크를 제안한다. 기존 self-evolving agent들은 skill file, prompt, memory schema 등 텍스트 수준의 artifact만 수정할 수 있어 routing, hook ordering, state invariant 등 코드 레벨의 구조적 결함은 해결할 수 없었다. MOSS는 source-level rewriting을 통해 이러한 구조적 실패까지 수정 가능하게 하며, 각 evolution은 실패 사례에 anchor되어 검증 후 적용된다. 이를 통해 agent가 반복적 실패를 인간 개입 없이 스스로 수정하고 지속적으로 성능을 향상시킬 수 있음을 보인다.

**방법론**

핵심 아이디어는 agent가 실패 사례를 anchor로 삼아 소스 코드 자체를 직접 rewriting함으로써 텍스트 artifact 수정 범위를 초월한 구조적 self-evolution을 수행하는 것이다. 각 evolution cycle은 실패 감지 → 원인 분석 → source-level patch 생성 → 자동 검증 → 적용의 단계로 구성되며, 수정은 base model의 compliance에 의존하지 않고 deterministic하게 코드에 반영된다. 이를 통해 routing, hook, state management 등 기존 self-evolution 방법으로는 접근 불가능했던 코드 레이어의 결함까지 수정 범위에 포함시킨다.

**주요 기여**

1. 기존 self-evolving agent의 텍스트 artifact 수정 한계를 지적하고, source-level rewriting이 Turing-complete하며 모든 텍스트 수정 범위의 strict superset임을 이론적으로 논증함.
2. Production agentic substrate에서 실패 사례 기반 source-level self-rewriting을 수행하는 MOSS 시스템을 설계 및 구현함.
3. Long-context drift나 base model compliance 문제 없이 deterministic하게 동작하는 evolution 메커니즘을 제시하여 더 안정적인 자율 진화 agent 패러다임을 제안함.

**맥락**

현재 대부분의 agentic system은 배포 이후 사용자 상호작용으로부터 학습하지 못하며, 반복적인 실패가 다음 인간 주도 업데이트까지 지속된다. 기존 self-evolving agent 연구들은 prompt나 skill file 같은 텍스트 수준 artifact만 수정 범위로 한정하여, 코드 구조에 내재된 근본적 결함을 해결하지 못하는 구조적 한계를 가진다. Source-level adaptation은 Turing-complete하고 모든 텍스트 수정 범위의 strict superset이므로, 이를 활용하면 훨씬 더 광범위한 종류의 실패를 자율적으로 수정할 수 있다.

**실무 시사점**

ML 엔지니어는 MOSS의 접근법을 참고하여 production agentic system에 source-level self-rewriting 루프를 설계함으로써, 반복적 버그 수정과 구조적 개선을 인간 개입 없이 자동화하는 파이프라인을 구축할 수 있다. 특히 routing logic, hook ordering, dispatch 등 기존 prompt-tuning이나 RAG 기반 접근으로는 수정 불가능했던 코드 레벨 결함을 자동으로 패치하는 시스템 설계에 직접 응용 가능하다. Long-context drift에 취약한 prompt-based evolution 대신 deterministic하게 동작하는 code rewriting 기반 evolution이 더 안정적인 production 환경을 제공할 수 있다.

**한계**

소스 코드를 직접 수정하는 특성상 잘못된 rewriting이 시스템 전체를 손상시킬 수 있는 안전성 리스크가 존재하며, 검증 메커니즘의 완전성에 대한 보장이 어렵다. 또한 논문이 공개된 시점 기준으로 실험 규모와 다양한 production 환경에서의 일반화 가능성에 대한 충분한 검증이 제한적일 수 있다.
