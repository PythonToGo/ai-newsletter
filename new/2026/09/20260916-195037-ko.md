## 이번 주 연구 동향

이번 주 논문들은 표면적으로는 서로 다른 주제를 다루지만, 공통적으로 'LLM을 얼마나 신뢰할 수 있는가'라는 질문에 수렴한다. OPEN-1B는 학습 과정 자체의 감사 가능성을, belief state geometry 연구는 모델 내부 표현의 해석 가능성을, JustFit과 지식 주입 비교 연구는 추론 단계에서의 효율성과 지식 접근 신뢰성을 각각 다루며, 결국 ML 시스템 전반에 걸친 투명성과 제어 가능성이라는 하나의 큰 흐름을 형성한다.

방법론적으로 주목할 점은 latent space 분석과 controlled comparison이 반복적으로 등장한다는 것이다. Belief state 연구는 residual stream activation에 linear probe를 적용해 모델 내부를 해부하고, patching·steering으로 인과 관계를 검증한다. 지식 주입 비교 연구는 ICL, KV-cache 기반 representation, parametric fine-tuning을 동일 조건에서 비교하며 storage budget이라는 단일 변수로 실험을 통제한다. JustFit은 just-in-time materialization이라는 시스템 수준 기법으로 메모리 제약을 우회하며, 이 모든 접근법이 '무엇을 어디에 얼마나 저장할 것인가'라는 representation 설계 문제로 귀결된다.

이 논문들이 남긴 과제는 명확하다. Bitwise reproducibility는 이종 하드웨어 환경에서 확장성이 검증되지 않았고, belief state geometry가 실제 downstream task 성능과 어떻게 연결되는지는 아직 미지수다. 지식 주입 방법론 비교도 oracle 설정에 의존해 realistic retrieval 노이즈 환경에서의 결론이 달라질 수 있다. 세 영역 모두 더 복잡한 실세계 조건에서의 검증이 다음 스텝으로 요구된다.

실무 시사점은 지식 주입 전략 선택에서 즉시 활용 가능하다. 문서 접근 정확도가 보장되는 환경이라면 KV-cache 기반 Cartridges가 fine-tuning 대비 약 10점의 정확도 우위를 제공하지만, 압축률이 50×를 넘는 고압축 환경에서는 parametric 방법이 역전된다. ML 엔지니어는 서비스의 storage budget과 retrieval 정밀도를 먼저 측정한 뒤 방법론을 선택하는 데이터 기반 의사결정 프레임워크를 도입할 것을 권장한다.

### 1. OPEN-1B: A Fully Auditable Training Run

- **출처**: arxiv
- **점수**: 7.6
- **URL**: http://arxiv.org/abs/2609.17380v1

**요약**

오픈소스 언어 모델은 가중치와 학습 데이터를 공개해도 floating-point arithmetic의 비결합성(non-associativity) 때문에 실제로 재현 가능하다고 증명할 수 없다는 근본적인 문제가 있다. 이 논문은 'fully auditable'이라는 새로운 투명성 수준을 제안하며, 학습 중 모든 데이터 샘플에 대한 모든 연산을 이종(heterogeneous) commodity hardware에서 bitwise 수준으로 독립 재현할 수 있도록 한다. GPU kernel reduction, 데이터 배치 순서 등 학습의 비결정성(nondeterminism) 원인에 명확한 순서를 부여함으로써 이를 달성하며, 이를 통해 미공개 데이터, 주입된 bias, backdoor 등의 가능성을 원천 차단할 수 있는 1B 파라미터 규모의 모델 학습 실험을 공개한다.

**방법론**

핵심 아이디어는 학습 과정에서 발생하는 모든 비결정성(nondeterminism)의 원인—GPU kernel reduction 순서, 데이터 배치 순서 등—에 명확하고 고정된 순서를 부여하여 bitwise 수준의 재현성을 보장하는 것이다. 이를 위해 floating-point 연산의 비결합성 문제를 우회하는 결정론적 연산 순서를 강제하고, 이종 commodity hardware 간에도 동일한 결과를 낼 수 있도록 학습 파이프라인 전체를 재설계하였다. 결과적으로 누구든 공개된 레시피로 학습을 재실행하면 동일한 checkpoint를 bitwise 수준에서 독립적으로 검증할 수 있다.

**주요 기여**

1. 'Fully auditable' 이라는 새로운 모델 투명성 계층을 정의하고, 이종 하드웨어에서 bitwise 재현성을 달성하는 방법론을 제시함.
2. GPU kernel reduction 및 데이터 배치 순서 등 학습 비결정성의 원인을 체계적으로 분류하고 이를 제어하는 구체적인 기법을 공개함.
3. 1B 파라미터 규모의 완전 감사 가능한 학습 실험(OPEN-1B)을 공개하여, proof-of-learning이나 proof-of-training-data로도 해결하지 못했던 undisclosed data 및 backdoor 문제를 원천적으로 차단할 수 있는 실증 사례를 제공함.

**맥락**

기존 오픈소스 LLM들은 가중치, 데이터, 학습 레시피를 공개하더라도 proof-of-learning이나 proof-of-training-data 같은 기법으로도 실제 학습 과정의 무결성을 검증할 수 없었다. 특히 동일 하드웨어에서만 동작하는 deterministic mode는 이종 하드웨어 간 검증을 불가능하게 하여, 모델 제공자가 undisclosed data나 backdoor를 삽입해도 외부에서 탐지할 방법이 없었다. AI 신뢰성과 규제 요구가 높아지는 현시점에서 학습 과정의 완전한 감사 가능성(auditability)은 매우 중요한 연구 방향이다.

**실무 시사점**

ML 엔지니어는 이 연구에서 제안한 학습 비결정성 원인 분류 및 제어 방법을 참고하여, 자체 학습 파이프라인의 재현성을 높이는 데 직접 활용할 수 있다. 특히 규제 환경이나 고신뢰성이 요구되는 프로덕션 환경에서 모델 학습의 감사 추적(audit trail)을 구축할 때, 이 논문이 제시하는 bitwise reproducibility 달성 방법론이 실질적인 엔지니어링 가이드로 활용될 수 있다.

**한계**

현재 공개된 실험은 1B 파라미터 규모에 한정되어 있어 대규모 모델로의 확장성이 검증되지 않았으며, fully auditable 학습을 위해 부과되는 연산 순서 제약이 학습 속도나 효율성에 미치는 영향이 충분히 분석되지 않은 상태이다.

**관련 링크**

- http://arxiv.org/abs/2609.17380v1

### 2. JustFit: 200K-Token LLM Serving on a 24 GiB Laptop with Just-in-Time State Management

- **출처**: arxiv
- **점수**: 7.1
- **URL**: http://arxiv.org/abs/2609.17475v1

**요약**

JustFit은 24 GiB 메모리를 가진 노트북에서 200K token 이상의 long-context LLM inference를 가능하게 하는 MLX 기반 runtime 시스템이다. KVExec(압축된 KV execution), PhaseSwap(컴포넌트 residency 관리), StateTrans(state 보존 serving 전환)의 세 가지 메커니즘을 결합하여 model weight quantization과 독립적으로 메모리를 관리한다. M4 Pro MacBook에서 Qwen3-27B MXFP4 모델로 196,608 input + 16,384 output token을 처리하며, 기존 mlx-vlm baseline 대비 single-request context를 6.93배(30,720 → 212,992 positions) 확장하는 데 성공했다.

**방법론**

핵심 아이디어는 KV cache와 실행 state를 필요한 순간에만 메모리에 올리는 just-in-time materialization로, model weight quantization과 직교(orthogonal)하게 동작한다. KVExec은 KV cache를 압축된 형태로 실행하며 reconstruction을 fuse하고, PhaseSwap은 prefill/decode phase에 따라 컴포넌트의 메모리 residency를 동적으로 전환하며, StateTrans는 serving 전환 시 state를 보존하여 context 손실 없이 메모리를 해제·재할당한다.

**주요 기여**

1. KVExec: compressed KV execution과 reconstruction fusion을 결합하여 KV cache의 메모리 footprint를 model quantization과 독립적으로 줄이는 메커니즘 제안
2. PhaseSwap + StateTrans: prefill/decode phase 전환 및 multi-request serving 시 just-in-time residency 관리와 state 보존을 동시에 달성하는 통합 runtime 설계
3. 실증적 검증: 24 GiB M4 Pro MacBook에서 Qwen3-27B MXFP4로 212,992 positions(baseline 대비 6.93x) context 처리 및 19.11 tokens/s throughput 달성

**실험 결과**

- Full-execution capacity: 24 GiB M4 Pro MacBook, Qwen3-27B MXFP4 기준 196,608 input + 16,384 output token 처리 완료 (3회 독립 실행)
- Single-request context: 30,720 positions(mlx-vlm baseline) → 212,992 positions (6.93x 향상)
- Two-request aggregate: 229,376 positions 유지
- Throughput: 32K input + 64 output probe에서 19.11 tokens/s
- Memory footprint: 32K+6K 반복 workload 기준 median peak process footprint 16,374 MiB

**맥락**

오픈소스 LLM의 성능이 향상되면서 로컬 환경에서의 코딩·추론 작업 수요가 급증하고 있지만, long-context inference는 KV cache가 GPU/통합 메모리를 빠르게 소진시켜 일반 소비자용 노트북에서는 사실상 불가능했다. 기존 접근법은 주로 model weight quantization에 의존했으나, KV cache와 activation state의 동적 메모리 관리 문제는 미해결 상태였다. JustFit은 just-in-time materialization 전략으로 이 문제를 정면 돌파한다.

**실무 시사점**

ML 엔지니어는 Apple Silicon MacBook 환경에서 27B급 모델로 200K token context를 처리하는 실용적인 방법을 JustFit에서 얻을 수 있으며, MLX 기반 프로젝트에 KVExec·PhaseSwap·StateTrans 패턴을 적용해 메모리 효율을 높일 수 있다. 특히 weight quantization과 독립적으로 동작하므로 기존 quantized 모델 파이프라인에 추가 레이어로 통합하기 용이하다.

**한계**

논문에서 제시한 실험은 단일 M4 Pro MacBook 환경에 국한되어 있어 다른 하드웨어(NVIDIA GPU, AMD 등)로의 일반화 가능성이 불명확하다. 또한 19.11 tokens/s의 throughput은 실용적이지만 서버급 GPU 대비 여전히 낮으며, 복잡한 multi-request 시나리오에서의 성능 저하 분석이 충분히 제시되지 않았다.

**관련 링크**

- http://arxiv.org/abs/2609.17475v1
- https://github.com/ml-explore/mlx

### 3. Large Language Models Develop Belief State Geometry In-Context

- **출처**: arxiv
- **점수**: 6.9
- **URL**: http://arxiv.org/abs/2609.17376v1

**요약**

이 연구는 Large Language Model(LLM)이 in-context learning(ICL)을 수행할 때 내부적으로 어떤 표현을 형성하는지 분석합니다. Hidden Markov Model(HMM)에서 생성된 데이터를 LLM에 입력하고, residual stream activation에서 belief state(숨겨진 상태에 대한 posterior distribution)가 선형적으로 디코딩 가능한지 probe를 통해 검증했습니다. 6개의 오픈소스 LLM과 40개의 HMM 조합에서 probe R²값이 0.83~0.99에 달했으며, patching과 steering 개입 실험을 통해 이 표현이 실제 예측에 기능적으로 관여함을 입증했습니다.

**방법론**

핵심 아이디어는 HMM에서 생성된 시퀀스를 LLM에 입력하고, 각 레이어의 residual stream activation으로부터 linear probe를 학습해 belief state(hidden state posterior)를 복원하는 것입니다. 이후 probe가 식별한 subspace에 직접 patching 및 steering 개입을 수행해 해당 표현이 실제 예측에 기능적으로 연결되어 있는지 인과적으로 검증했습니다.

**주요 기여**

1. 6개의 오픈소스 LLM에서 residual stream activation이 HMM belief state를 선형적으로 인코딩함을 R²=0.83~0.99 수준으로 실증적으로 입증
2. Patching과 steering을 통한 인과적 개입 실험으로 belief state 표현의 기능적 관련성 확인
3. 통제된 HMM 환경을 활용한 재현 가능하고 체계적인 ICL 내부 표현 분석 프레임워크 제시

**실험 결과**

40개의 HMM과 6개의 오픈소스 LLM 조합에서 linear probe의 peak R²값이 0.83~0.99 범위로 측정되었으며, belief state subspace에 대한 patching/steering 개입 시 예측 품질이 원본 모델 수준을 유지한 반면, control 개입은 성능을 크게 저하시켰습니다.

**맥락**

LLM이 next-token prediction만으로 학습했음에도 강력한 ICL 능력을 보이는 이유는 아직 명확히 밝혀지지 않았습니다. 특히 LLM 내부에서 어떤 기하학적 표현이 형성되어 ICL을 지원하는지에 대한 mechanistic 이해가 부족한 상황입니다. 이 연구는 통제된 환경(HMM)을 활용해 LLM의 내부 표현과 belief state 사이의 관계를 체계적으로 규명하려 했습니다.

**실무 시사점**

ML 엔지니어는 residual stream activation에서 linear probe를 통해 모델의 내부 belief state를 추출하고 모니터링하는 방식을 실무에 적용할 수 있습니다. 또한 특정 subspace에 대한 patching과 steering 기법이 모델 동작을 제어하는 데 유효함을 확인했으므로, 모델 해석 및 targeted intervention 파이프라인 설계에 참고할 수 있습니다.

**한계**

실험이 HMM이라는 통제된 합성 환경에 한정되어 있어, 실제 자연어 태스크에서도 동일한 belief state geometry가 형성되는지는 추가 검증이 필요합니다. 또한 분석 대상이 오픈소스 LLM 6종으로 제한되어 있어 일반화 가능성에 의문이 남습니다.

**관련 링크**

- http://arxiv.org/abs/2609.17376v1

### 4. Where Should a Document Live: Context, Representations, or Parameters?

- **출처**: arxiv
- **점수**: 6.8
- **URL**: http://arxiv.org/abs/2609.17346v1

**요약**

대규모 언어 모델(LLM)이 사전 학습 데이터 외부의 새로운 지식에 접근하는 방법으로 context window에 문서를 직접 넣는 방식(ICL), KV-cache 기반 representation 주입 방식, fine-tuning 기반 parametric 방식 세 가지를 체계적으로 비교한 연구다. 5개의 knowledge-intensive benchmark에서 controlled 실험을 수행한 결과, oracle 설정에서는 Cartridges(KV-cache 기반)가 거의 모든 storage budget에서 parametric 방법보다 약 10점 높은 정확도를 달성했다. 현실적인 multi-document retrieval 시나리오에서는 Cartridges가 ICL 성능에 필적하는 유일한 방법으로 나타났으며, 각 방법의 효율성·비용·성능 trade-off를 명확히 정량화했다.

**방법론**

핵심 아이디어는 동일한 knowledge-intensive task에서 (1) ICL, (2) KV-cache 기반 Cartridges/Compaction, (3) fine-tuning 기반 parametric adaptation을 storage budget을 변수로 삼아 controlled 비교하는 것이다. 각 방법은 동일한 문서 집합을 입력으로 받아 oracle(단일 문서 접근)과 realistic(multi-document retrieval) 두 가지 시나리오에서 평가되며, storage 대비 정확도 곡선을 통해 각 방법의 효율성 trade-off를 정량화한다. 특히 Cartridges는 문서별로 KV-cache를 미리 계산해 저장하고 inference 시 재사용하는 방식으로, context 길이 증가 없이 새 지식을 주입한다.

**주요 기여**

1. ICL, KV-cache 기반(Cartridges, Compaction), parametric(fine-tuning) 세 가지 지식 주입 패러다임을 5개 knowledge-intensive benchmark에서 동일 조건으로 최초 controlled 비교 수행.
2. Oracle 설정에서 Cartridges(KV)가 거의 모든 storage budget에서 parametric 방법보다 약 10점 높은 정확도를 달성함을 실증적으로 입증.
3. Realistic multi-document retrieval 시나리오에서 Cartridges가 ICL 성능에 필적하는 유일한 방법임을 보이며, 압축률별 성능 저하 패턴을 정량화해 실무 설계 기준 제시.

**실험 결과**

5개 knowledge-intensive benchmark 기준: oracle 설정에서 Cartridges(KV-cache)가 parametric(fine-tuning) 방법 대비 약 10점 높은 정확도 달성. Compaction(KV)은 낮은 압축률에서만 Cartridges와 동등하며, 50× 이상 압축 시 parametric 방법보다 약 10점 낮은 성능. Realistic multi-document retrieval 시나리오에서 Cartridges만이 ICL과 동등한 성능을 기록.

**맥락**

LLM이 최신 정보나 도메인 특화 지식을 활용해야 할 때 어떤 방식으로 새 지식을 주입할지는 실무에서 매우 중요한 설계 결정이지만, 기존 연구들은 각 방법을 개별적으로 평가해 직접 비교가 어려웠다. RAG(Retrieval-Augmented Generation), fine-tuning, KV-cache 재사용 등 다양한 접근법이 혼재하는 상황에서 어떤 조건에서 어떤 방법이 유리한지에 대한 체계적인 분석이 부재했다. 이 논문은 동일한 실험 조건 아래 세 가지 패러다임을 공정하게 비교함으로써 실무 선택 기준을 제시하려 했다.

**실무 시사점**

ML 엔지니어는 storage budget과 retrieval 정확도에 따라 지식 주입 방법을 선택할 수 있는 실용적인 가이드라인을 얻을 수 있다: oracle 환경처럼 정확한 문서 접근이 보장될 때는 Cartridges(KV-cache 기반)가 최선이며, 압축률이 50× 이상으로 높아지면 parametric(fine-tuning) 방식이 경쟁력을 가진다. 실제 multi-document retrieval 파이프라인을 구축할 때 Cartridges가 ICL과 동등한 성능을 내면서도 inference 시 context 길이를 줄일 수 있어 latency·비용 최적화에 활용 가능하다.

**한계**

이 연구는 특정 모델 아키텍처와 5개 benchmark에 한정된 실험이므로 다른 모델 패밀리나 도메인에서의 일반화 가능성은 추가 검증이 필요하다. 또한 Compaction(KV) 방식은 높은 압축률(50× 이상)에서 성능이 크게 저하되는 문제가 미해결 과제로 남아 있다.
