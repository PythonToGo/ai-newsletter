## 이번 주 연구 동향

이번 주 논문들은 표면적으로는 서로 다른 주제를 다루지만, 두 가지 공통된 연구 방향으로 수렴된다. 첫째는 기존 AI 시스템의 신뢰성과 측정 가능성에 대한 근본적 의문이고, 둘째는 대형 모델에 대한 의존도를 줄이면서도 성능을 유지하는 경량화·효율화 전략이다. LLM judge의 reliability failure를 실증한 연구와 compile by training으로 대형 모델 호출을 소형 adapter로 대체하는 연구는 각각 이 두 방향을 정면으로 겨냥하고 있다.

방법론적으로는 '기존 자원의 재활용'이라는 공통 키워드가 반복 등장한다. Terminal-Universe는 새로운 환경을 처음부터 구축하는 대신 agent trajectory를 역재생(replay)하여 workspace를 복원하고, EditVid는 별도의 fine-tuning 없이 diffusion model의 attention mechanism을 조작하는 training-free 접근을 택한다. compile by training 역시 teacher model이 생성한 예제로 compact adapter를 학습시키는 distillation 구조를 활용한다. 세 논문 모두 추가적인 대규모 학습 비용 없이 기존 모델과 데이터를 영리하게 재조합하는 방식으로 문제를 해결한다는 점에서 일관된 흐름을 보인다.

이 논문들이 남긴 과제는 명확하다. LLM judge의 non-determinism 문제는 단순한 기술적 버그가 아니라 평가 인프라 전반의 재설계를 요구하며, training-free video editing과 compile by training은 아직 복잡한 compositional task나 도메인 외 일반화에서 한계를 드러낼 가능성이 크다. 특히 평가 신뢰성 문제가 해결되지 않으면, 다른 연구들의 benchmark 결과 자체가 얼마나 재현 가능한지에 대한 의문이 분야 전체로 확산될 수 있다.

실무 시사점은 단순하지만 중요하다. LLM judge를 데이터 품질 필터링이나 모델 평가 파이프라인에 사용하고 있다면, 지금 당장 동일 입력에 대한 반복 호출로 test-retest reliability를 직접 측정해볼 것을 권한다. black-box API의 non-determinism이 생각보다 훨씬 큰 noise를 만들어내고 있을 수 있으며, 이는 모델 선택과 데이터 curation 결정 전반에 조용히 영향을 미치고 있을 가능성이 높다.

### 1. Clean Engineering, Unstable Measurement: A Preregistered Reliability Failure of Black-Box LLM Observers on Shared Endpoints

- **출처**: arxiv
- **점수**: 7.5
- **URL**: http://arxiv.org/abs/2609.04198v1

**요약**

LLM을 judge로 사용하는 평가 시스템의 신뢰성을 검증한 논문으로, 동일한 요청을 동일한 모델에 보내도 결과가 재현되지 않는다는 문제를 preregistered 실험으로 입증했다. 52,988건의 요청을 감사한 결과, 동일 window 내 반복 ranking의 Spearman 상관계수는 요구 기준 0.90에 한참 못 미치는 0.400에 불과했고, byte-identical 재현 실험에서도 0.99 기준 대비 0.78에 그쳤다. 이 실패의 원인으로는 label-to-meaning mapping 편향, candidate 간 점수 차이가 noise floor보다 7 order of magnitude 낮은 문제, byte-identical 입력에서도 다른 ranking이 반환되는 비결정성 세 가지가 지목된다. 결론적으로 black-box LLM을 measurement instrument로 사용하는 현재의 관행은 측정 도구 자체의 신뢰성을 검증하지 않은 채 운용되고 있음을 경고한다.

**방법론**

핵심 아이디어는 LLM judge를 과학적 measurement instrument로 간주하고, 사전에 모든 threshold를 고정한 preregistered 실험 설계로 test-retest reliability를 감사하는 것이다. 두 차례의 캠페인에서 동일 window 내 반복 요청과 byte-identical next-day replay를 각각 수행하여 Spearman rank correlation을 측정했으며, 실패 원인을 label-to-meaning mapping 편향, signal-to-noise ratio 부족, endpoint non-determinism 세 가지 메커니즘으로 분해·분석했다. Metric substitution과 sampling 전략 변경 등 보정 시도도 사전 정의된 grid 내에서 실험적으로 평가했다.

**주요 기여**

1. Black-box LLM judge의 test-retest reliability가 실용적 기준(Spearman 0.90 이상)에 크게 미달함을 52,988건의 preregistered 감사로 실증적으로 증명
2. 신뢰성 실패의 세 가지 구체적 메커니즘(label-to-meaning mapping 편향, candidate gap이 noise floor보다 7 order of magnitude 낮음, byte-identical 입력의 non-deterministic 출력)을 식별 및 정량화
3. LLM-as-judge 패러다임을 measurement instrument 관점에서 재프레이밍하여, instrument validation 없이 judge를 사용하는 현재 관행의 방법론적 위험성을 공론화

**실험 결과**

동일 window 내 반복 ranking: Spearman 0.400 (요구 기준 0.90 미달) / byte-identical next-day replay: Spearman 0.78 (요구 기준 0.99 미달) / 총 감사 요청 수: 52,988건 / metric substitution 및 sampling 전략 변경은 테스트된 grid 내에서 reliability 기준 달성에 실패

**맥락**

LLM-as-judge 패러다임은 training data 필터링, generation 품질 평가, leaderboard 운영 등 ML 파이프라인 전반에 걸쳐 광범위하게 사용되고 있다. 그러나 이 접근법은 '동일한 모델 이름에 동일한 요청을 보내면 내일도 동일한 결과를 반환한다'는 암묵적 가정에 의존하며, 이 가정이 실제로 성립하는지는 거의 검증되지 않았다. 본 연구는 이 가정을 체계적으로 감사함으로써, 현재 LLM 평가 인프라의 근본적인 measurement reliability 문제를 공론화하려 한다.

**실무 시사점**

LLM judge를 production 평가 파이프라인에 사용하는 ML 엔지니어라면, black-box API endpoint의 non-determinism이 benchmark 결과와 데이터 품질 필터링에 심각한 noise를 유발할 수 있음을 인지해야 한다. 평가 시스템 설계 시 반드시 instrument validation(측정 도구 자체의 test-retest reliability 검증)을 선행해야 하며, candidate 간 점수 차이가 모델 자체의 noise floor보다 충분히 큰지 확인하는 절차가 필요하다. 특히 leaderboard나 RLHF data collection처럼 판단 결과가 downstream에 큰 영향을 미치는 용도에서는 open-weight 모델이나 deterministic endpoint 사용을 검토해야 한다.

**한계**

본 연구는 특정 시점의 특정 black-box API endpoint를 대상으로 한 감사이므로, 결과가 모든 LLM provider나 모델 버전에 일반화되지 않을 수 있다. 또한 metric substitution이나 sampling 전략을 일부 grid에서만 테스트했기 때문에, 다른 파라미터 설정에서 reliability가 개선될 가능성을 완전히 배제하지 못한다.

**관련 링크**

- http://arxiv.org/abs/2609.04198v1

### 2. One Editor, Many Edits: A Unified Training-Free Framework for Diverse Video Editing

- **출처**: arxiv
- **점수**: 7.0
- **URL**: http://arxiv.org/abs/2609.04190v1

**요약**

EditVid는 다양한 video editing 작업을 하나의 통합된 framework로 처리하는 training-free 방법론을 제안합니다. instruction-guided editing(스타일 변환, 속성 수정 등)과 reference-guided editing(객체 삽입, subject 교체 등)을 단일 framework에서 지원하며, sparse causal memory, correspondence-based post-attention token injection, soft latent blending 세 가지 핵심 기법을 결합합니다. FiVE benchmark에서 기존 최강 training-free baseline 대비 78.16 vs 58.95 FiVE-Acc를 달성하며 압도적인 성능 향상을 보였고, 7개 경쟁 방법론 대비 user study에서 51.8% 선호도를 기록했습니다.

**방법론**

핵심 아이디어는 diffusion model의 attention mechanism을 조작하여 별도 학습 없이 다양한 editing을 통합 처리하는 것입니다. sparse causal memory는 프레임 간 local coherence를 유지하고, correspondence-based post-attention token injection은 reference subject의 identity를 장거리에 걸쳐 보존하며, soft latent blending은 편집 영역을 원본 배경과 자연스럽게 합성하여 edit locality를 보장합니다. 이 세 모듈의 조합으로 instruction-guided와 reference-guided 두 editing paradigm을 하나의 inference pipeline에서 처리합니다.

**주요 기여**

1. Training-free 방식으로 instruction-guided editing과 reference-guided editing을 단일 framework(EditVid)에서 통합 지원하는 최초의 범용 video editing framework 제안
2. Sparse causal memory, correspondence-based post-attention token injection, soft latent blending을 결합한 새로운 temporal coherence 및 edit locality 보장 메커니즘 도입
3. FiVE benchmark에서 기존 최강 training-free baseline 대비 약 19.2 포인트(78.16 vs 58.95 FiVE-Acc) 향상 및 7개 경쟁 방법론 대비 user study 51.8% 선호도 달성

**실험 결과**

FiVE benchmark: EditVid 78.16 FiVE-Acc vs 최강 training-free baseline 58.95 FiVE-Acc (약 19.2 포인트 향상). IVEBench에서도 competitive한 결과 달성. User study: 7개 경쟁 방법론 대비 51.8% overall preference 기록.

**맥락**

Video editing은 style transfer, object insertion, subject replacement 등 매우 다양한 paradigm을 포함하지만, 기존 방법들은 특정 editing 유형에만 특화되어 있어 범용적인 framework가 부재했습니다. 특히 training-based 방법들은 대규모 데이터와 연산 비용이 필요하고, 기존 training-free 방법들은 장거리 temporal coherence 유지와 edit locality 보장에 어려움을 겪었습니다. 하나의 framework로 instruction-guided와 reference-guided editing을 모두 고품질로 처리하는 통합 솔루션에 대한 수요가 높아지고 있습니다.

**실무 시사점**

EditVid는 별도의 fine-tuning 없이 바로 사용할 수 있는 training-free framework이므로, ML 엔지니어가 다양한 video editing 파이프라인에 즉시 통합할 수 있습니다. sparse causal memory와 soft latent blending 기법은 기존 diffusion-based video 모델에 플러그인 형태로 적용 가능하여, 실무에서 inference-time 비용을 크게 늘리지 않고도 temporal consistency와 edit locality를 동시에 개선할 수 있습니다. 단일 framework로 여러 editing 유형을 커버하므로, 프로덕션 환경에서 여러 모델을 유지·관리하는 복잡성을 줄일 수 있습니다.

**한계**

Training-free 특성상 특정 도메인에 특화된 training-based 방법 대비 세밀한 제어력이 부족할 수 있으며, 매우 복잡한 motion이나 장시간 영상에서의 성능은 아직 검증이 필요합니다. 논문이 평가한 benchmark(FiVE, IVEBench)가 실제 다양한 실세계 시나리오를 완전히 대표하지 못할 수 있다는 점도 주목해야 합니다.

**관련 링크**

- http://arxiv.org/abs/2609.04190v1

### 3. Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments

- **출처**: arxiv
- **점수**: 7.0
- **URL**: http://arxiv.org/abs/2609.04148v1

**요약**

Terminal-Universe는 기존 코드 agent의 실행 trajectory를 재활용하여 실제로 실행 가능한 terminal 환경을 자동으로 재구성하는 framework이다. Agent가 실행한 파일 조작 기록을 역재생(replay)하여 원본 workspace를 복원하고, 이를 기반으로 새로운 task를 합성하며 추가적인 상호작용을 생성한다. 기존에는 agent post-training에 필요한 실행 가능한 환경이 부족했지만, 이 접근법은 이미 대규모로 축적된 trajectory에서 환경을 추출함으로써 scalable한 학습 데이터 생성을 가능하게 한다.

**방법론**

핵심 아이디어는 agent trajectory 내의 tool-execution history(파일 읽기·쓰기·삭제 등 조작 기록)를 역순으로 재생(replay)하여 agent가 수정하기 이전의 원본 파일 상태를 복원함으로써 실행 가능한 partial workspace를 재구성하는 것이다. 복원된 workspace 위에서 completion agent가 누락된 부분을 채우고, 새로운 task를 합성하며 추가적인 agent 상호작용을 생성하는 파이프라인을 구성한다. 이를 통해 단일 trajectory가 재사용 가능한 environment로 변환되어 다수의 verifiable task 생성에 활용된다.

**주요 기여**

1. Trajectory를 실행 가능한 terminal environment로 자동 변환하는 Terminal-Universe framework 제안
2. 파일 조작 기록의 역재생(replay)을 통한 원본 workspace 복원 방법론 도입
3. 복원된 환경에서 새로운 task 합성 및 continued interaction 생성을 통한 scalable agent post-training 데이터 파이프라인 구축

**맥락**

Terminal 기반 code agent가 확산되면서 agent trajectory는 대규모로 축적되었지만, agent post-training에 실제로 필요한 것은 실행 가능한 환경(environment)이다. 하나의 trajectory는 단일 고정된 demonstration에 불과하지만, 환경 하나는 여러 개의 검증 가능한 task로 재활용될 수 있고 execution feedback도 제공한다. 기존 연구들은 환경을 처음부터 생성하려 했지만, 이미 존재하는 trajectory 안에 환경 구조가 내재되어 있다는 점을 활용하지 못했다.

**실무 시사점**

ML 엔지니어는 이미 보유한 agent trajectory 데이터를 그대로 활용하여 추가 비용 없이 실행 가능한 training environment를 대규모로 생성할 수 있다. Post-training 파이프라인에서 환경 구축 비용을 크게 줄이고, 각 환경에서 다양한 verifiable task를 자동 합성하여 reinforcement learning이나 supervised fine-tuning용 데이터를 확장할 수 있다. 특히 terminal 기반 coding agent를 개발하는 팀이라면 이 framework를 데이터 증강 파이프라인에 직접 통합할 수 있다.

**한계**

논문의 내용이 초록 수준에서 잘려 있어 전체 실험 결과 및 한계에 대한 상세한 평가가 불가능하다. Trajectory에서 복원되는 workspace가 '부분적(partial)'일 수 있어, 원본 환경을 완전히 재현하지 못하는 경우 task 품질이 저하될 가능성이 있다.

**관련 링크**

- http://arxiv.org/abs/2609.04148v1

### 4. Compile by Training: Turning Natural-Language Specifications into Local Neural Functions

- **출처**: arxiv
- **점수**: 6.9
- **URL**: http://arxiv.org/abs/2609.04199v1

**요약**

자연어로 작성된 함수 명세(specification)를 소형 neural network로 변환하는 'compile by training' 방법론을 제안한다. 컴파일 시점에 대형 teacher model이 task-specific 예제를 생성하고, 이를 이용해 compact interpreter용 소형 adapter를 학습시킨다. 학습된 함수는 teacher model 없이 독립 실행되며, 일반 소프트웨어처럼 저장·버전 관리·조합이 가능하다. FuzzyBench-Hard benchmark에서 기존 fast compiler 대비 83.6% semantic accuracy를 달성했다.

**방법론**

핵심 아이디어는 자연어 명세를 '컴파일'하여 teacher model 없이 독립 실행되는 소형 neural adapter로 증류(distillation)하는 것이다. 컴파일 시점에 대형 teacher model(들)이 해당 task에 특화된 입출력 예제를 자동 생성하고, 이 예제로 compact interpreter에 부착되는 adapter를 fine-tuning한다. 결과물인 neural function은 일반 함수처럼 저장·버전 관리·파이프라인 조합이 가능하며, 런타임에는 teacher model과 완전히 분리되어 동작한다.

**주요 기여**

1. 자연어 명세를 재사용 가능한 local neural function으로 변환하는 'compile by training' 패러다임을 제안하여 LLM 반복 호출 비용과 latency 문제를 해결함.
2. FuzzyBench-Hard에서 기존 Program-as-Weights fast compiler가 exact match를 전혀 달성하지 못한 반면 83.6% semantic accuracy를 달성하여 방법론의 우수성을 실증함.
3. 공개 interactive 컴파일 서비스를 배포하고 multi-site website helper, language-controlled 3D avatar 등 실제 애플리케이션에 적용하여 실용성을 검증함.

**실험 결과**

FuzzyBench-Hard subset 기준: compile by training 83.6% semantic accuracy. 비교 대상인 Program-as-Weights fast compiler는 동일 subset에서 exact match 0건(0%). compile time은 fast compiler의 수 초 대비 약 1분 소요.

**맥락**

LLM을 매 입력마다 호출하면 반복적인 비용, latency, 외부 provider 의존성이 발생하는 문제가 있다. 반면 규칙 기반 구현은 자연어로 표현하기 쉬운 텍스트 처리 함수조차 작성하기 어렵다. 이 연구는 자연어 명세를 한 번만 '컴파일'해 재사용 가능한 local neural function으로 만들어 두 문제를 동시에 해결하려 한다.

**실무 시사점**

ML 엔지니어는 반복 호출이 많은 텍스트 처리 파이프라인에서 대형 LLM 대신 compile by training으로 생성한 경량 adapter를 배포해 inference 비용과 latency를 크게 줄일 수 있다. 컴파일된 함수는 버전 관리와 조합이 가능하므로 기존 소프트웨어 개발 워크플로우에 자연스럽게 통합할 수 있다. 공개 interactive service로 배포된 사례(multi-site website helper, language-controlled 3D avatar 등)가 제시되어 실제 프로덕션 적용 가능성을 확인할 수 있다.

**한계**

compile time이 fast compiler 대비 약 1분으로 훨씬 길어, 빠른 프로토타이핑이나 즉각적인 함수 생성이 필요한 상황에는 적합하지 않다. 또한 teacher model의 품질에 학습 예제가 의존하므로, teacher가 잘못된 예제를 생성할 경우 컴파일된 함수의 정확도가 저하될 수 있다.
