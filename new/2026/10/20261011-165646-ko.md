## 1. Thinking Inertia: LLMs Keep Thinking When Told Not To

- 저자: Dianqiao Lei, Kevin Qinghong Lin, Pan Lu, Philip Torr, James Zou
- 상태: NeurIPS 2026 Poster 채택; arXiv v1
- 최초 제출: 2026-10-08 11:49:37 UTC
- 정규 URL: https://arxiv.org/abs/2610.11765
- 프로젝트: https://thinking-inertia.github.io/
- 코드: https://github.com/thinking-inertia/code

### 무엇을 묻고 어떻게 측정했나

이 연구는 모델 내부에서 계산이 일어났는지가 아니라, 최종 답 앞에 보이는 텍스트가 남는지를 측정한다. 응답을 답변 전 텍스트 (T)와 최종 답 (A)로 나누고, 세 지표를 사용한다. ETR(Empty-Thinking Rate)은 허용된 답 형식 밖의 실질적 텍스트가 전혀 없는 비율, QRel은 질문과 (T)의 관련성, EIR(Explicit Inference Rate)은 (T)에 명시적인 추론 단계가 보이는 비율이다. QRel은 Qwen3-Embedding-4B로 계산했고, EIR의 주 평가는 블라인드된 GPT-5.5 judge를 사용한 뒤 Claude Opus 4.8과 사람 평가로 방향을 확인했다.

실험은 6개 모델, 6개 벤치마크(BoolQ·StrategyQA·MMLU·MMLU-Pro·GSM8K·MATH), 6개 개입 방식에 걸쳐 진행됐다. 이 구성은 Boolean, 객관식, 개방형이라는 답 공간의 차이를 비교한다. 전체 감사 대상은 성공한 응답 572,688개였고, 사람 검증은 600개 응답을 다섯 명이 블라인드 평가했다.

### 핵심 결과와 조건

| 비교 | 원문 결과 | 해석 범위 |
| --- | --- | --- |
| 기본 think-off(M2) EIR | Boolean 5.15%, MCQ 45.57%, Open 99.69% | 보이는 명시적 추론의 전체 출력 기준 비율 |
| strict answer-only(M5) EIR | Boolean 0.12%, MCQ 25.39%, Open 62.00% | 강한 형식 지시도 개방형에서 추론을 제거하지 못함 |
| 개방형 M2 → M5 | 평균 ETR 거의 0% → 약 40%; 정확도 약 15%p 하락 | 답변 형식 준수와 성능 간 trade-off |
| 동일 수학 문항, Qwen3-32B | MCQ 정확도 77.8%·ETR 10.5%; Boolean 78.9%·62.5%; Open 52.6%·0% | 문제 내용이 같아도 답 공간이 행동을 바꿈 |
| 사람 검증 | ETR 판정 94.2% 일치; 주 EIR judge와 평균 98.8% 이진 일치 | 자동 지표의 표본 검증이며 완전한 진실 판정은 아님 |

저자들이 말하는 “thinking inertia”는 no-think 지시 뒤에도 질문에 조건화된 명시적 추론 텍스트가 남는 현상이다. 이는 hidden state의 사고 유무나 비공개 chain-of-thought를 측정한 결과가 아니다. 정확도가 비슷하더라도 답변 전 텍스트 노출과 형식 준수는 별도 품질 축으로 시험해야 한다는 점이 실무적으로 중요하다.

### 코드·재현 상태

공식 저장소는 MIT 라이선스이며 Python 3.10 이상, 여섯 개 개입 모드, 정규화된 공개 벤치마크 입력과 평가 코드를 제공한다. 모델 서버는 외부의 OpenAI-compatible endpoint를 사용자가 직접 연결해야 하며, 모델 가중치·토크나이저·자격증명은 저장소에 포함되지 않는다. 따라서 코드 공개는 확인했지만 원 논문의 572,688개 응답을 이번 편집에서 독립 재현하지는 않았다. 공개 벤치마크별 라이선스와 모델 endpoint 비용도 사용자가 따로 확인해야 한다.

### 한계

평가는 영어의 QA·수학 과제와 결정적 decoding 중심이다. 다국어, 코드 생성, 도구 사용, 다중 턴, 확률적 sampling으로 일반화되는지는 열려 있다. QRel은 관련성 지표이지 추론 탐지기가 아니며 EIR은 LLM judge에 의존한다. 저자들은 대체 judge와 사람 평가를 제시했지만, 특정 provider endpoint와 모델 버전 변화가 장기 재현성에 영향을 줄 수 있다.

### 엔지니어의 다음 실험 — 편집 제안

- **대상:** 짧은 구조화 출력이 필요한 agent/API.
- **방법:** 실제 업무 문항을 Boolean·선택형·개방형으로 나누고, think-off와 strict schema를 동일 temperature·token budget에서 비교한다.
- **완료 기준:** 정확도, schema 통과율, 답 앞 추가 텍스트 비율, 출력 토큰과 지연을 과제군별 한 표에 기록한다.
- **주의:** “추론을 숨겼다”가 아니라 “보이는 형식이 맞았다”로만 결론을 제한한다.
