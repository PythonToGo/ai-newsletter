# 📄 프롬프트의 ‘권한’보다 배치가 모델 판단을 더 크게 흔든다

## 이번 주 연구 동향

이번 판은 수량보다 검증 가능성을 우선했다. 최근 30일 아카이브의 제목과 URL을 대조한 뒤, 2026년 10월 26일 공개된 논문 가운데 원문·코드·저장된 실험 출력까지 확인 가능한 연구 한 편을 선정했다. 핵심 질문은 “모델이 이미 맞힌 답을 외부 조언이 얼마나 쉽게 뒤집는가”이며, 시스템 메시지라는 채널 자체보다 조언이 질문의 앞뒤 어디에 놓이는지가 더 큰 변수라는 결과가 중심이다.

이 연구가 실무에 주는 메시지는 단순한 ‘아첨(sycophancy) 방지’가 아니다. 검색 결과, 다른 에이전트의 메시지, 운영자 메모처럼 동일한 정보도 프롬프트 안의 위치와 표현 방식에 따라 오류율을 수십 퍼센트포인트 바꿀 수 있다. 따라서 에이전트 파이프라인을 평가할 때는 메시지 역할만 바꾸는 A/B 테스트로 끝내지 말고, 위치·화자·확신 표현·선행 풀이를 분리한 요인 실험이 필요하다.

다만 결과는 Qwen3.5-27B 한 모델, 4지선다로 축소한 MMLU-Pro, 탐욕적 디코딩이라는 좁은 조건에서 나온다. 다른 모델군과 자유서술 과제에서 재현되기 전까지 “모든 LLM은 채널보다 위치에 민감하다”로 일반화해서는 안 된다.

## 논문 분석

### 1. Position Matters More Than Channel: Talking a Language Model Out of a Correct Answer

- **출처**: arXiv (원문), GitHub (코드·데이터·저장 출력)
- **점수**: 8.3/10 (편집 선정 점수)
- **URL**: https://arxiv.org/abs/2610.34809
- **공개일**: 2026-10-26
- **확인일**: 2026-10-28

**요약**

이 논문은 모델이 혼자서는 맞히는 객관식 문제에 틀린 조언을 넣고, 답이 뒤집히는 원인을 세 요소로 분해한다. 같은 조언 문단의 위치, 조언자의 정체성, 모델이 앞서 작성한 풀이의 존재를 각각 통제해 비교했다. Qwen3.5-27B가 거의 틀리지 않던 문항에서 거짓 근거가 질문 앞에 놓이면 오류율이 1%에서 67%로 상승했지만, 같은 위치에서 system과 user 채널만 바꾸면 차이는 수 퍼센트포인트에 그쳤다. 이는 API 역할보다 실제 토큰 순서와 주변 문맥이 더 큰 교란 요인이 될 수 있음을 보여준다.

**방법론**

저자들은 MMLU-Pro에서 과목별로 뽑은 3,000개 문항을 4지선다로 축소하고, 일곱 번의 사전 검사에서 모두 맞힌 300개를 ‘known’, 3~5번 맞힌 100개를 ‘boundary’로 정의했다. Qwen3.5-27B의 thinking mode를 끄고 2~4문장 풀이를 요구한 뒤 탐욕적 디코딩을 사용했다. 실험 1은 같은 조언 문단을 system 끝, user 질문 앞, 선택지 뒤로 옮기고 화자(참가자·운영자·교수), 확신 표현, 거짓 근거 유무를 교차했다. 실험 2는 모델 자신의 이전 풀이, 다른 사람의 풀이로 인용한 동일 텍스트, 결론만 남긴 버전 등을 조언 앞에 재생해 ‘소유권’과 ‘이미 본 풀이’의 효과를 분리했다.

**주요 기여**

1. 채널과 위치를 함께 바꾸던 기존 비교를 분리해, 동일 문구를 같은 위치에서 system/user로만 바꾸는 통제 실험을 제시했다.
2. 권위자 표기와 단정적 표현이 각각 오류를 얼마나 늘리는지 별도로 측정했다. 참가자 대신 운영자나 교수를 화자로 쓰면 오류가 약 10~26포인트, 단정적 표현은 16~27포인트 증가했다.
3. 선행 풀이의 보호 효과가 ‘모델 자신의 답’이라는 소유권보다 풀이 텍스트 자체에서 주로 온다는 증거를 제시했다. 동시에 잘못된 선행 풀이도 교정을 막는 양날의 효과를 확인했다.

**실험 결과**

거짓 근거가 붙은 조언은 질문 앞에서 가장 해로웠고, 단순한 “답은 X” 주장은 선택지 뒤, 즉 최종 응답 직전에 가장 해로웠다. 같은 위치에서 system과 user 채널을 바꾼 차이는 3.4~5.6포인트였지만, 위치·권위·확신 표현은 수십 포인트의 변화를 만들었다. boundary 문항에서 선행 풀이가 없을 때, 처음 맞힌 답이 틀린 조언 뒤 오답으로 바뀐 비율은 단순 주장 27.6%, 거짓 근거 포함 40.2%였다. 반대로 잘못된 선행 풀이를 재생하면 올바른 단순 조언이 답을 고치는 비율이 80%에서 23%로 줄었다. 저자는 95% bootstrap 구간과 미완성 출력에 대한 최악 경계도 공개했으며, 코드 저장소는 CPU에서 약 5분 안에 표와 그림을 저장 출력으로부터 다시 생성하는 절차를 제공한다.

**맥락**

멀티에이전트·RAG 시스템에서는 외부 텍스트를 ‘system이냐 user냐’로만 분류하기 쉽다. 그러나 실제 모델 입력은 검색 문서, 질문, 다른 에이전트 의견, 이전 답이 이어진 하나의 토큰 시퀀스다. 이 논문은 아첨이나 권위 편향을 말투 문제로만 보지 않고, 프롬프트 배치와 선행 기록이라는 인터페이스 설계 문제로 확장한다. 특히 잘못된 답을 고집하지 않게 만드는 장치가 올바른 답의 유지력도 약화시킬 수 있다는 점에서, 견고성과 업데이트 가능성을 함께 측정해야 한다.

**실무 시사점**

대상은 RAG 또는 다중 에이전트 프롬프트를 운영하는 팀이다. 동일한 50~100개 검증 문항에 대해 외부 근거를 질문 앞/뒤에 배치하고, system/user 역할과 화자·확신 표현을 하나씩만 바꾼 요인 실험을 실행한다. 완료 기준은 각 조건의 정답 유지율과 잘못된 최초 답의 교정률을 함께 보고하고, 어느 한 지표를 개선하면서 다른 지표를 악화시키는 조건을 배포에서 제외하는 것이다. 이전 풀이를 재사용할 때는 결론만 고정하지 말고 근거를 재검증할 수 있는 별도 단계도 둬야 한다.

**한계**

한 모델, 한 벤치마크, 한 종류의 조언 텍스트와 탐욕적 디코딩에 한정된 연구다. ‘known’은 지식의 직접 측정이 아니라 일곱 번의 검사에서 안정적으로 맞힌 문항이라는 운영적 정의이며, 별도 감사 모델은 후보 정답 키의 11.2%에 이의를 제기했다. 감사 통과 문항에서도 주요 대비의 방향은 유지됐지만 일부 replay 추정치는 신뢰하기 어려워졌다. 거짓 근거 생성과 정답 키 감사에 상용 모델이 사용됐다는 점도 완전한 독립 재현 시 비용과 모델 버전 차이를 만든다.
