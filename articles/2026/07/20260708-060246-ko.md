## 트렌드 분석

오늘의 뉴스를 관통하는 핵심 테마는 두 가지다. 첫째, AI 도입의 '숨겨진 비용'이 수면 위로 드러나고 있다는 것. 둘째, inference의 무게중심이 클라우드에서 엣지·클라이언트로 분산되기 시작했다는 것이다. 표면적으로는 서로 다른 세 뉴스처럼 보이지만, 이들은 하나의 큰 구조적 전환을 서로 다른 각도에서 가리키고 있다.

$10,000짜리 AI 코드 삭제 서비스와 GLM 5.2의 margin collapse 분석은 같은 방향을 향한다. 둘 다 'AI가 만들어낸 것의 실제 원가'를 재평가하라는 신호다. AI-generated 코드는 개발 속도를 높이지만 중복과 기술 부채라는 숨겨진 비용을 누적시킨다. 마찬가지로, 현재 AI API 가격에는 실제 compute 원가를 훨씬 웃도는 gross margin이 내포되어 있다. GLM 같은 오픈소스 모델의 등장이 이 거품을 압박하기 시작했고, 이는 곧 API provider들의 가격 경쟁으로 이어질 가능성이 높다. 즉, '싸 보이는 AI'가 실은 두 겹의 비용—코드 품질 저하와 과도한 API 마진—을 숨기고 있었던 셈이다.

Ternlight의 7MB WASM embedding model은 조금 다른 맥락에서 등장하지만, inference 비용 압박과 연결된다. API 비용이 실제 원가 대비 과도하게 책정되어 있다는 인식이 퍼질수록, 개발자들은 self-hosted 또는 클라이언트 사이드 inference로 눈을 돌리게 된다. Ternlight는 그 방향의 극단적 사례—서버 자체를 없애버리는 아키텍처—를 보여준다. RAG pipeline이나 semantic search를 브라우저 안에서 완결시킨다는 것은, inference의 탈중앙화가 이미 실용 단계에 진입했음을 의미한다.

실무자에게 주는 시사점은 명확하다. 지금 당장 두 가지 감사를 시작해야 한다. 하나는 코드베이스 감사—AI-assisted 개발을 도입했다면 jscpd나 SonarQube를 CI pipeline에 통합해 중복을 조기에 탐지하고, agent guardrail 파일을 프로젝트 초기부터 세팅해야 한다. 다른 하나는 비용 감사—현재 의존하는 API의 실제 compute 원가를 추정하고, GLM 같은 오픈소스 대안이나 WASM 기반 클라이언트 사이드 inference로의 마이그레이션 경로를 지금부터 설계해두어야 한다. AI 전환의 다음 단계는 '도입'이 아니라 '최적화'다.

### 1. We charge $10k a week to delete AI-generated code

- **출처**: hackernews
- **점수**: 7.4
- **URL**: https://odra.dev/slopfix/

**요약**

AI가 생성한 코드베이스의 기술 부채를 1주일 안에 정리해주는 서비스가 등장했다. 3명의 시니어 엔지니어가 $10,000에 중복 코드를 제거하고 코드량을 최대 65%까지 줄여준다고 주장한다.

**맥락**

Vibe coding 트렌드가 확산되면서 Claude, Cursor 등 AI agent로 빠르게 프로토타입을 만드는 팀이 급증했다. 그러나 agent는 전체 codebase context를 잃으면 기존 함수를 재사용하지 않고 중복 생성하는 패턴을 반복하며, 이로 인한 기술 부채가 실제 비즈니스 문제로 부상하고 있다.

**실무 시사점**

AI-assisted 개발을 도입한 팀은 지금 당장 CLAUDE.md 같은 agent guardrail 파일, lint rule, CI check를 프로젝트 초기부터 세팅해야 한다. 또한 코드 중복 탐지 도구(예: jscpd, SonarQube)를 CI pipeline에 통합해 slop 누적을 조기에 차단하는 것이 현실적인 예방책이다.

**한계 및 의문**

$10,000/주라는 가격이 실제 ROI를 정당화하는지는 프로젝트 규모와 팀 상황에 따라 크게 다르며, '같은 기능 유지'를 보장하는 QA checklist의 커버리지 수준이 공개되지 않아 리스크 평가가 어렵다. 서비스 자체도 Claude Code를 사용한다고 인정하므로 AI slop을 AI로 고치는 아이러니한 구조적 한계가 존재한다.

**관련 링크**

- https://odra.dev/slopfix/

### 2. Ternlight – 7 MB embedding model that runs in browser (WASM)

- **출처**: hackernews
- **점수**: 7.3
- **URL**: https://ternlight-demo.vercel.app/

**요약**

Ternlight는 7MB 크기의 embedding model로, WASM을 통해 브라우저에서 직접 실행되며 React 문서를 대상으로 semantic search를 시연한다. 서버 없이 클라이언트 사이드에서 완전히 동작한다.

**맥락**

온디바이스 AI에 대한 관심이 높아지는 가운데, WebAssembly(WASM) 기반 ML inference가 점점 현실화되고 있다. llama.cpp의 WASM 포팅, Transformers.js 등 브라우저 내 ML 실행 생태계가 성숙해지면서, 경량 embedding model의 브라우저 배포가 실용적인 선택지로 부상하고 있다.

**실무 시사점**

프라이버시가 중요한 서비스나 서버 비용을 줄이고 싶은 개발자라면, 이처럼 WASM 기반 embedding model을 활용해 semantic search나 RAG pipeline을 완전히 클라이언트 사이드로 구현하는 아키텍처를 검토할 수 있다. Transformers.js나 ONNX Runtime Web과 함께 비교 벤치마킹을 해보고, 자신의 도메인 데이터에 대한 retrieval 품질을 실측하는 것이 우선이다.

**한계 및 의문**

7MB 모델이 실제로 어떤 architecture와 학습 데이터를 사용했는지, multilingual 지원 여부나 embedding 품질에 대한 정량적 벤치마크가 공개되지 않아 프로덕션 적용 전 검증이 필요하다. 또한 모바일 저사양 기기에서의 성능과 메모리 사용량에 대한 데이터도 부재하다.

**관련 링크**

- https://ternlight-demo.vercel.app/

### 3. GLM 5.2 and the coming AI margin collapse

- **출처**: hackernews
- **점수**: 7.2
- **URL**: https://martinalderson.com/posts/the-upcoming-ai-margin-collapse-part-1-glm-5-2/

**요약**

GLM 5.2 출시를 계기로 AI inference 비용의 급격한 하락과 그에 따른 AI 기업들의 margin collapse 가능성을 분석한 글. Training 비용은 고정비지만 inference는 수요에 따라 변동하는 진짜 marginal cost이며, 현재 API 가격에는 막대한 gross margin이 숨어있다고 주장한다.

**맥락**

DeepSeek R1 공개 이후 AI 모델 training 비용에 대한 논의가 집중됐지만, 실제 AI 비즈니스의 핵심 수익 구조는 inference API pricing에 있다. Anthropic과 OpenAI가 $25/MTok 수준으로 책정한 inference 가격은 실제 compute 원가 대비 약 90% gross margin으로 추정되며, 오픈소스 및 중국 모델들의 급성장으로 이 구조가 흔들리기 시작했다.

**실무 시사점**

ML 엔지니어와 개발자들은 현재 API 비용이 실제 compute 원가와 크게 괴리되어 있음을 인지하고, GLM 같은 오픈소스 대안 모델로의 전환 가능성을 지금부터 평가해야 한다. Self-hosted inference 또는 저비용 provider로의 마이그레이션 전략을 미리 수립해두면 향후 margin collapse 시 경쟁 우위를 확보할 수 있다.

**한계 및 의문**

이 글은 Part 1으로 napkin math 수준의 추정에 기반하며, OpenAI의 leaked financials 등 불확실한 데이터를 사용한다. Margin collapse의 실제 타이밍과 규모는 모델 품질 격차, 규제 환경, 기업 고객의 switching cost 등 다양한 변수에 따라 크게 달라질 수 있다.
