# Agent 시대의 역설: 성능은 치솟고 신뢰는 흔들린다

## 트렌드 분석

오늘의 뉴스를 관통하는 핵심 테마는 두 가지다. 첫째, AI agent의 능력이 인간 수준을 넘어서는 속도가 빨라지고 있다는 것. 둘째, 그 능력이 실제로 '신뢰할 수 있는가'에 대한 의문이 동시에 커지고 있다는 것이다. 이 두 흐름은 서로 긴장 관계에 놓여 있으며, 오늘의 세 아이템은 각각 이 긴장의 다른 면을 보여준다.

GPT-6 Astra의 ARC-AGI-3 benchmark 결과는 표면적으로 가장 자극적인 뉴스다. Standard harness에서 62.7%, Provider Adapter harness에서 99.9%라는 수치는 단순한 성능 향상이 아니다. 특히 Provider Adapter가 reasoning state를 요청 간에 보존하고 compaction을 활용한다는 점은, 장기 agentic task에서 '기억'과 '상태 관리'가 성능의 핵심 변수로 부상했음을 의미한다. 이는 Armature Tech의 17,000회 coding agent 실험과 연결된다. Claude, Codex, Cursor가 75개 repository에 걸쳐 어떤 tool을 선택하는지 측정한 이 실험은, agent의 능력이 높아질수록 그 내부 의사결정 과정이 더 불투명해진다는 역설을 드러낸다. Prompt 스타일(vibe-coder vs senior engineer)에 따라 tool 선택이 달라진다는 발견은, agent가 아직 '맥락에 독립적인 최적 판단'을 내리지 못한다는 뜻이다.

그리고 가장 불편한 뉴스가 이 그림을 완성한다. 세 개의 스팸 사이트가 215,128개의 페이지를 대량 생성했고, Perplexity는 이를 실제 출처로 인용하고 있다. Web-grounded model이 citation의 신뢰성을 자체적으로 검증하지 못한다는 이 사실은, GPT-6 Astra의 인상적인 benchmark 수치와 극명하게 대비된다. benchmark에서 인간을 초월하는 모델이, 스팸 도메인과 신뢰할 수 있는 출처를 구분하지 못하는 것이다. 이는 능력(capability)과 신뢰성(reliability)이 아직 함께 성장하지 않고 있음을 보여준다.

실무자에게 주는 핵심 시사점은 하나다. Agent의 output을 평가하는 기준을 '결과물의 품질'에서 '추론 과정의 검증 가능성'으로 이동시켜야 할 시점이다. Coding agent가 추천하는 dependency, grounded search가 인용하는 출처, agentic pipeline이 유지하는 reasoning state — 이 모든 것에 post-processing 검증 레이어를 설계하는 것이 이제 선택이 아닌 필수 엔지니어링 과제가 되었다.

## 아이템 분석

### 1. Three sites made 215,128 “best software” pages for AI. Perplexity cites them

- **출처**: hackernews
- **점수**: 7.6
- **URL**: https://trellner.com/reports/manufactured-sources-behind-ai-recommendations/

**요약**

세 개의 스팸 사이트가 AI 추천용 215,128개의 '최고 소프트웨어' 페이지를 대량 생성했고, Perplexity가 이를 실제 출처로 인용하고 있다는 사실이 실험을 통해 밝혀졌다.

**맥락**

Perplexity 같은 web-grounded AI 모델은 실시간 검색 결과를 retrieval 단계에서 참조해 답변을 생성한다. 이 연구는 2023년 12월 이후 생성된 저품질 도메인들이 의도적으로 'Facts & Grounding Page'라는 HTML title을 달아 AI의 grounding 메커니즘을 역이용하고 있음을 보여준다. RAG 기반 AI 검색이 주류로 자리잡으면서 SEO 스팸이 AI grounding 조작으로 진화하는 새로운 공격 벡터가 등장한 것이다.

**실무 시사점**

ML 엔지니어와 개발자는 web-grounded model의 citation을 맹신하지 말고, 인용된 도메인의 Tranco 순위나 도메인 생성일을 검증하는 post-processing 레이어를 추가해야 한다. Perplexity API나 유사한 grounded search API를 프로덕션에 사용 중이라면, 저신뢰 도메인 필터링 로직을 retrieval pipeline에 직접 구현하는 것을 즉시 검토해야 한다.

**한계 및 의문**

이 실험은 380개 카테고리와 760번의 API 호출로 제한되어 있어 전체 AI 검색 생태계를 대표한다고 보기 어렵고, Perplexity 외 다른 모델(예: ChatGPT Search, Gemini)에서도 동일한 패턴이 나타나는지는 아직 검증되지 않았다.

**관련 링크**

- https://trellner.com/reports/manufactured-sources-behind-ai-recommendations/

### 2. Which tools do Claude, Codex and Cursor choose? We measured 17k runs to find out

- **출처**: hackernews
- **점수**: 7.3
- **URL**: https://armature.tech/blog/which-tools-coding-agents-install

**요약**

Armature Tech이 Claude, Codex, Cursor 등 주요 coding agent를 대상으로 17,000회 실험을 실행해 각 agent가 실제 작업에서 어떤 tool을 선택하는지 측정했다. 75개 repository, 10개 언어, 4가지 개발자 프로필로 체계적인 benchmark를 구성했다.

**맥락**

Claude Code, OpenAI Codex, Cursor 등 agentic coding tool이 급속히 보급되면서, 이 agent들이 실제로 어떤 third-party library나 tool을 선택하는지에 대한 체계적인 데이터가 부족했다. AI가 tool 선택에 미치는 영향력이 커지면서 vendor lock-in이나 security 리스크에 대한 우려도 함께 증가하고 있다.

**실무 시사점**

ML 엔지니어와 개발자는 coding agent가 자신의 prompt 스타일(vibe-coder vs senior engineer)에 따라 tool 선택이 달라질 수 있음을 인지하고, agent가 추천하는 dependency를 무비판적으로 수용하지 말고 반드시 직접 검토해야 한다. 특히 enterprise 환경에서는 compliance나 procurement 제약을 prompt에 명시적으로 포함시키는 것이 agent의 tool 선택에 실질적인 영향을 줄 수 있다.

**한계 및 의문**

실험에 사용된 75개 repository는 실제 enterprise 코드베이스가 아닌 합성 데이터이며, fake git history와 fake API key를 사용했기 때문에 실제 프로덕션 환경과의 괴리가 존재한다. 또한 tech startup 편향을 보정했다고 하나, 공개 GitHub 데이터 기반의 unbiasing 방법론의 정확성은 검증이 필요하다.

**관련 링크**

- https://armature.tech/blog/which-tools-coding-agents-install

### 3. OpenAI's GPT-6 Astra on ARC-AGI-3

- **출처**: hackernews
- **점수**: 7.3
- **URL**: https://arcprize.org/blog/astra

**요약**

OpenAI의 GPT-6 Astra가 ARC-AGI-3 벤치마크에서 Standard harness로 62.7%, Provider Adapter harness로 99.9%를 달성하며 인간 baseline을 초과했다. 특히 96%의 레벨에서 인간 중앙값보다 적은 action으로 문제를 해결했다.

**맥락**

ARC-AGI 시리즈는 단순 암기나 pattern matching이 아닌 진정한 추론 능력을 측정하기 위해 설계된 벤치마크로, AGI 진척도를 가늠하는 핵심 지표로 자리잡았다. ARC-AGI-3는 이전 버전과 달리 agentic intelligence에 초점을 맞춰, 모델이 명시적 지시 없이 환경을 탐색하고 내부 world model을 구축해야 한다는 점에서 난이도가 크게 높아졌다.

**실무 시사점**

Provider Adapter harness가 opaque reasoning state를 요청 간에 보존하고 compaction을 활용한다는 점은, 장기 agentic task에서 reasoning state 관리가 성능의 핵심 변수임을 시사한다. ML 엔지니어는 자체 agentic 시스템 설계 시 단순 context window 확장보다 symbolic world model 구축과 domain-specific language 생성 능력을 평가 기준에 포함시킬 필요가 있다.

**한계 및 의문**

99.9% 달성에 $19K의 비용이 소요된다는 점은 실용적 배포에 큰 장벽이며, Standard harness 기준 62.7%와의 격차는 harness 설계에 따라 결과가 크게 달라짐을 보여준다. 또한 벤치마크 환경이 인간 테스트로 difficulty-calibrate되었다고 하나, 실제 open-ended 환경으로의 generalization 여부는 여전히 미검증 상태다.

**관련 링크**

- https://arcprize.org/blog/astra
