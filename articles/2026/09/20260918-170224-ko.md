# AI agent, 코드도 훔치고 오류도 낸다: 신뢰의 위기

> **리포트 ID**: `20260918-170224`  
> **생성**: 2026-09-18 17:02 UTC  
> **아이템**: 3개  

## 트렌드 분석

오늘 뉴스를 관통하는 핵심 테마는 하나다: **AI agent를 얼마나 믿을 수 있는가?** ZCode의 무단 데이터 업로드 사건, Bend 언어의 등장, 그리고 Infinite-Parameter LLM 연구는 각각 다른 레이어에서 같은 질문을 던지고 있다. AI agent가 개발 워크플로우 깊숙이 침투한 지금, '신뢰'의 문제는 학술적 논의가 아니라 실무적 긴급 사안이 됐다.

ZCode 사건은 가장 직접적인 경고다. GLM 모델 자체가 오픈소스라는 사실이 런타임 클라이언트의 신뢰를 보장하지 않는다는 점이 reverse-engineering으로 드러났다. 313MB, 42,411개 파일이 암호화돼 Alibaba Cloud OSS로 전송됐다는 사실은 단순한 버그가 아니라 구조적 설계 문제일 가능성을 시사한다. 이 사건은 Bend의 등장과 직접 연결된다. Bend는 AI agent가 생성한 코드를 formal proof로 검증해 오류 자체를 차단하겠다는 철학을 가진 언어다. ZCode가 '신뢰할 수 없는 agent의 행동'을 보여줬다면, Bend는 '검증 가능한 agent 출력물'을 만들기 위한 인프라적 응답이다. 두 아이템은 서로 상충하는 것처럼 보이지만, 실은 같은 문제의 공급과 수요 측면을 보여준다.

Infinite-Parameter LLM 연구는 결이 다르지만 무관하지 않다. 입력 데이터에 따라 weight를 실시간으로 생성하는 이 접근법은 기존 fine-tuning 패러다임을 근본적으로 흔든다. 모델이 고정된 parameter를 갖지 않는다면, 그 행동을 사전에 감사하거나 예측하기가 훨씬 어려워진다. ZCode 사건이 보여준 '예측 불가능한 agent 행동'의 문제가 모델 아키텍처 레벨에서도 심화될 수 있다는 뜻이다. 혁신적인 연구일수록 interpretability와 감사 가능성에 대한 질문이 함께 따라와야 한다.

실무자에게 주는 핵심 시사점은 명확하다: AI agent 도입 시 '모델의 성능'과 '클라이언트의 투명성'을 반드시 분리해서 평가해야 한다. 모델 가중치 라이선스 확인만으로는 부족하다. 네트워크 트래픽 감사, CI 파이프라인에 Bend 스타일의 proof 검증 단계 추가, 그리고 Infinite-Parameter 계열 모델 도입 시 행동 감사 체계 설계가 지금 당장 검토해야 할 실천 항목이다.

## 아이템 분석

### 1. ZCode, the GLM coding agent, silently uploads your Git history

- **출처**: hackernews
- **점수**: 7.4
- **URL**: https://tokenstead.ai/guides/zcode-silent-git-history-upload

**요약**

AI 코딩 에이전트 ZCode가 사용자 동의 없이 전체 Git history, LFS 캐시, 설정 파일 등을 암호화해 Alibaba Cloud OSS에 업로드하는 것이 reverse-engineering으로 발각됐다. 313MB 아카이브, 42,411개 파일이 무단 전송됐으며, GLM 모델이 오픈소스라고 해서 ZCode 런타임도 오픈소스라는 오해가 피해를 키웠다.

**맥락**

GLM 시리즈(GLM-5.3-Flash 등)는 local AI 커뮤니티에서 널리 쓰이는 open-weight 모델이지만, Z.ai가 제공하는 ZCode 데스크탑 앱은 별개의 closed-source 소프트웨어다. 오픈소스 모델 가중치와 closed-source 런타임 하네스를 혼동하는 사용자가 많은 상황에서, 이번 사건은 'open-weight ≠ open-source 에코시스템'이라는 경계를 명확히 보여준다.

**실무 시사점**

ZCode를 사용 중이라면 즉시 앱을 비활성화하고 네트워크 트래픽을 감사해야 한다. 앞으로 AI 코딩 에이전트를 선택할 때는 모델 가중치의 라이선스뿐 아니라 런타임 클라이언트의 소스 공개 여부, 네트워크 통신 내역을 반드시 별도로 검증해야 하며, 상업용 코드베이스에서는 open-source agent(예: Continue, Aider 등)를 우선 검토하는 것이 안전하다.

**한계 및 의문**

현재 Z.ai의 공식 해명이나 업로드 목적(모델 학습용 데이터 수집인지, 기능상 필요인지)이 공개되지 않았으며, 암호화된 아카이브의 실제 서버 측 처리 방식은 아직 확인되지 않아 피해 범위를 정확히 산정하기 어렵다.

**관련 링크**

- https://tokenstead.ai/guides/zcode-silent-git-history-upload

### 2. Infinite-Parameter LLMs: Generating and Adapting Weights from Live Data

- **출처**: hackernews
- **점수**: 7.4
- **URL**: https://arxiv.org/abs/2609.18842

**요약**

Live data로부터 LLM의 weight를 동적으로 생성·적응시키는 'Infinite-Parameter' 접근법을 제안. 고정된 parameter 대신 입력 데이터에 따라 weight를 실시간 생성해 모델 용량을 사실상 무한히 확장한다.

**맥락**

기존 LLM은 학습 후 weight가 고정되어 새로운 도메인 적응에 fine-tuning이나 RAG가 필요했다. parameter-efficient adaptation 연구가 활발한 가운데, weight 자체를 동적으로 생성하는 hypernetwork 계열 접근이 주목받고 있다.

**실무 시사점**

ML 엔지니어는 이 접근법이 기존 LoRA·adapter 기반 fine-tuning 파이프라인을 대체할 가능성을 검토해야 한다. 특히 스트리밍 데이터나 지속적 학습(continual learning) 시나리오에서 weight 생성 방식의 latency·메모리 트레이드오프를 실험적으로 평가할 필요가 있다.

**한계 및 의문**

arxiv 논문으로 아직 peer review를 거치지 않았으며, 실제 대규모 모델에서의 inference 속도와 메모리 오버헤드에 대한 실증 데이터가 부족하다. 'Infinite-Parameter'라는 표현은 마케팅적 과장일 수 있어 실제 확장성 한계를 면밀히 검토해야 한다.

**관련 링크**

- https://arxiv.org/abs/2609.18842

### 3. Bend – a language that blocks AI mistakes via proof and runs on GPUs

- **출처**: hackernews
- **점수**: 7.3
- **URL**: https://bend-lang.com/

**요약**

Bend는 Python 유사 문법을 사용하면서 Lean/Rocq 스타일의 formal proof, C 수준 성능, GPU 병렬 실행을 동시에 지원하는 언어로, AI agent가 코드를 생성할 때 발생하는 오류를 proof 검증으로 차단하는 것을 목표로 한다.

**맥락**

AI coding agent(GitHub Copilot, Cursor 등)가 코드 생성을 주도하는 시대에, hallucination이나 논리 오류를 런타임 이전에 잡아내는 수단이 절실해졌다. Lean, Rocq(Coq) 같은 proof assistant는 correctness 보장에 강력하지만 컴파일 속도가 느려 AI agent의 빠른 iteration loop에 맞지 않았는데, Bend는 이 gap을 1초 이내 type/proof checking으로 메우려 한다.

**실무 시사점**

AI agent 기반 개발 워크플로우를 구성 중인 엔지니어라면 AGENTS.md에 `bend guide`, `bend PROOF.bend` 단계를 추가해 commit 전 자동 proof 검증을 CI에 통합하는 방식을 검토할 만하다. 또한 GPU 병렬화가 필요한 수치 연산 코드를 thread/kernel 없이 작성할 수 있다는 점은 ML inference 전처리나 시뮬레이션 워크로드에 실질적인 대안이 될 수 있다.

**한계 및 의문**

현재 공개된 벤치마크는 Apple M4 Max 단일 환경에 한정되어 있고, 실제 mid-sized 이상 codebase에서의 proof 완성도와 생태계(라이브러리, 툴링) 성숙도는 검증되지 않았다. 'post-AGI economy'를 전제로 한 마케팅 언어가 기술적 실체보다 앞서 있을 가능성을 감안해 실사용 전 신중한 평가가 필요하다.

**관련 링크**

- https://bend-lang.com/
- https://bend-lang.com/install.sh
