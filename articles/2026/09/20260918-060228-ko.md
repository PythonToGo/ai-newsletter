# Ternary 혁명과 AI DB 최적화: 소형 모델의 역습

## 트렌드 분석

오늘의 뉴스를 관통하는 핵심 테마는 두 가지다. 첫째, 모델 압축 기술의 실용화 임계점 돌파. 둘째, 소형 LLM이 전통적인 시스템 소프트웨어 영역까지 침투하는 현상이다. 이 두 흐름은 표면적으로는 별개처럼 보이지만, 실제로는 같은 방향을 가리키고 있다. '작고 빠른 모델이 실제 production 환경을 바꾸기 시작했다'는 것이다.

Bonsai 2 27B와 1.58-bit ternary LLM 연구는 사실상 하나의 이야기다. 두 아이템 모두 {-1, 0, +1} ternary weight 체계를 중심으로 전개되며, 각각 다른 각도에서 같은 명제를 증명한다. Bonsai 2는 '이미 동작하는 제품'으로서 benchmark 성능 98.2% 유지와 9배 압축이라는 수치를 제시하고, 1.58-bit 연구는 이 패러다임의 이론적 한계를 더 밀어붙이는 방법론을 탐구한다. 즉, 업계는 ternary quantization을 실험 단계에서 벗어나 점점 production-ready한 기술로 정착시키고 있다. 262K token context window와 multimodal 지원까지 갖춘 5.9GB 모델이 Apache 2.0으로 공개된다는 사실은, 엣지 환경에서의 agentic pipeline 구축 비용이 급격히 낮아지고 있음을 의미한다.

한편 Postgres query optimizer를 능가하는 4B 모델 사례는 또 다른 차원의 시사점을 던진다. SFT와 agentic RL을 결합한 post-training만으로 수십 년간 정제된 rule-based 시스템을 특정 도메인에서 압도할 수 있다는 것이다. 이는 단순한 benchmark 경쟁이 아니라, LLM이 시스템 소프트웨어의 핵심 로직을 대체하거나 보완하는 실질적인 사례다. 그리고 이 4B 모델이 의미 있는 이유 중 하나는, 앞서 언급한 ternary 압축 기술과 결합될 경우 훨씬 가벼운 형태로 배포 가능하다는 점이다. 세 아이템은 서로를 증폭시키는 구조로 연결되어 있다.

실무자에게 주는 핵심 시사점은 명확하다. 지금은 '소형 모델 + 도메인 특화 post-training + aggressive quantization'의 조합을 진지하게 실험할 시점이다. inference 비용과 하드웨어 제약이 여전히 병목인 팀이라면, GPT-4급 대형 모델에 의존하는 대신 ternary 압축 모델을 fine-tuning하여 특정 태스크에 최적화하는 접근이 현실적인 대안으로 부상하고 있다.

### 1. Training a 4B model to produce 81% faster query plans than Postgres

- **출처**: hackernews
- **점수**: 7.8
- **URL**: https://rohanbansal.com/qorl

**요약**

4B 파라미터 오픈소스 모델을 SFT와 agentic RL로 post-training하여 Postgres 기본 query optimizer보다 평균 44.7%, 최대 81% 빠른 query plan을 생성하는 데 성공했다.

**맥락**

Leis et al.이 2015년과 2025년 두 차례에 걸쳐 지적했듯, join ordering이 NP-hard 문제임에도 불구하고 전통적인 query optimizer는 10년간 큰 진전을 보이지 못했다. 최근 LLM의 reasoning 능력 향상과 RL 기반 post-training(예: DeepSeek-R1, GRPO) 기법의 대중화가 맞물리면서, 검증 가능한 단일 목표(query 실행 시간)를 가진 DB 최적화 문제가 RL 적용의 이상적인 타깃으로 부상했다.

**실무 시사점**

DB 성능 튜닝을 담당하는 엔지니어라면 전통적인 hint 기반 튜닝 대신 소형 LLM + RL 파이프라인을 실험적으로 도입할 시점을 검토할 수 있다. 특히 join이 많은 복잡한 OLAP 쿼리 환경에서는 4B급 오픈소스 모델로도 의미 있는 latency 개선이 가능하므로, 자체 워크로드 데이터로 SFT 데이터셋을 구성하고 실행 시간을 reward signal로 삼는 RL fine-tuning 파이프라인 구축을 고려해볼 만하다.

**한계 및 의문**

실험이 113개의 join-heavy 쿼리에 국한되어 있어 다양한 실제 워크로드에 대한 일반화 가능성이 검증되지 않았고, 모델 inference 비용과 query plan 생성 latency가 전통적인 optimizer 대비 얼마나 오버헤드를 추가하는지에 대한 분석이 공개된 내용에서 명확하지 않다.

**관련 링크**

- https://rohanbansal.com/qorl
- https://www.vldb.org/pvldb/vol9/p204-leis.pdf

### 2. Bonsai 2 27B: Near-Lossless Compression in a 9x Smaller Footprint

- **출처**: hackernews
- **점수**: 7.5
- **URL**: https://prismml.com/news/bonsai-2-27b

**요약**

PrismML이 Qwen3.8 27B 기반의 Ternary Bonsai 2 27B를 출시했다. {-1, 0, +1} ternary weight와 FP16 group-wise scaling으로 1.76 bits per weight를 달성하며, 원본 대비 9배 이상 작은 5.9GB 크기로 benchmark 성능의 98.2%를 유지한다.

**맥락**

온디바이스 AI 수요가 급증하면서 대형 모델의 local deployment가 핵심 과제로 부상했다. BitNet 등 1-bit/ternary quantization 연구가 활발해진 가운데, 27B급 multimodal 모델을 near-lossless로 압축해 실제 배포 가능한 수준으로 만든 사례는 드물었다.

**실무 시사점**

ML 엔지니어는 Apache 2.0 라이선스로 공개된 이 모델을 즉시 로컬 환경에 테스트할 수 있으며, 262K token context window와 multimodal 지원을 고려하면 엣지 서버나 고사양 consumer 기기 기반 agentic 파이프라인 구축에 바로 활용 가능하다. Ternary weight + FP16 group-wise scaling 조합은 자체 모델 압축 파이프라인 설계 시 참고할 수 있는 실용적인 레퍼런스 아키텍처다.

**한계 및 의문**

98.2% benchmark 성능 유지는 aggregate 수치이므로 특정 도메인(예: 수학 추론, 코드 생성 세부 태스크)에서는 성능 저하가 더 클 수 있다. 또한 ternary quantization 전용 커널 지원 없이는 실제 추론 속도 이점이 제한될 수 있으며, 하드웨어 호환성에 대한 상세 정보가 공개되지 않았다.

**관련 링크**

- https://prismml.com/news/bonsai-2-27b

### 3. Breaking the 1.58-bit Barrier for Ternary LLMs

- **출처**: hackernews
- **점수**: 7.5
- **URL**: https://arxiv.org/abs/2609.16338

**요약**

1.58-bit ternary LLM의 성능 한계를 돌파하는 새로운 방법론을 제시. 각 weight를 {-1, 0, 1}로 표현하면서도 기존 full-precision 모델에 근접한 성능을 달성.

**맥락**

BitNet b1.58 등 1-bit/ternary LLM 연구가 활발해지면서 엣지 디바이스 배포와 추론 비용 절감에 대한 관심이 높아졌다. 그러나 ternary quantization은 표현력 손실로 인해 성능 저하가 불가피하다는 인식이 지배적이었고, 이를 극복하는 것이 핵심 과제였다.

**실무 시사점**

엣지 추론이나 저비용 서빙 파이프라인을 구축하는 ML 엔지니어라면 ternary weight 모델의 실용성이 높아졌음을 주목해야 한다. fine-tuning 또는 post-training quantization 전략 수립 시 1.58-bit 접근법을 진지하게 검토할 시점이다.

**한계 및 의문**

arxiv 논문으로 아직 peer review를 거치지 않았으며, 실제 하드웨어(예: ARM, RISC-V 엣지 칩)에서의 실측 벤치마크나 대규모 모델(70B+)에 대한 검증이 부족할 수 있다.

**관련 링크**

- https://arxiv.org/abs/2609.16338
