## 트렌드 분석

에이전트 제품에서 모든 모델 호출이 긴 자연어 답변을 필요로 하지는 않는다. 입력을 어느 대기열로 보낼지, 다음 행동을 실행할지, 사람에게 넘길지처럼 많은 단계는 정해진 선택지 안에서 빠르고 일관되게 답하는 것이 더 중요하다. OpenAI가 일반 제공한 Decisions API는 이 영역을 별도 endpoint로 분리해, 텍스트·이미지·JSON 입력을 확률·선택·점수라는 제한된 출력으로 바꾼다.

이번 발표의 핵심은 새로운 범용 모델보다 ‘생성’과 ‘판단’을 다른 실행 경로로 나누는 제품 설계다. 하나의 요청에서 공통 입력을 공유하며 최대 400개 질문을 평가할 수 있고, 반복되는 공통 prefix에는 prompt caching을 적용한다. GPT-Live와도 연결할 수 있어 음성 대화 중 라우팅·표정 선택·상담 이관 같은 짧은 결정을 응답 경로에 넣을 수 있다.

다만 빠른 typed output은 정확성 보증이나 정책 엔진을 뜻하지 않는다. 확률은 calibration을 따로 검증해야 하고, choice는 미리 열거한 후보 바깥의 올바른 행동을 표현하지 못한다. 공급사가 제시한 최대 10배 속도와 고객 사례는 서로 다른 workload·baseline에서 나온 결과이므로, 각 팀은 실제 데이터에서 품질·p95 latency·비용·오판 비용을 함께 측정해야 한다.

**요약**

OpenAI는 Decisions API를 일반 제공했다. 이 API는 텍스트, 이미지, 대화 기록과 native JSON을 입력받고 세 가지 typed answer를 반환한다. predicate는 조건이 참일 확률을 0~1로, choice는 사용자가 정의한 후보 중 하나와 확률·confidence를, score는 순서형 rubric 단계의 확률 가중 평균을 돌려준다.

Public beta 이후 prompt caching, 질문별 이미지, native JSON, hosted image URL, 대화·도구 호출 기록, 조직 단위 사용량 조회, GPT-Live 연동이 추가됐다. 한 요청의 questions 배열에는 1~400개의 독립 질문을 넣을 수 있다. 앞선 답에 따라 다음 질문이 달라지는 의존적 판단은 별도 요청으로 나누라고 공식 문서는 명시한다.

가격은 GPT-6 Luna 기준 uncached input 100만 token당 0.10달러이며 output token 요금은 없다. 공통 입력 prefix가 최소 1,024 token이고 동일하게 반복될 때 cache read 혜택을 받을 수 있다. 지역 처리 할증과 long-context multiplier는 별도로 적용되며, 현재 dedicated endpoint에서 지원되는 모델은 GPT-6 Luna 하나다.

**맥락**

기존 Responses API에서도 structured output이나 function calling으로 분류기를 만들 수 있지만, 범용 생성 경로는 수백 밀리초가 중요한 실시간 라우팅이나 대량의 작은 판정에서 비용과 지연이 누적된다. Decisions API는 자유 생성 대신 답 공간을 미리 고정함으로써 문서 분류, agent action 선택, 위험 점수, 상담 이관처럼 애플리케이션이 즉시 소비할 수 있는 결과를 겨냥한다.

OpenAI는 Responses API 대비 최대 10배 빠르다고 설명한다. 고객 사례로 Box는 보험증서 30건의 route selection에서 약 5배 속도와 같은 정확도, Datadog은 agent 생성 shell command 위험 점수에서 frontier model 대비 p95 40배 속도와 유사 정확도, Sierra는 280ms 미만 p95와 이전 방식 대비 호출당 90% 낮은 비용을 보고했다. Speak는 GPT-Live 통합에서 다음 행동까지 1.4초에서 0.13초로 줄었다고 밝혔다. 모두 공급사 발표에 포함된 개별 고객 평가이며 공통 benchmark는 아니다.

**실무 시사점**

- **대상:** 분류·라우팅·우선순위·agent gate처럼 답의 형태가 미리 정해져 있고 짧은 지연이 중요한 제품팀
- **방법:** 실제 traffic을 대표하는 holdout set에서 기존 rules 또는 Responses API baseline과 Decisions를 같은 입력·threshold로 비교한다. predicate는 reliability diagram과 calibration error를, choice는 confusion matrix와 후보 밖 정답 비율을, score는 순서형 오차와 threshold별 비용을 기록한다. 고위험 행동에는 confidence threshold, 인간 검토, 명시적 deny rule을 별도 계층으로 둔다.
- **완료 기준:** 사전 정의한 품질 하한을 유지하면서 p95 latency와 요청당 비용 목표를 충족하고, drift·refusal·timeout·candidate 누락 시 안전한 fallback이 통합 테스트에서 모두 통과할 때 production 경로에 넣는다.

400개 질문 batching은 동일 입력에 대한 서로 독립적인 검사를 묶을 때 유용하다. 반대로 “손상 여부가 참이면 수리 유형 선택”처럼 순차 의존성이 있으면 두 요청으로 분리해야 한다. 공통 문서나 기준 이미지를 반복 평가하는 workload에서는 shared input을 앞에 고정하고 usage의 cached·cache-write token을 관찰해야 실제 할인 여부를 확인할 수 있다.

**한계 및 의문**

‘10배 빠름’은 OpenAI의 Responses API 대비 공급사 주장으로, 입력 길이·동시성·지역·cache 상태·품질 기준이 통일된 독립 평가가 공개되지 않았다. Box의 정확도 비교는 30개 사례에 불과하고, 다른 고객 수치도 서로 다른 기준 모델과 workload를 사용한다. 따라서 사례 수치를 자체 SLA나 비용 추정에 그대로 대입하면 안 된다.

반환 확률은 경험적 빈도와 일치한다는 보장이 없다. 0.9를 곧바로 90% 정답 가능성으로 해석하기 전에 도메인별 calibration과 threshold 평가가 필요하다. choice는 닫힌 후보 집합을 강제하므로 unknown, abstain, human_review 같은 안전 출구를 설계하지 않으면 틀린 후보 중 하나를 선택하게 만들 수 있다.

이 endpoint는 판단 결과를 제공할 뿐 권한·정책·감사 체계를 대체하지 않는다. shell 명령 실행, 환불, 계정 잠금처럼 복구 비용이 큰 행동은 모델 점수 하나로 자동 승인해서는 안 된다. 입력 데이터 지역성은 US·EU 처리를 지원하고 일부 고객은 Zero Data Retention을 신청할 수 있지만, eligibility와 지역 할증, Private Link·보존 설정은 계정 조건에 따라 별도 확인해야 한다.
