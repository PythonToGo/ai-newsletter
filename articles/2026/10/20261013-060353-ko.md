## 1. Microsoft Maia 300 — 칩 성능이 아니라 랙·전력·데이터 이동을 함께 설계한다

- 원 발표자: Microsoft
- 사건 날짜: 2026-10-12
- 공식 발표: https://blogs.microsoft.com/blog/2026/10/12/microsoft-to-expand-azure-maia-system-to-multi-gigawatt-deployments/
- 아키텍처 설명: https://azure.microsoft.com/en-us/blog/deep-dive-into-azure-maia-300-architecture/
- 확인일: 2026-10-13

Microsoft는 Azure Maia를 2027년부터 multi-gigawatt 규모로 배포하고, Maia 300을 자사 제품·서비스의 주요 AI inference 시스템으로 만들겠다고 발표했다. Maia 200은 이미 Copilot을 포함한 production workload를 처리하며 GitHub Copilot과 Microsoft Foundry 지원은 연말까지 확대할 계획이라고 밝혔다. Maia 300은 long-context reasoning, 지연시간에 민감한 대화, 여러 단계를 오래 수행하는 agent workload에 맞춘 inference-first 시스템이다. 현재 고객이 주문할 수 있는 일반 Azure accelerator 출시가 아니라, 2027년 생산 배포 계획과 시스템 설계 공개다.

### 무엇이 달라졌나

Maia 200의 SDLA(Software Defined Locally Accessed Dataflow Architecture)는 control path와 data path 실행을 분리하고, 소프트웨어가 local SRAM, HBM, DMA, network 사이의 데이터 배치와 이동을 명시적으로 조정한다. Maia 300은 chiplet 전체의 uniform memory access를 locality-aware NUMA 구조로 바꿔 계산과 가까운 곳에 데이터를 놓고, narrow precision과 hardware data-type conversion으로 토큰당 이동 바이트를 줄인다.

한 랙은 4-accelerator tray 24개, 총 96 accelerator를 167kW 안에 구성한다. accelerator·전압 조정기·switch ASIC에서 생기는 rack thermal load의 80% 이상을 liquid cooling으로 제거한다고 설명한다. 128개 rack, 최대 12,288 accelerator를 2단 network로 연결한 superpod 구성도 제시했다. tensor parallelism은 한 rack 안에, 더 넓은 expert·pipeline parallelism은 rack 사이에 배치하는 설계다.

### Microsoft가 제시한 수치

| 비교 조건 | Microsoft 발표 |
| --- | ---: |
| Maia 300 전체 96-accelerator rack 대 Maia 200 | rack-scale token throughput 최대 7배 |
| Maia 300 대 Maia 200 | performance per watt 2.5배 이상 |
| memory 대 Maia 200 | bandwidth 2.5배, capacity 33% 증가, HBM bandwidth per watt 약 2배 |
| Maia 300 대 “leading GPU-based systems” | tokens per megawatt 40% 증가 예상 |
| rack 구성 | 96 accelerators / 167kW |
| superpod | 최대 128 racks / 12,288 accelerators |

이는 Microsoft가 선택한 workload와 시스템 조건에서 발표한 vendor claim이다. “leading GPU”의 제품명, 모델·precision·batch·context/output length, latency SLO, 측정 방법과 독립 benchmark가 공개되지 않아 서로 다른 클라우드의 일반적인 가격·성능 비교로 사용할 수 없다. “40%”는 예상치이고 실제 2027 production 결과가 아니다. 또한 유용한 토큰의 품질이나 정확도를 동일하게 맞췄는지 판단할 정보가 부족하다.

### 엔지니어가 지금 할 일

- 대상: 자체 inference capacity 또는 cloud serving 비용을 계획하는 팀.
- 방법: chip peak FLOPS 대신 동일 모델·precision·context·batch·output length에서 output tokens/s, p50/p95 latency, accuracy·quality, wall power, tokens/kWh, 실제 utilization을 함께 기록한다. long-context, decode-heavy, multi-step agent workload를 별도 bucket으로 나눈다.
- 완료 기준: 최소 세 workload bucket에 대해 “요청당 비용–latency–quality–전력” 비교표가 있고, idle·failed request·cooling overhead 포함 여부와 benchmark 조건이 명시돼 있다.
- 의사결정 주의: Maia 300의 외부 Azure 판매 형태·가격·region·정식 가용일이 나오기 전에는 조달 후보가 아니라 향후 platform direction으로만 추적한다.

## 2. StudentSim — AI 튜터를 학생에게 보내기 전에 ‘학생 반응’을 모의한다

- 원 발표자: Microsoft Research
- 블로그 공개: 2026-10-12
- 연구 논문: arXiv 2609.01591, 2026년 9월
- 공식 블로그: https://www.microsoft.com/en-us/research/blog/simulating-student-learning-for-better-ai-tutoring/
- 논문 기록: https://www.microsoft.com/en-us/research/publication/studentsim-training-llm-based-student-simulators/
- 코드: https://github.com/microsoft/StudentSim (MIT)
- 확인일: 2026-10-13

StudentSim은 특정 학생이 새 문제에 어떻게 답하고, tutor guidance를 받은 뒤 답을 어떻게 바꾸는지를 모의하는 연구 시스템이다. 공개·비식별화된 학습 기록을 여러 학생에 걸쳐 먼저 학습한 뒤 각 학생의 적은 기록으로 다시 특화한다. StudentSimEval은 chess, 제2언어 영어 작문, 중학교 수학의 60명을 대상으로 behavioral fidelity와 guidance responsiveness를 분리해 평가한다. 전자는 해당 학생의 held-out 반응을 얼마나 닮았는지, 후자는 설명을 받은 뒤 실제처럼 답을 갱신하는지를 본다.

### 근거와 의미

체스에서 StudentSim은 behavioral fidelity 0.5150, guidance responsiveness 0.9067을 보고했다. prompted GPT-5.4는 각각 0.2316과 0.7186, chess 전용 Maia2는 0.4535와 0.2721이었다. 즉 범용 역할극 모델은 설명에 반응하지만 특정 학생의 능력 경계를 충분히 보존하지 못했고, 전통적인 chess behavior model은 현재 행동은 더 닮았지만 자연어 지도를 반영하는 능력이 낮았다는 저자 해석이다.

proof-of-concept tutor RL에서는 실제 학생의 이전 오답과 문제를 받은 tutor가 guidance를 만들고, 고정된 StudentSim이 수정 답을 생성한다. Stockfish로 이전 수와 수정 수의 품질 차이를 reward로 삼았다. 같은 tutor policy·초기 checkpoint·RL 설정에서 human chess expert가 blind 평가했을 때 StudentSim reward tutor의 정확도는 90.5%, no-RL baseline은 75.7%, GPT-5.4 simulated-student reward는 71.6%였다. 이는 실제 학습 향상률이 아니라 체스 guidance에 대한 전문가 평가 수치다.

### 제한과 배포 상태

Microsoft는 StudentSim이 제품도, 교실 배포 시스템도, 교사나 실제 학습자 연구를 대체하는 도구도 아니라고 명시한다. 짧고 희소한 과거 기록을 바탕으로 만든 simulator가 장기 학습, 동기·피로·불안, 사회경제적 맥락, 예기치 않은 오개념을 정확히 재현한다고 볼 수 없다. simulator를 reward로 사용하면 tutor가 실제 학생이 아니라 simulator의 허점을 최적화하는 Goodhart 위험도 있다. 체스의 Stockfish 품질은 명확한 외부 신호지만 작문·수학의 교육적 효과는 같은 방식으로 환원하기 어렵다.

코드는 MIT로 공개됐지만 완전한 로컬·무API 재현 pipeline은 아니다. README에 따르면 L2 데이터는 EFCAMDAT 원자료를 별도로 받아야 하고, 수학 data build의 일부 단계와 closed-model baseline은 Azure OpenAI endpoint/key를 요구한다. 이번 뉴스레터 작성에서는 해당 코드나 API를 실행하지 않았다.

### 연구·제품 팀이 지금 할 일

- 대상: AI tutor, 사용자 simulator, human-in-the-loop agent를 평가하는 연구팀.
- 방법: 정답률 하나 대신 (1) 실제 사용자 행동 일치, (2) intervention 후 변화 일치, (3) 불확실성·abstention, (4) simulator와 실제 사용자 결과의 상관을 분리한다. simulator로 후보를 거른 뒤 반드시 held-out real-user study로 다시 검증한다.
- 완료 기준: simulator가 선택한 tutor A/B 순위가 사전등록된 실제 사용자 평가에서도 유지되고, student subgroup별 오류와 privacy·consent·data provenance가 문서화된다.
- 적용 아이디어: EEG/sAAD 연구에서는 synthetic subject를 최종 성능 증거로 쓰지 말고, preprocessing·window·feedback policy를 빠르게 거르는 surrogate로만 사용한 뒤 unseen-subject 결과로 확정한다.

## 오늘의 요약

Maia 300은 inference 최적화의 단위가 개별 chip에서 rack, network, cooling, datacenter power envelope로 이동하고 있음을 보여준다. StudentSim은 AI 시스템의 출력이 아니라 사용자가 그 출력에 어떻게 반응하는지를 학습 신호로 삼는다. 둘을 하나의 시장 추세로 억지로 묶을 필요는 없지만, 공통된 운영 교훈은 proxy metric을 최종 결과로 착각하지 말라는 것이다. vendor token throughput은 공개 조건의 독립 benchmark로, simulated student reward는 실제 학습자 평가로 다시 확인해야 한다.
