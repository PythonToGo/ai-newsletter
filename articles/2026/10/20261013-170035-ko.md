## 트렌드 분석

오늘은 Arm이 공개한 에이전트용 CPU 평가 방법론과 연결된 성능 보고서를 선정했다. 오전에 다룬 Maia 300이 모델 추론 시스템의 전력 효율에 초점을 뒀다면, 이번 발표는 도구 실행·검색·샌드박스·오케스트레이션을 담당하는 CPU의 기여를 측정한다. 같은 인프라 분야지만 별개의 제품·발표·평가 방법이다.

모델 호출 속도만으로 에이전트 전체 성능을 설명하기는 어렵다. 실제 작업에는 코드 빌드, 데이터 조회, 환경 생성, 재시도와 결과 검증이 포함된다. 이번 방법론은 CPU만의 영향을 분리하는 구성요소 측정과 최종 작업 결과를 보는 end-to-end 측정을 함께 사용하자고 제안한다.

편집 관점에서 중요한 변화는 성능 지표의 단위다. 코어 수나 단일 CPU 처리량에 더해, 고정 전력·공간에서 완료 가능한 작업량을 비교하려는 시도다. 다만 랙 모델링 수치와 실제 랙 측정 결과는 구분해야 하며, 평가기관이 별도 회사라는 사실과 연구의 의뢰 주체도 함께 밝혀야 한다.

### 1. Arm, 에이전트 CPU 평가 방법론 공개 — 랙당 1.99배 주장의 조건

- **출처**: Arm Newsroom, Signal65 직접 분석; 발견 경로: 웹 검색·공식 페이지
- **점수**: 7.8 / 10 — 편집 선정 점수이며 성능 점수가 아님
- **URL**: https://newsroom.arm.com/news/arm-agi-cpu-agentic-benchmarks
- **발표·게시일**: Arm 2026-10-13; Signal65 분석 2026-10-12
- **게시 시각·별도 수정일**: 페이지에 미표시
- **확인일**: 2026-10-13
- **상태**: 평가 방법론 공개 및 초기 시스템 분석; 완성된 업계 표준 benchmark suite는 아님

**요약**

Arm은 Fujitsu·Meta·OpenAI의 지원을 받아 에이전트 작업용 CPU 평가 방법론을 발표했다. 모델 추론 외에 도구 실행과 작업 조율을 측정하고, 구성요소 결과가 실제 작업 완료 성능으로 이어지는지 검증한다. 함께 소개된 Signal65 분석은 Arm AGI CPU와 AMD EPYC 9755를 일곱 CPU workload에서 비교했다. 평균 랙당 성능 1.99배는 실제 랙 실측이 아니라 서버 측정치와 정격 전력을 이용한 모델링 결과다.

**맥락**

Arm 백서는 CPU 작업을 에이전트 프레임워크와 실제 도구 workload로 나눈다. 전자는 상태·세션 관리, routing, retries, telemetry 등이며 후자는 compiler, database, search, browser·shell 실행 같은 작업이다. 소프트웨어 개발, 기업 운영, 금융·과학 연구, 개인 비서, 로보틱스의 다섯 archetype을 사용해 서로 다른 CPU 부하를 구분한다.

백서는 재생 가능한 agent trajectory로 모델·네트워크·비결정적 행동의 영향을 줄이는 방향을 제시한다. 구성요소 benchmark는 원인 귀속에, end-to-end benchmark는 사용자에게 보이는 결과에 유리하므로 서로 보완해야 한다. 하나의 종합 점수나 완성된 표준 suite를 확정한 문서가 아니다.

Signal65가 밝힌 비교 조건은 다음과 같다.

| 항목 | 보고서 조건·결과 |
| --- | --- |
| 주 비교 대상 | AMD EPYC 9755, 일곱 CPU workload |
| 평균 모델링 랙 성능 | AGI CPU 1.99배; 개별 workload 1.43–3.19배 |
| 랙 전력 모델 | 24kW 안에 AGI 서버 21–23대, EPYC 서버 13대 |
| 사용한 정격 서버 전력 | AGI 950–1,050W, EPYC 1,700W |
| 별도 sandbox 비교 | EPYC 9965 대비 cold-start 시간 45% 감소 |
| 연구 관계 | Arm 의뢰, Signal65 분석 |

EPYC 9755의 처리량 비교와 EPYC 9965의 sandbox 비교는 같은 실험이 아니다. 수치가 모델 추론 속도나 전체 에이전트 정답률을 뜻하지도 않는다.

**실무 시사점**

에이전트 운영 팀은 모델 대기, tool 실행, sandbox 시작, retrieval, queue 시간을 분리해 trace를 수집하자. 동일 모델 응답과 입력을 재생해 CPU·runtime 변화의 영향을 먼저 측정하고, 이어 실제 end-to-end task 성공률과 p95 latency를 확인한다.

완료 기준은 같은 workload·동시성에서 성공 작업/시간, 실패·재시도율, p95 latency, 실제 서버 전력을 함께 기록한 비교표다. 랙당 환산값을 사용할 때에는 서버 대수·전력·네트워크·냉각 가정을 표에 남긴다. ARM 전환 시 native dependency와 container image의 아키텍처 호환성도 확인한다. 마지막 두 문단은 발표를 바탕으로 한 편집자의 적용 제안이다.

**한계 및 의문**

Signal65는 Arm이 의뢰한 연구임을 공개한다. 별도 기관의 검증을 이해관계 없는 독립 재현과 동일하게 해석하면 안 된다. 초기 AGI CPU 시스템이며 최종 production hardware와 더 넓은 workload 비교는 후속 과제다.

정격 전력 기반 랙 밀도가 평균 우위의 중요한 원인이다. 실제 소비전력, 냉각, I/O와 소프트웨어 최적화가 달라지면 운영 결과도 달라질 수 있다. 자체 서비스의 모델 호출이 전체 시간을 지배한다면 CPU 개선이 사용자 지연시간에 주는 효과는 제한될 수 있다. 이번 검수는 공개 문서 열람이며 하드웨어 실험을 수행하지 않았다.
