# 초경량 Agent 전쟁: 온디바이스 AI가 임계점을 넘었다

## 트렌드 분석

오늘 24시간 동안 쏟아진 뉴스를 관통하는 하나의 거대한 테마가 있다. 바로 'agent 기능을 클라우드 없이, 저사양 기기에서 실행한다'는 온디바이스 agentic AI의 동시다발적 성숙이다. Needle2, Muse Glimmer, LFM2.5-2.6B — 세 모델은 서로 다른 팀이 독립적으로 만들었지만, 놀랍도록 같은 방향을 가리키고 있다.

세 모델의 공통 키워드는 function calling과 로컬 inference다. Needle2는 45M parameter에 14MB라는 극단적 경량화로 Raspberry Pi 수준의 기기에서 800+ tok/s를 달성했고, LFM2.5-2.6B는 2.6B임에도 4배 큰 모델과 경쟁하는 agentic benchmark 성능을 보이며 Apple M5 Max에서 220 tok/s로 구동된다. Muse Glimmer는 30B로 상대적으로 크지만, 단일 consumer GPU가 장착된 Mac/PC에서 LLM-as-a-judge까지 로컬에서 돌릴 수 있다는 점에서 같은 흐름이다. 규모는 다르지만 세 모델 모두 '인터넷 연결 없이 agent를 작동시킨다'는 명제를 현실로 만들고 있다.

흥미로운 점은 이 모델들이 서로 다른 계층의 시장을 동시에 공략하고 있다는 것이다. Needle2는 $200 이하 임베디드 기기와 웨어러블을, LFM2.5는 스마트폰과 엣지 디바이스를, Muse Glimmer는 개발자 워크스테이션을 타깃으로 한다. 이는 단일 제품의 성공이 아니라 온디바이스 agent 생태계 전체가 스택별로 채워지고 있다는 신호다. 특히 Muse Glimmer의 Apache 2.0 오픈소스 공개는 이 생태계의 확산 속도를 더욱 높일 변수다.

실무자에게 주는 핵심 시사점은 명확하다. 지금 당장 agentic 워크플로우를 설계하고 있다면, 클라우드 API 의존도를 기본 가정으로 삼지 말 것. 프라이버시, 레이턴시, 비용 세 가지를 동시에 잡아야 하는 프로덕션 환경이라면 이 세 모델을 기기 스펙에 맞게 계층적으로 테스트하는 것이 다음 단계다. 온디바이스 agent는 더 이상 연구 단계가 아니다.

## 아이템 분석

### 1. Show HN: Needle2: 14MB agentic LLM for phones, wearables, smart home and robots

- **출처**: hackernews
- **점수**: 8.4
- **URL**: https://cactuscompute.com/needle

**요약**

Needle2는 45M parameter, 14MB 크기의 초경량 agentic LLM으로, GPU/NPU 없이 Raspberry Pi 등 $200 이하 저사양 기기에서 800+ tok/s prefill 속도로 function calling을 수행한다.

**맥락**

Edge AI 논의가 Mac/PC 중심으로 흘러가는 동안, 실제 IoT 기기는 210억 대에 달하며 대부분 저사양 하드웨어다. LLM의 소형화 경쟁(예: Phi-3 Mini, Gemma 등)이 가속화되는 가운데, function calling 특화 모델로 파라미터 수를 극단적으로 줄인 접근은 주목할 만한 방향 전환이다.

**실무 시사점**

스마트홈, 웨어러블, 로봇 등 embedded 환경에 AI agent를 통합하려는 엔지니어라면 Needle2의 CQ2-bit compression과 tool retrieval 파이프라인을 참고할 것. 범용 chat 능력 대신 function calling에 task를 한정하면 수십억 파라미터 없이도 실용적 성능을 달성할 수 있음을 보여주므로, 도메인 특화 경량 모델 설계 전략을 재검토할 필요가 있다.

**한계 및 의문**

Mobile-Actions 벤치마크 하나에만 의존한 평가라 일반화 가능성이 불확실하고, CQ2-bit라는 극단적 quantization이 다양한 실제 function calling 시나리오에서 얼마나 robust한지 독립적 검증이 부족하다.

**관련 링크**

- https://cactuscompute.com/needle
- https://huggingface.co/datasets/google/mobile-actions

### 2. Muse Glimmer: 30B-parameter model optimized for always-on local agent workflows

- **출처**: hackernews
- **점수**: 7.7
- **URL**: https://research.meta.ai/blog/introducing-muse-glimmer-open-agentic-model

**요약**

Meta Superintelligence Labs가 30B parameter 규모의 로컬 agent 특화 모델 Muse Glimmer를 Apache 2.0 라이선스로 오픈소스 공개했다. 단일 consumer GPU가 장착된 Mac/PC에서 실행 가능하며, function calling, local coding, LLM-as-a-judge 등 agentic workflow에 최적화되어 있다.

**맥락**

클라우드 의존도를 줄이고 오프라인에서도 AI를 활용하려는 수요가 급증하는 가운데, Mistral, Qwen, Phi 등 소형 고성능 모델 경쟁이 치열해지고 있다. Meta는 Llama 시리즈에 이어 agent 특화 소형 모델로 로컬 AI 생태계 주도권을 강화하려는 전략을 취하고 있다.

**실무 시사점**

개발자는 Hugging Face에서 즉시 모델 weights를 다운로드해 llama.cpp, MLX, ExecuTorch 기반 로컬 agent 파이프라인 구축을 시작할 수 있다. 인터넷 연결 없이 function calling과 LLM-as-a-judge 평가가 가능해지므로, 프라이버시 민감 데이터를 다루는 엔터프라이즈 환경이나 엣지 디바이스 배포 시나리오에서 즉각적인 대안으로 검토할 만하다.

**한계 및 의문**

공개된 벤치마크 결과가 '동급 모델 대비 우수'라고 주장하지만 구체적인 수치와 비교 대상 모델이 명시되지 않아 독립적인 검증이 필요하다. llama.cpp, MLX 등 핵심 통합 기능이 아직 출시되지 않아 실제 사용성은 추후 확인이 필요하다.

**관련 링크**

- https://research.meta.ai/blog/introducing-muse-glimmer-open-agentic-model
- https://huggingface.co

### 3. LFM2.5 2.6B model competitive with 4x larger models

- **출처**: hackernews
- **점수**: 7.6
- **URL**: https://huggingface.co/LiquidAI/LFM2.5-2.6B

**요약**

Liquid AI의 LFM2.5-2.6B 모델이 4배 큰 모델과 경쟁하는 agentic 성능을 보이며, Apple M5 Max에서 220 tok/s, 2.5GB 미만 메모리로 on-device 추론을 지원한다.

**맥락**

엣지 디바이스용 소형 고성능 LLM 경쟁이 치열해지는 가운데, Liquid AI는 기존 transformer 대신 short convolution block과 GQA를 혼합한 hybrid architecture로 차별화를 시도하고 있다. 특히 agentic AI 수요가 급증하면서 tool use와 multi-step reasoning에 특화된 소형 모델의 필요성이 커진 시점에 출시됐다.

**실무 시사점**

온디바이스 AI 앱을 개발하는 엔지니어라면 LFM2.5-2.6B를 Llama나 Phi 계열 대신 agentic workload 벤치마크에서 먼저 테스트해볼 가치가 있다. 34조 토큰으로 학습된 base 모델도 공개되어 있어 domain-specific fine-tuning 실험에 바로 활용 가능하며, 128K context window는 긴 문서 처리 use case에도 적합하다.

**한계 및 의문**

"4배 큰 모델과 경쟁"이라는 주장은 Liquid AI 자체 벤치마크 기준일 가능성이 높으며, 독립적인 third-party 평가가 아직 부족하다. 또한 22개의 double-gated short convolution block 기반 hybrid architecture가 기존 transformer 생태계 툴링과 얼마나 호환되는지 실제 배포 환경에서 검증이 필요하다.

**관련 링크**

- https://huggingface.co/LiquidAI/LFM2.5-2.6B
