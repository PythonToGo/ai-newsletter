# 양자화가 흔든다: 망각·보안·신뢰의 균열

> **리포트 ID**: `20260515-1257`  
> **생성**: 2026-05-15 12:57 UTC  
> **아이템**: 6개  

## 트렌드 분석

오늘 AI/ML 씬을 관통하는 가장 굵은 흐름은 두 가지다. 첫째, '양자화'라는 배포 관행이 모델의 안전성과 신뢰성 전반을 뒤흔드는 변수로 급부상했다. 둘째, LLM을 둘러싼 '기억과 망각'의 문제—무엇을 어떻게 지우고, 무엇을 어떻게 유지할 것인가—가 아키텍처 설계의 핵심 축으로 자리 잡고 있다.

양자화 이슈만 놓고 보면, 오늘 두 편의 연구가 정반대 방향에서 같은 결론을 가리킨다. MANSU는 기존 머신 언러닝 기법이 4비트 양자화 이후 효과를 잃는다는 구조적 취약점을 폭로했고, 아웃라이어 인젝션 공격 연구는 풀 정밀도에서 멀쩡해 보이는 모델이 양자화 후 악성 동작을 유발할 수 있음을 처음으로 실증했다. 즉, 양자화는 단순한 최적화 기법이 아니라 모델의 '의미'와 '행동'을 근본적으로 바꿀 수 있는 변환이다. 두 연구를 함께 읽으면 메시지는 명확하다—양자화 전후를 별개의 모델로 취급하고 검증해야 한다.

'기억'의 반대편에서는 TFGN이 재앙적 망각 없이 LLM을 지속적으로 사전학습하는 방법을 제시하며, 무엇을 '잊지 않게' 할 것인가의 문제를 다룬다. MANSU가 '지워야 할 것을 확실히 지우는' 문제를 푼다면, TFGN은 '지워지면 안 될 것을 보존하는' 문제를 푼다. 두 연구는 서로 상충하는 듯 보이지만, 실은 같은 질문의 양면—LLM의 파라미터 공간을 얼마나 정교하게 제어할 수 있는가—을 탐구한다. 한편 AsyncFC와 ML-Embed는 이 무거운 안전성 논의와 다소 결을 달리하며, 현재 운영 중인 시스템의 효율을 모델 교체 없이 끌어올리는 실용적 접근을 보여준다. FutureSim의 25% 정확도 한계는 이 모든 최적화 노력에도 불구하고 에이전트의 실세계 적응력이 여전히 초보 수준임을 냉정하게 상기시킨다.

실무자에게 주는 핵심 메시지는 하나다. 오늘부터 양자화 모델은 '검증된 모델'이 아닌 '재검증이 필요한 새 모델'로 취급하라. 언러닝 효과 확인, 출력 동작 비교, 보안 무결성 검증—이 세 가지를 양자화 이후 CI/CD 파이프라인에 필수 단계로 편입시키지 않는다면, 배포 환경의 모델은 개발 환경의 모델과 다른 존재일 수 있다.

### 1. Forgetting That Sticks: Quantization-Permanent Unlearning via Circuit Attribution

- **출처**: arxiv
- **점수**: 7.5
- **URL**: http://arxiv.org/abs/2605.15138v1

**요약**

기존 머신 언러닝 기법은 4비트 양자화 후 효과가 사라지는 구조적 문제를 가진다. MANSU는 인과적 회로 귀인으로 최소 서브그래프를 격리해 양자화 후에도 망각이 유지되도록 설계된 새 기법이다.

**맥락**

LLM 배포 시 거의 모든 모델이 4비트 양자화(NF4 등)를 거치지만, 언러닝 평가는 풀 프리시전 상태에서만 이루어져 왔다. 최근 양자화가 언러닝을 되돌릴 수 있다는 연구가 나왔고, 이 논문은 그것이 단순 튜닝 문제가 아닌 그래디언트 기반 방법 전반의 구조적 결함임을 체계적으로 증명한다.

**실무 시사점**

언러닝 파이프라인을 운영하는 ML 엔지니어는 반드시 양자화 후 상태에서도 망각 효과를 검증해야 하며, 기존 GradAscent·RMU 등의 방법은 배포 환경에서 신뢰할 수 없다. MANSU처럼 회로 수준의 타겟 업데이트를 적용하거나, 최소한 NF4 bin width 이상의 파라미터 업데이트 크기를 확보하는 방식으로 언러닝 전략을 재설계해야 한다.

**한계 및 의문**

MANSU의 인과적 회로 귀인 과정 자체의 계산 비용과 대규모 모델(70B+)에서의 확장성이 아직 검증되지 않았으며, NF4 외 다른 양자화 포맷(GPTQ, AWQ 등)에서의 일반화 여부도 열린 문제로 남아 있다.

**관련 링크**

- http://arxiv.org/abs/2605.15138v1

### 2. Concurrency without Model Changes: Future-based Asynchronous Function Calling for LLMs

- **출처**: arxiv
- **점수**: 7.4
- **URL**: http://arxiv.org/abs/2605.15077v1

**요약**

AsyncFC는 LLM 디코딩과 함수 실행을 분리해 비동기 병렬 처리를 가능하게 하는 실행 레이어 프레임워크로, 모델 파인튜닝 없이 기존 함수 호출 프로토콜을 그대로 유지하면서 전체 작업 완료 시간을 크게 단축한다.

**맥락**

LLM 에이전트가 복잡한 멀티스텝 태스크를 수행하는 사례가 급증하면서, 동기식 함수 호출로 인한 레이턴시 병목이 실제 서비스 배포의 핵심 과제로 부상했다. OpenAI, Anthropic 등 주요 LLM 제공사들이 tool use 기능을 강화하는 시점에서, 모델 변경 없이 실행 효율을 높이는 접근법의 필요성이 커지고 있다.

**실무 시사점**

ML 엔지니어는 기존 에이전트 파이프라인에 AsyncFC 방식의 실행 레이어를 도입해 독립적인 함수 호출들을 병렬로 처리함으로써 레이턴시를 줄일 수 있다. 파인튜닝이나 모델 교체 없이 적용 가능하므로, 현재 운영 중인 LLM 에이전트 시스템에 비교적 낮은 비용으로 성능 개선을 시도해볼 수 있다.

**한계 및 의문**

논문 내용이 일부 잘려 있어 벤치마크 결과의 구체적인 수치와 실패 케이스를 확인하기 어렵고, 함수 간 의존성이 복잡한 실제 프로덕션 환경에서의 안정성과 오류 처리 방식은 추가 검증이 필요하다.

**관련 링크**

- http://arxiv.org/abs/2605.15077v1

### 3. TFGN: Task-Free, Replay-Free Continual Pre-Training Without Catastrophic Forgetting at LLM Scale

- **출처**: arxiv
- **점수**: 7.3
- **URL**: http://arxiv.org/abs/2605.15053v1

**요약**

TFGN은 리플레이 버퍼나 태스크 ID 없이 LLM을 여러 도메인에 걸쳐 지속적으로 사전학습할 수 있는 트랜스포머 아키텍처 오버레이로, LLaMA 3.1 8B 수준에서 재앙적 망각을 효과적으로 억제한다.

**맥락**

LLM의 지속적 학습(Continual Learning)은 새 도메인 데이터 학습 시 기존 지식이 소실되는 재앙적 망각 문제로 인해 실용화가 어려웠다. 기존 해결책인 리플레이 버퍼나 EWC 같은 정규화 기법은 LLM 규모에서 메모리·연산 비용이 폭발적으로 증가해 실용성이 낮았으며, 이 문제는 멀티도메인 파운데이션 모델 구축의 핵심 병목으로 남아 있었다.

**실무 시사점**

ML 엔지니어는 TFGN 방식을 통해 도메인별 파인튜닝 파이프라인을 단순화하고, 별도의 리플레이 데이터 관리 인프라 없이 코드·수학·바이오메디컬 등 이종 도메인을 순차적으로 학습하는 아키텍처 설계를 검토할 수 있다. 특히 기존 모델에 Retrofit 방식으로 적용 가능하다는 점에서, 이미 배포된 LLM에 새 도메인 지식을 추가할 때 실용적인 대안이 될 수 있다.

**한계 및 의문**

논문 초록만으로는 TFGN의 파라미터 효율성 구체적 수치와 추론 시 오버헤드가 불명확하며, HellaSwag 등 제한된 벤치마크만으로 일반화 성능을 단정하기 어렵다. 또한 9B 수준에서의 실험이 포함되어 있으나 더 대형 모델(70B+)로의 확장성은 아직 검증되지 않았다.

**관련 링크**

- http://arxiv.org/abs/2605.15053v1

### 4. Widening the Gap: Exploiting LLM Quantization via Outlier Injection

- **출처**: arxiv
- **점수**: 7.2
- **URL**: http://arxiv.org/abs/2605.15152v1

**요약**

공격자가 풀 정밀도에서는 정상처럼 보이지만 양자화 후 악성 동작을 유발하는 LLM을 배포하는 새로운 공격 기법이 제안됐다. AWQ, GPTQ, GGUF I-quants 등 주요 고급 양자화 기법을 모두 대상으로 성공한 첫 번째 사례다.

**맥락**

LLM 경량화를 위한 양자화는 엣지 디바이스 및 로컬 배포의 핵심 기술로 자리잡았고, Hugging Face 등 플랫폼에서 양자화 모델 공유가 일상화됐다. 기존 공격은 단순한 양자화 방식에만 통했으나, 이번 연구는 실제 현장에서 널리 쓰이는 AWQ·GPTQ·GGUF까지 뚫어 공급망 보안 위협이 현실화됐음을 보여준다.

**실무 시사점**

Hugging Face 등에서 다운로드한 양자화 모델을 그대로 프로덕션에 사용하는 팀은 모델 출처와 무결성 검증 프로세스를 즉시 점검해야 한다. 풀 정밀도 모델과 양자화 모델의 출력 동작을 비교하는 자동화 테스트를 CI/CD 파이프라인에 추가하고, 신뢰할 수 없는 소스의 모델 사용을 제한하는 정책 수립이 필요하다.

**한계 및 의문**

논문이 아직 arXiv 프리프린트 단계로 동료 심사를 거치지 않았으며, 실제 공격 성공률과 탐지 가능성에 대한 상세 분석이 공개된 내용만으로는 충분히 검증되지 않는다. 또한 방어 기법이나 탐지 방법론은 제시되지 않아 실질적인 대응책 마련에는 추가 연구가 필요하다.

**관련 링크**

- http://arxiv.org/abs/2605.15152v1

### 5. ML-Embed: Inclusive and Efficient Embeddings for a Multilingual World

- **출처**: arxiv
- **점수**: 7.2
- **URL**: http://arxiv.org/abs/2605.15081v1

**요약**

ML-Embed는 3D Matryoshka Learning(3D-ML) 프레임워크 기반의 다국어 텍스트 임베딩 모델 제품군으로, 높은 계산 비용·좁은 언어 지원·불투명성 문제를 동시에 해결하려 한다. 140M~8B 파라미터 규모의 모델을 오픈 방식으로 제공한다.

**맥락**

OpenAI, Cohere 등 상용 임베딩 API가 시장을 주도하는 가운데, 비영어권 언어 지원 부족과 폐쇄적 모델 구조가 연구·실무 모두에서 병목이 되고 있다. MRL(Matryoshka Representation Learning) 계열 기법이 효율적 임베딩의 대안으로 주목받는 시점에 등장한 연구다.

**실무 시사점**

다국어 RAG 파이프라인이나 시맨틱 검색 시스템을 구축하는 엔지니어라면 ML-Embed의 가변 차원·가변 레이어 추론 기능을 활용해 지연 시간과 스토리지를 동시에 줄일 수 있다. 특히 한국어 등 비영어 언어 처리 품질이 상용 API 대비 어느 수준인지 벤치마크 비교 실험을 직접 수행해볼 가치가 있다.

**한계 및 의문**

논문 초록만 공개된 상태라 실제 벤치마크 수치와 지원 언어 목록이 확인되지 않았으며, 8B 모델의 실제 추론 비용 절감 효과도 검증이 필요하다. 오픈웨이트와 완전 오픈소스의 차이가 명확히 밝혀지지 않아 상업적 활용 가능성도 불투명하다.

**관련 링크**

- http://arxiv.org/abs/2605.15081v1

### 6. FutureSim: Replaying World Events to Evaluate Adaptive Agents

- **출처**: arxiv
- **점수**: 7.1
- **URL**: http://arxiv.org/abs/2605.15188v1

**요약**

FutureSim은 실제 뉴스 이벤트를 시간순으로 재현해 AI 에이전트의 적응 능력을 평가하는 벤치마크로, 최고 에이전트도 정확도 25%에 그쳐 현 AI의 한계를 드러냈다.

**맥락**

AI 에이전트가 동적 환경에 실시간 배포되는 사례가 늘면서, 지식 컷오프 이후 새 정보에 적응하는 능력을 측정하는 현실적 벤치마크의 필요성이 커졌다. 기존 벤치마크는 정적 데이터셋 기반이라 실제 배포 환경과 괴리가 있었다.

**실무 시사점**

ML 엔지니어는 자사 에이전트의 장기 예측 및 실시간 정보 적응 능력을 FutureSim 방식으로 검증해볼 필요가 있으며, 단순 정확도보다 Brier Skill Score 같은 보정된 확률 지표로 모델을 평가하는 습관을 가져야 한다. 또한 테스트타임 적응(test-time adaptation) 연구가 실용적 가치를 가짐을 인식하고 관련 기법 도입을 검토할 시점이다.

**한계 및 의문**

평가 기간이 2026년 1~3월 3개월로 한정되어 장기 일반화 여부가 불확실하며, 뉴스 기반 시뮬레이션이 실제 에이전트 배포 환경의 다양성을 완전히 대표하지 못할 수 있다.

**관련 링크**

- http://arxiv.org/abs/2605.15188v1
