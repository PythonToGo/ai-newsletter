### 1. GPT-Live-1.1 API: 말하기·듣기와 별도로 ‘대기’를 설계한다

- **출처**: OpenAI API 변경 기록·공식 모델/세션 문서·개발자 공지
- **점수**: 8.7/10 *(편집 선정 점수이며 벤치마크 점수가 아님)*
- **URL**: https://developers.openai.com/api/docs/changelog
- **원 게시자**: OpenAI
- **발견 경로**: 최신 음성 모델 검색 → API 변경 기록 → 공식 공지·요금·세션 동작 대조
- **API 변경 기록일**: 2026-11-19
- **별도 공지일**: 개발자 커뮤니티에 2026-11-20 04:12 표시; 표시 시간대 미확인, UTC로 변환하지 않음
- **수정일**: 각 문서의 별도 수정 시각 미확인
- **확인일**: 2026-11-20
- **상태**: API 제공; 기존 ChatGPT 음성 제공과 이번 API 제공을 구분

**요약**

OpenAI가 GPT-Live-1.1의 API 제공을 변경 기록에 추가했다. 듣는 중 말하거나 말하는 중 듣는 전이중(full-duplex) 음성 모델이며, 회사는 다국어 발음·억양 유지·전사 개선을 설명한다. 복잡한 작업을 별도 백엔드에 넘기는 구조를 지원한다. GPT-Live-1과 1.1의 WebRTC 세션에는 연결을 유지하면서 추론을 쉬는 standby 설정도 추가됐다.

**맥락**

공지에 따르면 1.1은 10월 15일부터 ChatGPT Plus·Pro 음성에 사용됐지만 이번 변화는 **개발자의 자체 앱에서 사용하는 API**다. 회사의 품질 개선 설명을 한국어의 독립적인 오류율 측정치로 바꾸지 않았다.

공식 요금 단위는 입력·출력 토큰이 아니라 **음성 세션 시간**이다.

| 세션 상태 | 분당 미국 달러 | 조건 |
| --- | ---: | --- |
| 활성 | $0.05 | 활성 음성 세션 |
| 대기 | $0.02 | WebRTC에서 추론이 멈춘 standby 시간 |

백엔드 모델·도구 사용료는 별도다. 이 음성 요금에 입력·출력·캐시 토큰 단가를 임의로 부여하지 않는다. 백엔드 비용은 선택한 모델의 입력·출력·캐시 조건으로 따로 계산해야 한다. 예를 들어 활성 6분·대기 4분이면 음성 부분은 **$0.38**이며, 이는 명시 요금의 산술 예시이지 실측 청구액이 아니다.

**실무 시사점**

음성 서비스 담당자는 발화뿐 아니라 대기·재개·종료를 포함한 시험 대화를 만들자. 문서상 대기 전환은 5–60초 정수 타임아웃으로 설정하며, 대기 중에도 마이크 트랙을 유지해야 한다. 재개 뒤 짧은 첫 발화의 응답이 늦어질 수 있으므로 첫 단어 누락·오인식·중복 실행과 전체 비용을 측정한다.

완료 기준은 대기 비용 절감뿐 아니라 기존 대비 허용 가능한 재개 지연과 작업 성공률을 만족하는 것이다. 긴 공백에는 세션 종료·재연결도 비교하되 작업 상태를 보존한다. 이번에는 음성 업로드·모델 호출·과금 시험을 하지 않았다.

**한계 및 의문**

확인한 공지는 다국어 향상을 설명하지만 언어별 공개 정량 결과는 이 자료만으로 확정할 수 없다. 동시 세션 한도는 계정별 확인 대상이다. standby를 무료 무음 구간이나 모든 전송 방식의 기능으로 표현하지 않는다. 이 모델을 영상 입력 모델로 다루지도 않는다.

### 2. CellularAI: 새 세포의 반응을 큰 신경망 대신 실험 근거의 통합으로 예측한다

- **출처**: Illumina BioInsight AI Lab 방법 설명·공식 보도자료
- **점수**: 8.6/10 *(편집 선정 점수이며 생물학적 예측 정확도가 아님)*
- **URL**: https://www.illumina.com/science/genomics-research/articles/introducing-the-cellularai-algorithm--predicting-single-cell-res.html
- **원 게시자**: Illumina / Laurel Mastro, Kishore Jaganathan, Eyal Ben David, Robert Yamulla
- **발견 경로**: 최신 과학 ML·데이터 발표 검색 → 원 게시자의 방법·실험 설명과 보도자료 대조
- **알고리즘 발표·글 게시일**: 2026-11-19; 정확한 게시 시각 미확인
- **별도 사건**: 2026 Virtual Cell Challenge 우승을 회사가 같은 날 발표; 대회 결과 확정 시각 미확인
- **수정일**: 별도 수정일 미확인
- **확인일**: 2026-11-20
- **상태**: 초기 연구 접근과 간소화 버전의 오픈소스 공개 안내; 완전한 코드·라이선스·원천 데이터 배포 검증은 보류

**요약**

Illumina가 특정 유전자를 억제했을 때 새로운 세포 유형의 유전자 발현이 어떻게 변하는지 예측하는 CellularAI를 발표했다. 핵심은 같은 유전자를 다른 세포에서 억제한 실제 실험을 모아 신뢰도와 유사성에 따라 가중하는 것이다. 목표 세포의 대형 신경망을 학습하는 방식이 아니라 통계적 메타분석이 중심이다. 회사는 초기 간소화 버전의 공개를 안내하지만 Billion Cell Atlas 데이터 자체가 포함되는 것은 아니라고 명시한다.

**맥락**

CRISPRi는 유전자 활성을 낮추는 실험 방식이고, 전사체는 세포에서 측정한 여러 유전자의 발현 전체를 뜻한다. CellularAI는 미처리 세포의 상태에서 시작해 예측한 만큼 발현을 조정하며, 근거가 약하거나 불일치하면 큰 변화를 주지 않는 접근이다. ‘가상 세포를 생성한다’는 표현을 임의의 생물학을 처음부터 창조한다는 뜻으로 읽지 않는다.

방법 글은 **H1·K562·HEK293 세 유형**에서 해당 세포의 실험 자료를 참조 라이브러리에서 뺀 평가를 설명한다. 이는 관측된 세포를 그대로 찾아 답하는 것보다 의미 있는 분할이지만 모든 새 조직으로의 일반화를 보장하지는 않는다. ‘평균 기준선 대비 2배’라는 회사의 표현은 모든 유전자·지표에서 정확도가 두 배라는 뜻이 아니므로 단일 성능 보장치로 채택하지 않았다.

**실무 시사점**

과학 ML 팀은 신경망을 키우기 전에 평균·유사 사례 가중·통계적 통합 기준선을 함께 설계하자. 관련 데이터에서는 세포 유형을 통째로 보류하고, 참조 데이터의 중복과 측정 배치 효과를 점검한다. 완료 기준은 강한 단순 기준선을 넘고, 실제로 변화한 유전자에 대한 오차와 불확실성을 별도로 설명하는 것이다.

회사 발표의 대회 성과와 사용자가 재현할 수 있는 공개 범위를 구분해야 한다. 초기 알고리즘·실험 데이터·대회 최적화가 모두 같은 배포물에 들어 있다고 가정하지 않는다. 이번에는 생물학 데이터 분석이나 실험을 실행하지 않았다.

**한계 및 의문**

회사는 우승을 발표했지만 방법 글에는 최종 대회 수치가 게시 시점에 아직 없고 추후 갱신한다는 문구도 남아 있다. 따라서 회사의 성과 발표로 귀속하고 정확한 종합 점수·경쟁 모델 대비 차이는 쓰지 않았다. 상세 원고도 **2027년 초 예정**으로 안내한다.

코드 공개 안내와 전체 원천 데이터의 개방은 다르다. 참조 라이브러리의 범위가 바뀌면 재현 성능도 달라질 수 있다. 결과는 연구 가설이며 임상 효과나 치료 선택을 입증하지 않는다.

### 3. Gemini Tool Retrieval 프리뷰: 도구 정의를 줄이되 검색 비용까지 계산한다

- **출처**: Google 공식 출시 글·Gemini API Tool Retrieval 문서
- **점수**: 8.3/10 *(편집 선정 점수이며 비용 절감률이 아님)*
- **URL**: https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval/
- **원 게시자**: Google / Lucia Loher, Nora Kassner
- **발견 경로**: 최신 개발 도구·추론 인프라 검색 → 공식 발표 → 설정·과금 문서 대조
- **프리뷰 발표일**: 2026-11-19; 정확한 게시 시각 미확인
- **수정일**: 별도 수정일 미확인; 문서는 확인 시점 기준
- **확인일**: 2026-11-20
- **상태**: Interactions API 프리뷰, 지원 모델 조건 있음

**요약**

Google이 많은 도구의 매개변수 정의를 필요할 때 불러오는 Tool Retrieval을 발표했다. 모델은 지연 로딩한 도구의 이름과 설명을 보고 사용할 도구를 고르며, 전체 스키마는 그때 문맥에 들어간다. 서버측 방식은 `tool_search`와 `defer_loading: true`를 함께 사용하고 원격 MCP 서버에도 적용한다. 실제 사용자 함수 실행은 기존 함수 호출 흐름처럼 애플리케이션이 수행한다.

**맥락**

스키마는 함수가 받는 필드·자료형·필수값을 설명하는 명세다. 수백 개 도구의 명세를 처음부터 전부 보내는 대신 드물게 쓰는 도구를 늦게 불러올 수 있다. 발표는 Gemini 3.6 이상과 Gemini 4 계열의 Interactions API 지원을 안내한다.

중요한 과금 구분이 있다. 기능의 **별도 사용료는 없지만**, 입력·캐시 입력·출력은 사용 모델의 단가로 청구한다. 문서는 서버측 검색마다 같은 요청 안에서 추가 모델 호출이 생기며, 전체 문맥과 불러온 스키마가 `total_tool_use_tokens`에 잡혀 입력 요금으로 계산된다고 설명한다. 따라서 ‘스키마가 작아졌다’만으로 전체 요금이 줄었다고 할 수 없다.

**실무 시사점**

여러 시스템의 도구를 연결하는 팀은 같은 업무를 전체 사전 로딩·서버측 지연 로딩·기존 자체 검색으로 비교하는 시험을 설계하자. 성공률·도구 선택 오류·검색 횟수·전체 지연과 함께 일반 입력, 도구 사용 입력, 캐시 입력, 출력·추론 토큰을 각각 기록한다. 완료 기준은 성공률을 유지하면서 성공 작업당 총비용 또는 지연을 줄이는 것이다.

자주 쓰는 도구는 미리 로딩하고 긴 꼬리의 드문 도구만 지연시키는 방안이 출발점이다. 이름이 비슷한 도구는 서비스명을 넣고 설명을 구분한다. 이 제안은 도입 평가 절차이며 이번 작업에서는 API 요청을 실행하지 않았다.

**한계 및 의문**

검색이 여러 번 반복되거나 원래 스키마가 작으면 오히려 비싸질 수 있다. 스키마를 줄여 문맥이 캐시 최소 길이보다 짧아지는 경우도 문서가 지적한다. 캐시 적중을 가정한 할인과 실제 적중을 구분해야 한다.

클라이언트측 검색은 왕복 요청과 자체 검색 비용이 추가된다. 도구를 찾았다는 사실이 실행 권한을 부여하지도 않으므로 권한 필터와 승인 검사는 별도로 유지해야 한다. 공식 문서의 비용 구조를 확인했으며 특정 트래픽의 절감률이나 성능 향상 수치는 만들지 않았다.
