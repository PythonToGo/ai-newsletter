### 1. FoxBrain v2.1 발표: 지역 지식의 높은 점수와 기업 배포의 조건은 별개다

- **출처**: Hon Hai Research Institute / Foxconn 공식 발표
- **점수**: 7.6/10 — 편집 선정 점수
- **URL**: https://www.foxconn.com/en-us/press-center/press-releases/latest-news/2164

**요약**

Hon Hai Research Institute가 11월 27일 FoxBrain v2.1의 대만 Sovereign AI Benchmark 평가 결과와 기업 자체 환경 배포 구상을 발표했다. 모델 규모는 31B, 약 310억 파라미터다. 회사는 현재 집계된 해당 평가에서 종합 2위라고 보고하며, 중국어 96.20%·사회 91.40%·대만 가치 문항 98.00%를 제시한다. 이는 특정 문항군의 결과이지 범용 AI 전체의 세계 순위가 아니다.

**맥락**

평가는 최근 5년 대만 대학입학 시험의 중국어·사회 문항과 대만 가치 지표를 다룬다. 회사는 자체 번체중문 데이터 구축, 학습, 정렬, 평가의 연결을 강조한다. 이 발표가 가리키는 변화는 기업이 지역 언어·지식에 맞춘 모델 선택을 검토할 자료가 추가됐다는 점이다.

발표는 조건에 맞는 단일 AI 서버 배포가 가능하다고 설명하지만, 서버 사양과 추론 설정에 달려 있다. 따라서 ‘31B니까 아무 서버 한 대면 된다’는 결론은 성립하지 않는다. 원문이 연결하는 평가 결과는 10월 시험 자료이며, 오늘 새로 수행한 시험으로 소개하지 않는다.

**실무 시사점**

번체중문 업무를 다루는 엔지니어링 팀은 일반 상식 문항과 실제 업무 문항을 분리한 검증표를 준비하자. 문서 검색·표 추출·근거 없는 답변·지역 용어 처리를 같은 입력과 채점 기준으로 비교하고, 모델 접근 조건이 확인된 뒤 검증한다. 완료 기준은 공급자 순위를 재인용하는 것이 아니라 자사 오류 유형별 성적과 배포 자원 요구량을 확보하는 것이다.

자체 환경 배포를 검토할 때도 가중치 제공 방식·사용권·로그·외부 연결·데이터 보관 경로를 먼저 확인해야 한다. 모델을 내부 서버에 둔다는 설명만으로 전체 애플리케이션의 데이터 이동까지 결정되지는 않는다.

**한계 및 의문**

AIEC 결과 페이지는 이번 조회에서 403으로 열리지 않았다. 따라서 순위·정답률은 Foxconn 발표로 귀속하며 독립 대조 완료로 표시하지 않는다. 공개 발표만으로 가중치 다운로드·상업 사용 허가·일반 제공이 확인됐다고 주장하지 않는다. 정확한 최초 모델 공개일과 별도 수정일도 미확인이다.

### 2. WAVE-GPT 가중치 공개: 돌고래의 말을 번역하는 것이 아니라 소리의 순서를 검증한다

- **출처**: 연구자 Hugging Face 모델 카드·업로드 이력·공개 GitHub README
- **점수**: 7.8/10 — 편집 선정 점수
- **URL**: https://huggingface.co/j-h/wave-token-gpt-open

**요약**

WAVE-GPT 프로젝트가 11월 27일 동물 음향 사건의 연속을 모델링하는 공개 가중치 다섯 개를 올렸다. 원시 수중 녹음 전체를 바로 언어 모델에 넣는 대신, 물리 기반 전처리로 추출한 개별 울음소리의 특성을 사건 토큰으로 바꾼다. 공개판은 단일 소리 기준 모델, 겹치는 소리용 모델, 행동·차례 전환 연구용 모델을 포함한다. 가중치 공개는 다른 연구자가 접근법을 검사할 수 있게 한다는 의미이며, 동물 언어 번역기의 출시가 아니다.

**맥락**

README는 녹음 장소·수중 마이크 특성을 학습하는 지름길을 줄이는 것을 목표로 설명한다. 겹침을 다루는 표현은 기존 특성에 화음·동시 소리 슬롯·겹침 정도를 더하며, 시간 간격을 반영하는 인과 Transformer로 다음 사건을 예측한다. 공개판과 비상업 연구판의 학습 자료·가중치 경로도 분리한다.

연구자는 공개 자료 180,549개 사건으로 학습한 약 14.42M 모델이 미학습 지중해 Garraf 평가에서 HMM 대비 1.8297 nats의 예측 개선을 보였다고 보고한다. HMM은 숨은 상태의 전환으로 순서를 예측하는 통계 기준선이다. 이 수치는 음향 사건의 통계적 예측을 평가하며, 의도나 의미의 정답률이 아니다.

**실무 시사점**

과학 ML·환경 음향 팀은 모델 크기보다 먼저 녹음 장소 단위의 분리와 데이터 권리 추적을 검토하자. 같은 녹음 환경이 학습·평가에 섞이지 않도록 나누고, 간단한 통계 기준선과 신경망을 동일 사건 표현에서 비교하는 계획을 세운다. 완료 기준은 새 장소에서도 이득이 남고, 장소 식별 신호와 생물학적 유용성을 별도 지표로 설명하는 것이다.

공개 README의 결과 파일과 가중치 해시를 연결해 재현 대상을 고정할 수 있다. 이번 뉴스레터에서는 코드를 실행하거나 합성 음향을 생성하지 않았다. 후속 실험에서도 합성 울음소리를 야생 동물에게 재생하는 방식으로 사용하지 않아야 한다.

**한계 및 의문**

저자 보고의 전체 80-WAV 야생 행동 분류는 OVR-AUC 0.5850, p=0.1194로 유의하지 않았다. 일부 교란 검사도 새로 추가한 표현 요소 모두를 섞지 않았다는 한계가 명시돼 있다. 작은 탐색 연구의 긍정 수치만으로 종·장소를 초월한 의미 해독을 주장할 수 없다.

현재 README는 프리프린트 DOI를 연결하지만, 이를 동료심사 통과로 해석하지 않는다. 발견 기사보다 원 자료의 상태가 구체적이므로 원 자료를 기준으로 작성했다. Apache-2.0 공개판과 별도 비상업 연구판은 혼동하지 않는다.

### 3. eleMusic의 YuE2 악보 어댑터: 작은 추가 학습으로 편곡을 유도하되, 보컬 혼입은 남는다

- **출처**: eleMusic 모델 카드·공개 학습 코드
- **점수**: 7.5/10 — 편집 선정 점수
- **URL**: https://huggingface.co/elemusic/YuE2-3B-elemusic-lead-v1

**요약**

eleMusic이 11월 28일 YuE2-3B를 위한 lead-v1 어댑터를 공개했다. ABC라는 텍스트 악보 표기를 조건으로 기악 편곡을 생성하도록 유도하는 rank-16 LoRA다. 약 69.8MB의 두 파일은 서로 다른 적재 형식이며 별도 모델 두 개가 아니다. 실행에는 기존 YuE2-3B 본체가 필요하므로 전체 모델이 70MB라는 뜻은 아니다.

**맥락**

LoRA는 기본 가중치를 모두 새로 학습하지 않고 작은 저랭크 보정값을 더하는 방식이다. 공개 학습 README는 선호하지 않는 결과 전체에 벌점을 줄 때 정상 종료 토큰까지 억제돼 음악이 끝나지 않는 문제를 설명한다. 바람직한 결과를 따르는 SFT 학습과 선호 최적화 KTO를 결합하고, 종료 토큰 처리를 분리하는 접근이다.

모델 카드는 1900년 이전 공개 악보를 조건으로 기본 모델이 생성한 결과를 사용하고, 곡 ID 기준 학습 167·검증 13·시험 22개로 분리했다고 설명한다. 미학습 곡·스타일·seed 조합 24개 음향 평가에서 보컬 혼입은 기본 모델 70.8%에서 37.5%로 줄었다고 보고한다. 이는 개선인 동시에 여전히 기악 조건을 어긴 출력이 남는다는 결과다.

**실무 시사점**

음악 생성 연구팀은 ‘기악’이라는 스타일 문구뿐 아니라 주선율 준수·사람 목소리 혼입·자연스러운 종료를 각각 시험하자. 기본 모델과 어댑터를 같은 악보·스타일·seed·길이 예산으로 비교하고, 자동 평가 외에 청취 검토를 별도로 설계한다. 완료 기준은 선율 유사도만 높이는 것이 아니라 원치 않는 보컬과 끝나지 않는 출력이 사전에 정한 수준 아래로 내려가는 것이다.

코드 README의 일반 권장 레시피와 lead-v1 카드의 실제 학습 설정은 동일한 실험으로 합치지 않는다. 가중치·기본 모델·loader 버전을 함께 고정하고 두 파일 형식 중 실행 경로에 맞는 하나를 선택하는 검증 계획이 필요하다.

**한계 및 의문**

24개 조합은 작은 평가이며 장르·악보·길이가 달라져도 같은 개선이 유지된다는 증거는 아니다. 모델 카드의 선호 평가 20/22와 음향 평가 24개는 서로 다른 시험이므로 분모를 섞지 않는다. 합성 훈련 결과와 자동 점수가 음악 전문가의 평가를 대신하지도 않는다.

코드는 Apache-2.0이지만 어댑터 가중치는 CC BY-NC 4.0이다. 상업 배포는 별도 상위 모델 라이선스 검토가 필요하다는 프로젝트 안내가 있다. 악보의 공개 여부만으로 전체 모델과 출력의 권리 문제까지 해결됐다고 가정하지 않는다.
