## 트렌드 분석

이번 소식은 서로 다른 세 문제를 다룬다. Project Genie는 생성한 세계를 탐색하면서 바꾸는 상호작용을, SageMaker는 모델 전체 가중치의 맞춤 학습을, Microsoft-Decision-1.1은 정해진 선택지 중 답을 고르는 추론을 다룬다. 이를 하나의 성능 경쟁으로 묶기보다 시각적 일관성, 학습 후 능력 보존, 분류 오류와 지연이라는 각자의 기준으로 읽는 편이 유익하다.

공통된 실무 과제는 ‘쓸 수 있다’와 ‘업무에 맞는다’를 분리하는 것이다. 세계 모델의 사실적인 화면은 물리 시뮬레이터의 검증을 대신하지 않는다. 인프라를 직접 관리하지 않는 학습도 연산 비용과 망각 위험이 있다. 확률을 반환하는 분류 모델도 실제 데이터에서 임계값을 검증해야 한다. 이는 발표 내용을 도입 판단으로 옮긴 편집부의 해석이다.

AI·ML·딥러닝·비전·로보틱스·학습 인프라를 검색하고, 최근 14일 뉴스 아카이브 15개 및 오늘 오전 편의 URL·사건을 대조했다. 최근 7일의 과학 ML·로봇·비전 도구·음성·하드웨어와 균형을 고려했다. 이번 세 공식 글은 모두 **2026-11-18** 표시이며 게시 시각은 확인하지 못했다. 일부 발견 목록은 19일자로 표시하지만 이를 최초 발표일로 채택하지 않았다. 최근 발표의 미소개 소식으로 선정하되 엄밀한 최근 24시간 이내 여부는 확정하지 않는다. 오전의 Neon·Rumble·RTX Spark는 반복하지 않았다.

### 1. Genie 4 접근 확대: 탐색 중 세계를 고치되 물리적 정답으로 보지는 않는다

- **출처**: Google 공식 제품 발표·Google DeepMind 모델 카드
- **점수**: 8.8/10 *(편집 선정 점수, 측정된 성능 점수가 아님)*
- **URL**: https://blog.google/innovation-and-ai/models-and-research/google-deepmind/genie-4-now-available-project-genie/
- **원 게시자**: Google DeepMind·Google Labs / Diego Rivas, Pavan Kumar
- **발견 경로**: 최신 AI 뉴스 검색 → 공식 제품 발표 → 모델 카드 대조
- **발표·접근 확대일**: 2026-11-18, 정확한 시각 미표시
- **수정일**: 별도 수정일 미확인
- **확인일**: 2026-11-19
- **상태**: 실험적 연구 프리뷰의 제품 접근 확대; 자격을 갖춘 Google AI Ultra 대상 순차 제공, Pro는 대기 명단

**요약**

Google이 Project Genie에서 Genie 4를 이용할 수 있는 범위를 넓힌다고 발표했다. 사용자는 세계를 탐색하는 도중 텍스트로 환경이나 등장 요소를 바꾸고 장면에 반응하는 소리를 들을 수 있다. 모델 카드는 동기화된 오디오와 **720p·최대 24fps** 출력을 명시한다. 새 창작 보조 기능과 공유 갤러리도 제공하지만, 공개 가중치나 일반 개발자용 API의 무제한 제공을 뜻하지 않는다.

**맥락**

이번 변화는 모델 연구 소개보다 **제품에서의 접근과 조작 방식**에 있다. 같은 발표에 들어 있는 **생성당 최대 3분·360도 파노라마 입력**은 Genie 3 업데이트다. 이를 Genie 4의 세션 한도라고 옮기지 않았다.

모델 카드는 텍스트·이미지·사용자 조작을 입력으로 받는 상호작용 생성 시스템으로 설명한다. 반면 장면의 객체와 공간 관계가 긴 탐색이나 반복 편집 뒤 달라질 수 있다고 인정한다. 화면 품질과 상태의 지속성은 별도로 평가해야 한다.

**실무 시사점**

인터랙티브 콘텐츠·시각 시뮬레이션을 검토하는 팀은 방 하나와 물체 몇 개를 고정한 시험 시나리오부터 설계하자. 이동·뒤돌아보기·날씨 변경을 반복하며 물체 수와 위치, 소리의 시점, 조작 지연을 기록한다. 완료 기준은 예쁜 예시 한 편이 아니라 정해진 반복 횟수에서 허용 가능한 일관성을 유지하는 것이다.

로봇 학습 환경 후보로 검토한다면 접촉·질량·좌표의 정량적 정답을 요구하자. 이를 확인하기 전에는 기존 물리 엔진이나 실제 로봇 평가를 대체하지 않는 것이 타당하다. 이번 작업에서는 제품에 접속하거나 세계를 생성하지 않았다.

**한계 및 의문**

카드가 제시한 영상 사양은 실제 네트워크·세션마다 보장되는 조작 지연이 아니다. 공간 정확도·복잡한 물리 상호작용·장기 일관성은 여전히 연구 과제로 표시된다. 회사의 품질 향상 설명과 독립 검증 결과를 구분했으며, 수치가 없는 상대적 개선 폭을 만들지 않았다.

자격 조건과 순차 제공을 모든 지역·계정의 즉시 접근으로 해석하지 않는다. 구독 가격이나 사용량 할당은 여기서 확정하지 않았다.

### 2. SageMaker 전체 미세조정: 서버 관리가 줄어도 망각 검증은 남는다

- **출처**: AWS Machine Learning Blog·SageMaker AI 공식 문서
- **점수**: 8.5/10 *(편집 선정 점수, 학습 성능 점수가 아님)*
- **URL**: https://aws.amazon.com/blogs/machine-learning/full-fine-tuning-fft-on-sagemaker-ai-serverless-model-customization/
- **원 게시자**: AWS / Sandeep Raveesh-Babu
- **발견 경로**: 최신 학습 인프라 뉴스 검색 → AWS 원문 → FFT·지원 모델 문서
- **발표 글 게시일**: 2026-11-18, 정확한 시각 미표시
- **서비스 최초 지원일**: 이 글만으로 별도 확정하지 않음; 현재 지원 안내와 실험 설명으로 취급
- **수정일**: 별도 수정일 미확인; 문서의 최초 공개일도 미확인
- **확인일**: 2026-11-19
- **상태**: 지원 모델·학습 방식별 조건을 갖춘 관리형 학습 서비스

**요약**

AWS가 SageMaker AI Serverless Model Customization에서 전체 미세조정(FFT)을 지원한다고 안내하고 비교 실험을 공개했다. FFT는 일부 작은 행렬만 학습하는 LoRA와 달리 모델의 모든 가중치를 갱신한다. 서비스가 GPU 할당과 체크포인트 관리를 맡지만 계산량과 학습 시간까지 사라지는 것은 아니다. 공식 문서는 출력 아티팩트가 더 크고 지속적 맞춤 학습과 호환되지 않는다는 제약도 명시한다.

**맥락**

AWS 비교는 **Qwen3-4B**, **Magicoder 11만 코드 지시·응답 쌍**, **90/5/5 분할**을 사용한다. 학습 99,000개, 검증·시험 각 5,500개이며 두 방식에 같은 프롬프트·정답·평가 코드를 적용했다고 설명한다. 그러나 이 사례가 모든 모델·데이터에서 FFT의 우위를 증명하지는 않는다.

특히 본문의 **90.0%**는 특정 설정의 Nova Pro 판정 기반 의미적 정답률이며 코드 실행 테스트 통과율이 아니다. 글은 다른 설정에서 LoRA의 판정 점수 **81.5%**, FFT **79.5%**도 보고한다. 서로 다른 조건의 수치를 한 표의 일관된 승패처럼 섞지 않았다. MMLU·MATH 악화 사례 역시 함께 제시돼 있다.

**실무 시사점**

맞춤 학습 담당자는 기존 모델·LoRA·FFT를 같은 보류 데이터와 예산 기준으로 비교하는 계획을 세우자. 코드 업무에서는 실행 테스트, 원래의 일반 능력을 점검할 별도 자료, 학습 시간·비용을 함께 기록한다. 완료 기준은 도메인 성능 향상과 일반 능력 보존의 하한을 동시에 충족하는 것이다. 이번에는 학습이나 유료 평가를 실행하지 않았다.

공식 지원 표에서 목표 모델의 **SFT/FFT 등 해당 조합**을 확인하고, LoRA 전용 매개변수를 그대로 넘기지 않도록 설정을 검토하자. ‘서버리스’는 무료라는 뜻이 아니며 서비스 비용·모델 이용 조건·데이터 반입 승인은 별도 확인 대상이다.

**한계 및 의문**

단일 코드 데이터 사례, 자동 평가자의 편향, 초매개변수 차이 때문에 ‘전체 미세조정이 항상 낫다’는 결론은 부적절하다. 표면적 텍스트 유사도도 실행 정확성과 다르다. 대규모 학습에서 기존 지식을 잃는 치명적 망각을 검출할 시험이 필요하다는 것이 이번 자료의 실질적 교훈이다.

문서상 FFT는 더 많은 연산·시간과 전체 가중치 아티팩트를 요구한다. 실제 가격·지역별 용량·작업 대기 시간은 이 발표만으로 수치화하지 않았다.

### 3. Microsoft-Decision-1.1 정식 제공: 문장을 쓰는 대신 선택과 확률을 반환한다

- **출처**: Microsoft Foundry 공식 블로그·Microsoft Learn 배포 문서
- **점수**: 8.2/10 *(편집 선정 점수, 모델 정확도 점수가 아님)*
- **URL**: https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/introducing-microsoft-decision-1-1-build-faster-more-efficient-ai-applications-w/4573877
- **원 게시자**: Microsoft / Saumil Shrivastava
- **발견 경로**: 최신 추론 도구 뉴스 검색 → 공식 출시 글 → API·배포 문서 대조
- **발표·정식 제공 안내일**: 2026-11-18, 정확한 시각 미표시
- **수정일**: 별도 수정일 미확인
- **확인일**: 2026-11-19
- **상태**: Microsoft Foundry 일반 제공; 배포 유형·지역·계정 권한 조건 있음

**요약**

Microsoft가 선택형 판단에 특화한 Decision-1.1을 정식 제공한다고 발표했다. 텍스트·JSON·이미지를 받아 분류·순위·참거짓 판단에 사용할 수 있으며 자유 형식 설명을 생성하는 모델과 구분된다. 회사는 이미지 입력 지원과 이전 버전보다 빠른 추론을 강조한다. 개발 문서는 선택지와 확률 또는 척도상의 값을 반환하는 질문 유형을 안내한다.

**맥락**

이전 뉴스의 Hugging Face decision 모델 지원은 추론 인터페이스·생태계에 관한 소식이었다. 이번은 Microsoft 모델의 **1.1 버전 정식 제공·이미지 입력**이라는 별도 사건이다. 다만 유형이 같은 기능을 범용 추론의 대체재라고 과장하지 않는다.

회사는 학습에서 제외한 **102개 벤치마크·38만5천여 질문**에서 평균 정확도 **78.8%**를 보고한다. 이는 공급사 평가이며 모든 업무의 성공률이 아니다. ‘2배 이상 빠름’ 역시 동일한 운영 부하에서 독립 재현한 결과로 취급하지 않았다.

공식 글의 100만 입력 토큰당 가격은 Global Standard **$0.042**, US Data Zone **$0.046**, EU·APAC Data Zone **$0.050**이고 출력 토큰에는 추가 요금이 없다고 안내한다. **캐시 입력 전용 할인 단가는 해당 표에 없다**. 이미지 입력의 토큰 산정과 다른 중개 제공자의 요금은 별도 확인해야 한다.

**실무 시사점**

분류·라우팅 담당자는 실제 라벨이 있는 요청을 고정하고 기존 규칙·분류기와 비교하자. 전체 정확도 외에 클래스별 누락, 잘못된 자동 처리, 사람에게 넘기는 비율, p95 지연을 함께 측정한다. 완료 기준은 운영에서 허용하는 오류율을 지키면서 검토 부담이나 지연을 줄이는 것이다. 제시된 확률이 잘 보정됐는지도 별도로 확인해야 한다.

문서상 Global Standard는 지원 Azure 지역에서 전역 처리될 수 있다. 지역 내 처리가 필요하면 가능한 DataZoneStandard와 데이터 흐름을 확인하자. 배포 유형만으로 더 낮은 지연을 보장하지는 않는다. 이번에는 계정 배포나 과금 API 호출을 하지 않았다.

**한계 및 의문**

선택지가 잘못 설계되면 모델이 빠르게 틀린 결정을 내릴 수 있다. 낮은 확률을 사람 검토로 연결하되 임계값은 실제 데이터로 정해야 한다. 설명문을 생성하지 않는 성격상 근거가 필수인 업무에는 별도 검토 절차가 필요하다.

가격은 확인한 Microsoft 발표 기준이며 지원 지역·권한·요금 변경을 모두 보장하지 않는다. 평균 벤치마크와 비용 절감 주장을 그대로 운영 보증으로 사용하지 않았다.
