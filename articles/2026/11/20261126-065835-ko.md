### 1. XPENG IRON 공개: 매장 훈련과 공식 출시는 아직 앞으로의 계획이다

- **출처**: XPENG 공식 발표
- **점수**: 8.1/10 — 편집 선정 점수
- **URL**: https://www.xpeng.com/pressroom/news/01a212b0d830a1e838d68a02a2110174

**요약**

XPENG가 11월 25일 AI Day에서 Turing Physical AI Architecture와 휴머노이드 IRON을 공개했다. 회사는 신체 제어, 빠른 반응, 상위 계획을 각각 System 0·1·2로 나누는 구조를 설명한다. IRON에는 76개 자유도와 1,500개 이상의 촉각 감지 지점, Turing 칩 세 개가 들어간다고 발표했다. 매장 보조 역할의 훈련은 2027년 1분기, 공식 공개 출시는 2분기를 목표로 한다.

**맥락**

회사는 250개 이상의 시나리오와 15개 직종을 다루는 Robot Data Factory도 소개했다. 이는 데이터·개발 범위에 관한 수치이지 해당 작업을 모두 자율적으로 성공했다는 결과가 아니다. 공개 발표에는 작업별 성공률·개입 횟수·장시간 가동 평가가 제시되지 않는다.

편집 해석: 이번 소식의 핵심은 범용 로봇의 완성 선언이 아니라, 자동차에서 축적한 연산·제어·검증 체계를 로봇 사업으로 연결하려는 제품화 전략이다. 층별 제어를 설명했다고 각 층의 실패 복구가 실제 매장에서 입증된 것은 아니다.

**실무 시사점**

서비스 로봇 도입을 검토하는 팀은 먼저 “매장 보조”를 이동·응대·물체 취급·충전·이상 보고 같은 구체적 작업으로 나누자. 후속 실증 자료가 나올 때 같은 작업에서 자율 완료율, 사람 개입, 실패 후 복구와 연속 가동 시간을 요구하는 평가표를 준비한다.

완료 기준은 시연 영상이나 자유도 수가 아니라, 실제 운영 공간에서 정한 작업·시간·개입 기준을 충족하는 것이다. 현재 발표를 즉시 구매·배치 가능한 제품의 성능 보증으로 사용하지 않는 편이 좋다. 이는 검증 계획 제안이며 이번에 로봇을 시험한 것은 아니다.

**한계 및 의문**

1분기 훈련과 2분기 출시는 미래 목표다. 일정·시장별 제공·가격·현장 운영 조건은 별도 확인이 필요하다. 촉각 지점의 개수만으로 접촉 인식 정확도나 안전한 조작을 판단할 수도 없다. 공급자의 “범용”이라는 표현을 독립 검증된 범용성으로 옮기지 않았다.

### 2. Nemotron Parse 후속 공개: 문서 모델의 데이터·학습·속도 조건을 함께 연다

- **출처**: Hugging Face의 NVIDIA 공식 글·측정 노트·공식 학습 문서
- **점수**: 8.5/10 — 편집 선정 점수
- **URL**: https://huggingface.co/blog/nvidia/building-on-nemotron-35-parse-open-data-fine-tunin

**요약**

NVIDIA가 11월 26일 기존 Nemotron 3.5 Parse를 확장할 자료를 공개했다. 새 기반 모델 출시가 아니라 합성 데이터 세 종류, 미세조정 레시피와 DFlash2 추론 보조 모델에 관한 후속 발표다. 데이터 규모는 차트 998만, 표 100만, 다국어 OCR 790만 예제로 안내한다. 문서 파싱은 글자 인식에 더해 읽기 순서·표 구조·차트 값과 위치를 구조화하는 작업이다.

**맥락**

DFlash2는 작은 모델이 여러 토큰을 제안하고 원 모델이 함께 검증하는 speculative decoding 방식이다. 같은 Parse 3.5의 추측 디코딩 비활성 조건 대비 처리량 향상은 동시성 1에서 7.62배, 512에서 1.52배다. 단일 H200·BF16·동일한 2,078개 페이지의 단일 패스 조건이다. 낮은 동시성의 큰 배수를 대규모 서비스 전체 가속으로 읽으면 안 된다.

별도 측정 노트는 전처리·prefill·디코딩과 요청 보충·마무리를 시간에 포함하고, 모델 시작·이미지 로딩·예열·직렬화·HTTP는 제외한다고 명시한다. Parse 3.5는 세 차례 측정의 중앙값이며, 동시성별로 시험한 고정 draft 길이 중 최선의 값을 사용했다. 추가로 잘라낸 영역을 재처리하는 다중 패스 비용은 이 곡선에 포함되지 않는다.

**실무 시사점**

문서 추출 팀은 자사 양식에서 글자·표 셀·차트 값·좌표 중 어떤 오류가 중요한지 먼저 정하자. 공식 레시피는 치과 양식을 예제로 데이터 준비, supervised fine-tuning(SFT), 검증 가능한 보상 기반 강화학습(RLVR), 평가를 연결한다. 다른 업무에는 그 업무의 정답 판정기와 보상 정의를 직접 마련해야 한다.

완료 기준은 예제 실행 성공이 아니라, 미사용 양식에서 기본 모델·SFT·RLVR 결과를 같은 조건으로 비교해 중요 필드 오류·미완료·반복 출력·총 처리시간을 함께 기록한 것이다. 합성 생성기의 분할만으로 끝내지 말고 실제 스캔과 외부 문서도 별도 시험하는 계획이 적절하다.

**한계 및 의문**

학습 레시피의 높은 예제 성능은 같은 합성 생성기에서 나온 양식에 대한 결과이므로 다른 실제 문서로 일반화됐다고 볼 수 없다. 공식 문서는 치과 예제 외의 도메인·GPU 구성을 향후 확장으로 남긴다. 반복 탐지 감소도 환각 전반의 감소와 같은 뜻이 아니다.

이번에는 원문·문서·측정 정의를 읽었으며 데이터 다운로드, 학습, 추론을 실행하지 않았다. 데이터별 라이선스·배포 파일과 모델 조건은 실제 활용 전에 각각 확인해야 한다.

### 3. Update — Inkling 2 Mini 단일 GPU 최적화: 모델 교체 없이도 속도가 달라진다

- **출처**: Hugging Face 공식 실험 글·실험자 공개 저장소
- **점수**: 8.0/10 — 편집 선정 점수
- **URL**: https://huggingface.co/blog/inkling-2-mini-inference-hillclimb

**요약**

Hugging Face가 11월 25일 Inkling 2 Mini의 RTX PRO 6000 96GB 추론 최적화 사례를 공개했다. 11월 20일 모델 출시와는 별도의 실행 실험이다. 기존 SGLang·추측 디코딩 없음 구성에서 vLLM nightly·DSpark 구성으로 바꿨다. 단일 사용자 생성 속도는 약 136→190.6 tokens/s, 사용자 8명의 합산 처리량은 약 570→716 tokens/s라고 보고한다.

**맥락**

주 실험은 여섯 프롬프트, temperature 1.0, thinking 활성, 출력 512토큰 조건이다. 단일 사용자 값은 요청 12회의 중앙값으로 제시된다. 저장소는 배포 이미지와 모델 리비전을 고정하고, 인터넷 경유 endpoint의 별도 값도 기록한다. 토큰 속도 향상을 서비스 전체 응답시간의 같은 비율 감소로 바꾸면 안 된다.

DSpark는 초안 토큰을 여러 개 제안하고 원 모델이 검증하는 방식이다. 이 사례의 배포 설정은 문맥 상한을 262,144로 줄이고 메모리 사용 설정도 조정한다. 모델이 원래 1M 문맥을 지원한다는 설명과, 이 장비에서 검증한 실행 설정은 다르다.

**실무 시사점**

추론 인프라 팀은 모델을 바꾸기 전에 기존 병목과 실행 버전을 기록하자. 같은 모델·프롬프트·입출력 예산으로 한 변수씩 바꾸고, 변경 후보 앞뒤에 기준 설정을 다시 측정해 장비 변동을 분리한다. 완료 기준은 토큰 속도 상승뿐 아니라 첫 토큰 지연, 동시 요청, 긴 문맥, 출력 동등성 검사를 함께 통과하는 것이다.

공개 저장소에는 실패한 설정과 원시 기록도 있다. 그중 어떤 플래그가 한 번 빨라 보였다가 재측정에서 사라졌는지 읽는 것이 최종 명령 한 줄을 복사하는 것보다 유용하다. 이번에는 기록만 검토했으며 클라우드 작업이나 endpoint를 생성하지 않았다.

**한계 및 의문**

특정 GPU·모델·개발 버전의 결과이며 엔진 전체의 보편적 우열은 아니다. Greedy 출력 일치는 여섯 프롬프트의 검사 결과로, 모든 확률적 출력·모든 작업의 품질 보증이 아니다. 긴 문맥의 제한된 검색 검사도 광범위한 장문 이해 평가와 같지 않다.

실험 요약 README와 글의 일부 반복 수 표현이 다르므로, 실제 재현에서는 사용하려는 실행 기록의 측정 횟수를 확인해야 한다. 이번 수치는 표에 명시된 단일 사용자 12회 중앙값을 기준으로 소개했다.
