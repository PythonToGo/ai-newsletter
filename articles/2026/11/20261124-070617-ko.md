### 1. RoboTrack 공개: 로봇이 집어 든 물체의 한 점을 끝까지 따라가려면

- **출처**: Ai2 공식 발표·공식 GitHub README
- **점수**: 8.6/10 — 편집 선정 점수
- **URL**: https://allenai.org/blog/robotrack

**요약**

Ai2가 11월 23일 RoboTrack의 평가 자료·합성 학습 자료·두 추적 모델을 공개했다. 점 추적은 한 프레임에서 지정한 위치가 이후 어디로 움직이는지와 가려졌는지를 추정하는 기능이다. RoboTrack-Bench는 실제 로봇·사람의 조작 영상 **307개와 수작업 검증 궤적 2,522개**를 담는다. RoboTrack-15M은 시뮬레이션 기반 **3,000개 영상·1,500만 궤적**이며, RoboTracker와 RoboTracker-Warp는 각각 AllTracker·CoWTracker를 추가 학습한 모델이다.

**맥락**

공개 README의 같은 평가 체계에서 AllTracker는 **AJ 62.56**, RoboTracker는 **63.40**, CoWTracker는 **63.87**, RoboTracker-Warp는 **65.98**을 보고한다. AJ는 위치 추정과 가시성 판단을 함께 반영하는 지표로 높을수록 좋다. 클립별 점수를 구한 뒤 평균하며, 입력 해상도 등 실행 설정은 모델 계열별로 다르다. 동일 계산량 비교나 로봇 작업 성공률로 읽어서는 안 된다.

실제 피펫 액체 이송에서는 세 방식에 각각 **20개 배치**를 시험했다. 점 추적은 17회, 물체 마스크는 8회, 광학 흐름은 5회 전체 작업에 성공했다는 저자 보고다. 20회 안에는 명확한 시야 10개와 부분 가림 10개가 포함된다. 제한된 실증을 모든 조작으로 일반화하지 않는다.

**실무 시사점**

시연 학습·시각 서보 팀은 먼저 저장 영상에서 기존 추적기와 새 모델을 비교하자. 움직이는 물체와 로봇, 가림 전후, 시점별 오류를 나누고 실제 처리 지연도 기록한다. 완료 기준은 평균 AJ 상승만이 아니라 중요한 표적의 추적 실패가 줄고 제어 주기의 시간 한도를 만족하는 것이다.

재현 시에는 README의 수정된 질의점 대응 프로토콜을 사용해야 한다. 공개 안내는 기존 AllTracker 평가 코드의 질의 순서 오류를 수정했다고 명시한다. 또한 Ego-Exo4D에서 다시 잘라 인코딩한 42개 클립은 원 평가 영상과 픽셀 단위로 같지 않아 점수에 소폭 차이가 날 수 있다. 입력 파일 버전을 기록하지 않은 결과를 정확 재현으로 부르지 않는 것이 좋다.

**한계 및 의문**

장시간 가림과 작은 물체의 추적 실패는 남아 있다. 실제 로봇 실험도 한 종류의 제한된 작업이다. 모델이 좋아졌다는 이유만으로 위치 추정값을 검증 없이 구동 명령으로 바꾸면 안 된다.

라이선스도 묶어서 읽지 않는다. 저장소는 일반 코드·RoboTracker에 Apache 2.0을 안내하지만, RoboTracker-Warp 가중치는 **CC BY-NC 4.0**, CoWTracker 관련 코드는 별도의 비상업 연구 조건이다. 평가 주석과 원천 영상의 조건 역시 다르다. 공개 발표일은 2026-11-23이며 정확한 게시 시각·별도 수정일은 미확인이다.

### 2. Ling-3.2-air: 공개 가중치와 작은 활성 크기, 가벼운 배포는 별개다

- **출처**: InclusionAI 공식 Hugging Face 모델 카드·파일 목록; 공식 계정 게시물의 보존본
- **점수**: 7.9/10 — 편집 선정 점수
- **URL**: https://huggingface.co/inclusionAI/Ling-3.2-air

**요약**

InclusionAI가 Ling-3.2-air 가중치를 공개했다. 모델 카드는 기존 Ling-3.0-flash-VL과 같은 네이티브 멀티모달 구조를 사용하며, 총 **124B·토큰당 활성 5.5B** 파라미터라고 설명한다. 전문가 일부를 선택하는 MoE와 선형·attention 계열 층을 섞은 구조다. 공개 카드는 MIT를 표기하고 SGLang·vLLM 실행 경로를 제공한다.

**맥락**

공급자 카드의 AutomationBench-AA는 이전 모델 **15.7%에서 61%**로 높아졌다. 그러나 Harvey LAB-AA v1.1에서는 기준별 통과율 **87.7%**와 전체 기준 통과율 **8.3%**, 중대한 환각 검사까지 포함한 전체 통과율 **0.8%**가 함께 제시된다. 개별 기준을 잘 만족하는 것과 결과물 전체가 통과하는 것은 다르다는 사례다. 이번에는 평가 원시 결과나 독립 실행까지 검증하지 않았다.

배포 안내의 256K 문맥 구성은 **141GB급 GPU 네 장**을 권장하며, 80GB급에서는 병렬 규모를 여덟 장으로 늘리도록 한다. 이는 권장 예제이지 모든 작업의 최소 장비 요구량이나 모델의 확정 최대 문맥 길이가 아니다. 파일 목록의 크기는 약 **129GB**이며 런타임 캐시·버퍼는 별도다. 활성 5.5B를 근거로 작은 단일 GPU 모델처럼 설명하지 않는다.

**실무 시사점**

직접 배포를 검토하는 멀티모달·문서 처리 팀은 중요 필드가 있는 고정 문서 표본을 준비하자. 같은 입력·출력 예산과 추론 설정에서 필드 정확도, 문서 전체 통과율, 근거 없는 답, 최대 메모리와 지연을 각각 비교한다. 완료 기준은 평균 벤치마크 상승이 아니라 중요 오류와 전체 자원 예산이 사전 기준을 함께 충족하는 것이다.

도입 전에는 모델 리비전과 실행 이미지를 고정하고 외부 코드를 허용하는 옵션도 검토해야 한다. 공개 가중치는 비용 없는 운영을 뜻하지 않는다. 이번에는 안내를 읽었을 뿐 가중치를 다운로드하거나 추론 서버를 띄우지 않았다.

**한계 및 의문**

카드에는 비교 평가의 모든 프롬프트·반복 실행·신뢰구간이 제공되지 않는다. 높은 종합 결과를 한국어 문서나 다른 업무로 그대로 옮길 근거는 부족하다. 파일 페이지의 자동 집계는 128B로 표시되어 카드의 124B 설명과도 구분했다.

날짜 확인에도 한계가 있다. 공식 계정 게시물 보존본은 **2026-11-23 15:42 UTC 발표**를 기록하지만, X 원문은 이번 조회에서 403으로 열리지 않았다. 따라서 그 시각은 직접 검증한 원문 타임스탬프로 표시하지 않는다. 가중치 파일·카드의 현재 공개는 공식 저장소에서 확인했으나 최초 업로드 시각·개별 수정 이력은 확보하지 못했다.

### 3. Amazon, Decart 최적화 기술 매입 계약: 칩을 늘리기 전에 실행 경로를 바꾼다

- **점수**: 8.0/10 — 편집 선정 점수
- **URL**: https://www.aboutamazon.com/news/company-news/amazon-decart-ai-optimization

**요약**

Amazon이 11월 23일 Decart Optimization Stack, 즉 DOS의 독점 기술을 매입하는 계약을 체결했다고 발표했다. 공동창업자 세 명과 연구·엔지니어링 팀도 Amazon에 합류하는 내용이다. 두 회사는 2025년부터 Trainium에서 하드웨어와 소프트웨어를 함께 최적화하는 협업을 진행했다. 거래 완료에는 규제 승인 등 통상적인 선행 조건이 남아 있다.

**맥락**

이번 변화는 새로운 기반 모델 발표가 아니라 **실행 효율을 높이는 기술과 인력의 결합**이다. Amazon은 자체 칩과 추론의 성능·비용 개선을 목표로 내세운다. 다만 공식 발표에는 같은 모델·하드웨어·품질 조건으로 측정한 가속 배수나 고객 요금 인하표가 없다. 목표와 검증된 성능 향상을 구분해야 한다.

편집부는 칩 선정과 모델 선정 사이의 컴파일·커널·메모리 이동을 독립적인 검토 대상으로 볼 필요가 있다고 해석한다. 그러나 이번 계약만으로 여러 칩 간 모델 이전이 자동으로 쉬워졌다고 단정하지 않는다.

**실무 시사점**

추론 인프라 팀은 계약 발표를 이유로 즉시 이전하기보다 현재 서비스의 병목을 먼저 기록하자. 대표 입력 길이·동시 요청·출력 상한을 고정해 첫 토큰 지연, 처리량, 품질, 사용률과 실제 비용을 비교할 기준표를 만든다. 이후 구체적인 런타임이나 서비스가 공개될 때 같은 기준으로 재평가한다.

완료 기준은 가속기 명칭이나 거래 규모가 아니라, 같은 품질·가용성 조건에서 서비스의 전체 비용과 응답 시간 목표를 충족하는지다. 아직 제공되지 않은 제품 기능을 전제로 구매나 마이그레이션 일정을 확정할 단계는 아니다. 이는 편집부의 운영 제안이며 실행한 벤치마크가 아니다.

**한계 및 의문**

공식 발표는 기술 매입 계약과 예정된 인력 영입을 다룬다. Decart 회사 전체의 인수 완료로 쓰지 않았으며, 매입 금액·거래 종료일·고객 제공 시점은 원문에서 확정하지 않는다. 효과는 미래 전망으로 표현돼 있어 독립적으로 입증된 절감률도 없다.

발표일과 계약 발표 사건일은 **2026-11-23**이다. 정확한 공식 게시 시각·별도 수정일은 미표기다. 앞으로의 승인·통합·배포 결과가 이번 기대와 달라질 수 있다.
